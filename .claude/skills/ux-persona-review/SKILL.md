# AI 페르소나 UX 평가

평가 방법·페르소나·기준의 원본은 `docs/design/03-ux-persona-review.md`다. 실행 전에 반드시 그 문서를 읽고 그대로 따른다.

## 입력

- 화면 ID (예: `C-12`). 없으면 `docs/design/03-ux-persona-review.md`의 "평가 순서" 첫 화면부터.
- 화면 ID로 `docs/design/02-screens.md`에서 코드 경로와 Figma 프레임을 찾는다.

## 순서

1. **화면 확보** (하나 이상)
   - Figma 프레임 링크가 있으면 Figma MCP로 렌더링 이미지를 가져온다.
   - 사용자가 캡처를 줬으면 그것을 쓴다.
   - 둘 다 없으면 코드(해당 `page.tsx`와 컴포넌트, `app/globals.css`)를 읽고 화면 구성을 글로 재구성한다. 이 경우 결과 맨 위에 "코드 기반 평가 — 실제 렌더링 아님"이라고 적는다.
2. **페르소나별 평가**: P-1, P-2, P-3 각각의 입장에서 다섯 기준(읽기·누르기·이해·되돌리기·신뢰)을 1~5점으로 매긴다. 보호자 화면(G-*)이 아니면 P-2는 "해당 없음"으로 둔다.
   - 점수마다 근거를 화면의 구체적 요소로 든다 (예: "칩 글자 14px", "뒤로 가기 시 입력 사라짐").
   - 추측이 아니라 화면·코드에서 확인한 것만 문제로 적는다.
3. **문제 목록**: 심각도 순으로. 여러 페르소나가 같은 문제를 지적하면 심각도를 한 단계 올린다. 제안은 `docs/design/01-design-system.md`의 토큰과 컴포넌트 안에서 한다.
4. **저장**: `docs/design/reviews/<화면ID>.md`에 문서의 "결과 양식"대로 저장한다. 같은 파일이 있으면 지난 점수를 남긴 채 새 날짜 섹션을 위에 추가한다.
5. **보고**: 사용자에게 점수 표와 심각도 높음 항목만 짧게 알린다. 요구사항 문서는 직접 고치지 않는다 (디자인 담당이 결정).
