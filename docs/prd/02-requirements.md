# 02. 개선 요구사항

PRD를 쓰기 전에 **무엇을 고치고 무엇을 새로 만들지**를 이 문서에서 먼저 확정한다. 모든 작업은 여기 있는 ID로 부르고, 담당자는 표의 `담당` 칸에 이름을 적는다.

기준: 해커톤 본선 제출용 프로토타입 · 사용자는 요양보호사와 보호자 · 2026-10-03 정리

## 우선순위 기준

본선은 11/28이지만 멘토링이 11/20에 끝나므로 **11/20까지 마무리**한다. 다음 멘토링(10/23)까지 핵심 흐름과 차별화 기능이 동작해야 한다.

| 등급 | 마감 | 판단 기준 |
| --- | --- | --- |
| **P0** | 10/23 멘토링 전 | 심사위원이 직접 써볼 때 깨지거나, 남의 데이터가 보이거나, 차별화 기능이 없어 보이는 것 |
| **P1** | 11/20 멘토링 종료 전 | 데모 품질을 올리는 것, 시연 준비(데모 계정·실기기 QA) |
| **P2** | 본선 이후 | 실제 기관 파일럿에 필요한 것 |

## 역할

아래 모든 표의 `트랙` 칸이 주 담당이고, 괄호 안은 함께 보는 트랙이다. 트랙은 기획·디자인·개발 1·개발 2이고, 보안 작업은 개발 2가 주로 맡고 개발 1이 함께한다. 트랙별 담당자·맡는 범위·할 일·넘겨줄 것은 [06-roles.md](06-roles.md)에만 적는다.

### DIF-4 제출용 보고서 상세

- **만드는 사람**: 요양보호사는 수급자 화면에서, 보호자는 수급자별 대화방에서 기간(예: 최근 1개월)을 골라 직접 만든다 (D-26). 요양보호사가 만든 보고서는 대화방에 카드로 올라가 보호자도 내려받을 수 있다.
- **내용**: 수급자 기본정보, 기간 내 방문 일시 목록, 식사·복약·배뇨·배변·혈압 기록 표, 특이사항 모음, 기간 중 변화 요약
- **형식**: A4 인쇄용 화면 → 브라우저 인쇄 또는 PDF 저장. 문서 하단에 "요양보호사 관찰 기록이며 의료적 진단이 아닙니다" 문구와 작성자·작성일
- **제출**: 앱이 의료기관·보험사에 직접 보내지 않는다. 보호자(또는 수급자)가 내려받아 제출한다. (LAW-10)

### DIF-5 수급자별 대화방 상세

- 수급자 1명 = 대화방 1개. 참여자는 담당 요양보호사와 등록된 보호자.
- 방문 보고서를 보내면 대화방에 보고서 카드가 자동으로 올라가고, 같은 링크를 카카오톡으로도 공유한다. 보호자는 카드 아래에서 질문할 수 있다.
- 보고서 링크는 보고서 화면을 열고, PDF는 화면에서 따로 저장한다.
- 카카오톡의 사진·파일 모아보기처럼 대화방 안에서 방문 보고서·제출용 보고서를 날짜별로 모아 보는 "보고서 모아보기"를 둔다. 요양보호사와 보호자 모두 쓰며, 보고서 보관함 역할을 한다 (D-25).
- 보호자는 로그인 없이 수급자별 전용 링크(만료 기한 있음)로 들어온다.
- 프로토타입에서는 실시간 연결 없이 몇 초마다 새 메시지를 확인하는 방식(폴링)으로 만든다.
- 요양보호사 홈의 수급자 카드에 안 읽은 메시지 수를 표시한다.
