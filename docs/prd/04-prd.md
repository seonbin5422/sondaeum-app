# 04. 제품 요구사항 (PRD)

손다음은 **요양보호사가 돌봄 중 급여제공기록지(요양일지)를 빠르게 작성하고 보호자와 즉시 공유할 수 있는 모바일 최적화 웹 서비스**다. 본선 버전은 말 한 번으로 보호자 보고서, 기관 서류 초안, 의료기관·보험사 제출용 보고서까지 만든다. 이 문서는 [02-requirements.md](02-requirements.md)에서 확정한 요구사항을 기능과 화면 단위로 풀어 쓴다.

기준: 해커톤 본선(11/28) 제출용 프로토타입 · P0는 10/23 멘토링, 전체는 11/20 멘토링 종료까지 · 2026-10-03 (10/7 다시 쓴 PRD 초안 병합)

| 구분 | 내용 |
| --- | --- |
| 카테고리 | 건강 / 웰빙 |
| 사용자 역할 | 요양보호사, 보호자, 서비스 운영자 (2절) |
| 기기 | 모바일 웹 우선, 태블릿·데스크톱 웹 |

## 1. 목표

| 구분 | 내용 |
| --- | --- |
| 제품 목표 | 요양보호사가 돌봄을 멈추거나 근무가 끝난 뒤 기억에 의존하지 않고, 필요한 순간에 짧고 간편하게 기록하도록 돕는다. 기록은 급여제공기록지 형태로 정리해 보호자와 공유하고, 누락을 줄여 돌봄의 연속성·투명성·신뢰도를 높인다 |
| 본선 목표 | 심사위원이 직접 써봐도 끊김 없이 동작하는 완성도 높은 프로토타입 |
| 차별화 한 줄 | 기록 한 번 → 보호자 보고서 + 기관 서류 초안 + 제출용 보고서(PDF) + 수급자별 대화방 |

### 배경

요양보호사는 종이 양식에 기록하거나 근무가 끝난 뒤 급여제공기록지(요양일지)를 한꺼번에 쓰는 경우가 많다. 짧은 급여 제공 시간 안에 돌봄과 기록을 함께 해야 해서 기록이 빠지거나 부정확해지고, 기록에 신경 쓰는 동안 돌봄의 질이 떨어질 수 있다. 손다음은 돌봄 중 바로 쓸 수 있는 체크리스트·음성 입력·자유 입력을 주고, 쌓인 내용을 마지막에 검토해 보호자에게 공유하게 한다.

### 사용자 문제

- 요양보호사는 돌봄 중 손이 바쁘고 방문 시간이 정해져 있어 기록을 미루기 쉽다. 종이 기록이나 사후 작성은 누락과 기억 의존을 늘린다.
- 보호자는 떨어져 사는 가족의 그날 상태와 받은 돌봄을 빨리 알기 어렵고, 병원·보험사 제출 자료가 필요할 때 다시 모아야 한다.
- 민감한 돌봄 기록을 잘못 공유할 위험이 있다.

### 해결 방안

요양보호사는 수급자별 방문 화면에서 음성·텍스트·체크로 돌봄 내용을 기록한다. AI는 발화와 체크 기록을 급여제공기록지 항목에 맞춰 정리하되, 근거가 없는 내용은 채우지 않고 "확인 필요"로 표시한다. 요양보호사가 검토한 기록은 보호자 보고서, 기관 서류 초안, 기간별 제출용 보고서로 이어지고, 보고서는 수급자별 대화방에 카드로 올라가고 카카오톡으로도 링크가 공유된다. 보호자는 링크를 열어 바로 보고, 대화방에서 질문하며, 지난 보고서는 대화방의 "보고서 모아보기"에서 날짜별로 찾는다 (D-25).

### 차별점

- 단순 메모나 음성 전사가 아니라, 현장 기록 한 번이 보호자 보고서·기관 서류 초안·제출용 보고서로 이어진다.
- 급여제공기록지 항목 순서(D-24)로 AI가 관찰 사실만 정리하고, 빠진 항목과 원문 근거("내가 한 말")를 함께 보여 믿고 검토할 수 있다.
- 카카오 계정 없이 들어오는 "체험하기", 큰 글씨와 단순한 조작으로 디지털에 익숙하지 않은 요양보호사도 쓸 수 있다.

### 성공 기준

10/23 멘토링: 아래 1~4 중 1·3·4가 동작. 11/20: 전부.

- 심사위원이 로그인부터 보고서 전송까지 **3분 안에** 혼자 끝낼 수 있다.
- 핵심 흐름(기록 → 요약 → 검토 → 전송 → 열람)에서 오류 화면이 나오지 않는다. 흐름별로 오류 없이 끝난 비율을 잰다.
- 다른 심사위원의 수급자·보고서가 보이지 않는다. (SEC-1, SEC-2)
- 30초 분량의 음성 기록 하나로 보호자 보고서가 만들어지고(DIF-2), 11/20까지는 서류 초안도 함께 만들어진다(DIF-3).
- 심사위원이 카카오 계정 없이 "체험하기"로 바로 들어와 샘플 데이터로 써볼 수 있다. (OPS-1)
- 보호자가 링크로 보고서를 열고 대화방에 질문을 남길 수 있다. (DIF-5)

## 2. 사용자와 핵심 상황

| 사용자 | 핵심 상황 | 손다음이 주는 것 |
| --- | --- | --- |
| 요양보호사 (중장년층, 주로 60대, 하루 3~4가정 방문) | 스마트폰은 쓰지만 복잡한 업무용 앱은 부담스러움. 돌봄 중 손이 바빠 기록을 미루다 잊음 | 말로 바로 기록, AI 정리, 퇴근 때 한 번에 전송 |
| 보호자 (떨어져 사는 가족) | 어르신 상태를 알 길이 없음. 로그인 없이 그날 돌봄과 변화를 보고 요양보호사에게 묻고 싶음 | 링크 하나로 오늘 받은 돌봄(급여제공기록지 항목)과 특이사항 확인, 질문 남기기 |
| 서비스 운영자 (팀) | 체험 계정과 기본 서비스 운영 | 별도 화면 없음. 기관 관리자 화면·기관 단위 권한은 이번 범위 밖 (D-07) |

### 하루 사용 시나리오

1. 요양보호사가 카카오 로그인 또는 "체험하기"로 들어와 오늘 방문할 수급자와 일정을 확인한다.
2. 방문 전 수급자 프로필에서 병력·알레르기·복용약·특이사항을 확인한다.
3. 돌봄 중 음성·텍스트·체크로 서비스 시간, 신체활동, 인지·정서, 가사, 배설, 변화상태, 특이사항을 남긴다.
4. AI가 기록을 요약하고 빠진 항목을 "확인 필요"로 표시하면, 요양보호사가 검토·수정한 뒤 임시저장하거나 전송한다.
5. 전송한 보고서는 수급자별 대화방에 카드로 올라가고 카카오톡으로도 링크가 공유된다. 보호자는 링크로 보고서 화면을 열어 보고(필요하면 PDF로 저장), 대화방에서 질문하고 요양보호사는 답장한다.
6. 필요하면 요양보호사 또는 보호자가 기간을 골라 제출용 보고서를 만들고 PDF로 저장·인쇄한다 (D-26).

### 3.3 기록 항목 (D-24)

기록(C-12), 기록 확인(C-14), 보내기 전 확인(C-15), 보호자 보고서(G-01)는 모두 **장기요양급여 제공기록지(별지 제12호서식)** 항목 순서를 따른다. 요양보호사가 스마트장기요양에 입력하는 항목과 같게 해서 기록을 두 번 하지 않게 하고, 보호자 보고서와 서류 초안(DIF-3)을 같은 데이터로 만든다. 항목 정의는 [03-legal.md](03-legal.md) 1절.

| 순서 | 항목 | 기록 방식 | 요양보호사 화면 | 보호자 보고서 |
| --- | --- | --- | --- | --- |
| 1 | 서비스 시간 | 시작·종료 시각, 총시간 | 출근·퇴근 시간으로 자동 입력 | 날짜와 시간 |
| 2 | 신체활동지원 | 체크 (개인위생, 몸씻기, 식사도움, 체위변경, 이동도움, 화장실 이용) | 체크 버튼 | 한 것만 "신체활동 도움"으로 표시 |
| 3 | 인지·정서 지원 | 분 (인지자극활동, 일상생활 함께하기, 인지관리지원, 정서지원) | 분 입력 | 0분이 아닌 항목만 |
| 4 | 가사·일상생활지원 | 분 (식사준비·청소·세탁, 외출동행) | 분 입력 | 0분이 아닌 항목만 |
| 5 | 배설 | 대변·소변 실수 횟수 (기저귀 사용 시 교환 횟수) | 횟수 입력 | "없음" 또는 횟수 |
| 6 | 변화상태 | 신체·식사·인지기능 호전/유지/악화 | 직접 고름 (AI가 채우지 않음) | "좋아졌어요/비슷해요/나빠졌어요" |
| 7 | 특이사항 | 텍스트 | AI 요약 + "내가 한 말" 근거 | 그대로 |

- 기록지에 따로 칸이 없는 식사량·복약·혈압은 식사도움과 특이사항에 적는다.
- 발화에 없는 항목은 비워 두고 "확인 필요"로 표시한다 (LAW-2).
- 화면: [02-screens.md](../design/02-screens.md)의 C-12·C-14·C-15·G-01 Figma 링크.

## 4. 사용자 스토리와 완료 조건

| ID | 스토리 | 완료 조건 |
| --- | --- | --- |
| US-1 | 요양보호사로서 돌봄 중 말로 기록하고 싶다, 손이 바쁘니까 | 녹음 버튼 한 번으로 시작·종료, 앱이 꺼졌다 켜져도 내용이 남아 있음 |
| US-2 | 요양보호사로서 빠진 항목을 보내기 전에 알고 싶다 | 급여제공기록지 항목(신체활동·인지·정서·가사·배설·변화상태) 중 빠진 항목이 전송 전에 항목 이름으로 표시됨 |
| US-3 | 요양보호사로서 같은 기록으로 기관 서류도 끝내고 싶다 | 보고서 검토 화면에서 서류 초안 탭으로 이동, 자동으로 채워진 항목과 비어 있는 항목이 구분됨 |
| US-4 | 보호자로서 병원 진료나 보험 청구 때 돌봄 기록을 내고 싶다 | 기간을 고르면 A4 보고서가 만들어지고, PDF 저장·인쇄가 되며, 하단에 "관찰 기록이며 의료적 진단이 아님" 문구가 있음 |
| US-5 | 보호자로서 오늘 어머니가 어땠는지 한눈에 알고 싶다 | 링크를 열면 그날 받은 돌봄(급여제공기록지 항목), 지난 방문 대비 변화, 특이사항이 보임. 한 일만 보이고 의료적 판단이 아니라는 고지가 있음 |
| US-6 | 보호자로서 어머니에 대해 요양보호사와 계속 이야기하고 싶다 | 수급자별 대화방 링크로 들어가 메시지를 남기면, 요양보호사 홈의 그 수급자 카드에 안 읽은 메시지 수가 뜸 |
| US-7 | 요양보호사로서 내 수급자 정보는 나만 보길 원한다 | 다른 계정으로 로그인하면 내 수급자·방문·보고서가 하나도 안 보임 |

## 5. 핵심 흐름

흐름은 세 갈래다. ① 매일 하는 방문 기록, ② 보호자와 대화, ③ 필요할 때 만드는 제출용 보고서. 괄호 안은 그 단계에서 바뀌는 요구사항 ID다.

**① 방문 기록 (매 방문)**

```
[로그인: 카카오 또는 "체험하기"(OPS-1)]
   → [처음 한 번: 온보딩 + 동의(LAW-3)]
   → [홈: 오늘 방문할 어르신]
   → [기록: 음성·텍스트·체크박스]          꺼져도 내용 유지(STB-3)
   → [AI 처리중]                           중복 요약 차단(STB-2), 관찰 사실만(LAW-1)
   → [검토: 보호자 보고서 | 서류 초안 탭]  고도화된 보고서(DIF-2), 빠진 항목 "확인 필요"(LAW-2), 서류 탭은 P1(DIF-3)
   → 임시저장 또는 전송                    전송 후에는 수정 불가(STB-1)
   → [공유: 대화방에 보고서 카드 자동 등록 + 카카오톡으로 링크 공유]
```

**② 보호자와 대화 (수시)**

```
보호자: 카카오톡 링크 → [수급자 대화방] → 보고서 카드 확인 (지난 보고서는 [보고서 모아보기]에서 날짜별로) → 질문 남기기
요양보호사: [홈] 어르신 카드에 안 읽은 메시지 수 → [수급자 대화방] → 답장   (DIF-5)
```

**③ 제출용 보고서 (병원·보험 청구가 필요할 때)**

```
요양보호사: [수급자 화면] → 기간 선택 → [A4 보고서] → PDF 저장·인쇄 또는 대화방에 공유   (DIF-4)
보호자: [수급자 대화방] → 기간 선택 → [A4 보고서] (또는 요양보호사가 보낸 보고서 열기) → PDF 저장·인쇄 → 병원·보험사에 직접 제출   (D-26, LAW-10)
```

화면별 상세와 코드 경로는 [../design/02-screens.md](../design/02-screens.md)에 있다.

## 6. 기관 제출 서류 초안 (DIF-3, P1) 상세

- 입력: 한 방문의 전사문 + 체크박스 기록 + 수급자 프로필
- 출력: 장기요양급여 제공기록지(방문요양)의 항목별 값. 항목 목록과 근거 법령은 [03-legal.md](03-legal.md)에서 확정한다.
- AI가 발화에서 확인하지 못한 항목은 **비워 두고 "확인 필요"로 표시**한다. 추측해서 채우지 않는다.
- 서류는 초안이며, 최종 제출은 요양보호사·기관이 기존 시스템에서 한다. 앱은 제출하지 않는다.
- AI 문구는 의료적 판단처럼 보이지 않게 관찰 사실만 적는다. (예: "혈압 150/95 측정" O, "고혈압 악화 의심" X)

## 7. 의료기관·보험사 제출용 보고서 (DIF-4) 상세

- 만드는 곳: 요양보호사는 수급자 화면에서, 보호자는 수급자별 대화방에서 기간(최근 1주·1개월·직접 선택)을 골라 직접 만든다 (D-26). 요양보호사가 만든 보고서는 대화방에 올라가 보호자도 내려받을 수 있다.
- 내용: 수급자 기본정보, 방문 일시 목록, 식사·복약·배뇨·배변·혈압 기록 표, 특이사항 모음, 기간 중 변화 요약
- 형식: A4 인쇄용 화면 → 브라우저 인쇄·PDF 저장. 하단에 작성자, 작성일, "요양보호사 관찰 기록이며 의료적 진단이 아닙니다"
- 앱은 외부 기관에 직접 보내지 않는다. ([03-legal.md](03-legal.md), LAW-10)

## 8. 수급자별 대화방 (DIF-5) 상세

- 수급자 1명 = 대화방 1개, 참여자는 담당 요양보호사와 등록된 보호자
- 보호자는 수급자별 전용 링크(만료 기한 있음)로 로그인 없이 입장
- 방문 보고서를 보내면 보고서 카드가 대화방에 자동으로 올라가고, 같은 링크를 카카오톡으로도 공유함
- 보고서 링크는 PDF가 아니라 보고서 화면을 연다. PDF는 화면의 "PDF로 저장" 버튼으로 따로 저장 (D-25)
- 카카오톡의 사진·파일 모아보기처럼 대화방 안에서 방문 보고서·제출용 보고서를 날짜별로 모아 보는 "보고서 모아보기"를 둔다. 요양보호사와 보호자 모두 쓰며, 보고서 보관함 역할을 한다 (D-25)
- 프로토타입은 몇 초 간격으로 새 메시지를 확인 (실시간 연결 없음)

## 9. 본선 데모 시나리오 (초안)

본선은 **라이브 시연 후 심사위원이 직접 써본다**. 직접 사용은 발표 자료의 QR 코드 → "체험하기"로 들어온다. (OPS-1, OPS-6)

| 순서 | 화면 | 보여줄 것 | 시간 |
| --- | --- | --- | --- |
| 1 | 홈 | 오늘 방문할 어르신 3명, 큰 글씨 화면 | 15초 |
| 2 | 기록 | 30초 음성 기록 ("점심 반 공기 드셨고, 혈압 135에 85…") | 40초 |
| 3 | 검토 | AI 요약 + 누락 알림 + 서류 초안 탭 | 40초 |
| 4 | 보호자 대화방 | 보호자 링크를 열어 보고서 카드 확인 → 질문 → 요양보호사 화면으로 돌아와 안 읽은 메시지 확인 | 40초 |
| 5 | 제출용 보고서 | 최근 1개월 선택 → A4 보고서 → PDF 저장 | 20초 |

## 10. 리스크

| 리스크 | 대응 |
| --- | --- |
| 음성 기록에 민감한 건강·돌봄 정보가 들어감 | 마이크 권한 안내, 저장·전송 보안, 공유 링크 접근 제한과 만료 (STB-5) |
| AI가 관찰 사실을 넘어 의료적 판단·추측을 만듦 | 관찰 사실만 적고(LAW-1), 확인되지 않은 항목은 비워 두고 "확인 필요"로 표시 (LAW-2) |
| 네트워크·음성 인식 실패, 앱 종료, 중복 전송 | 꺼져도 내용 유지(STB-3), 중복 요약 차단(STB-2), 전송 후 잠금(STB-1) |
| 기관별 서식·행정 절차가 다름 | 기관 서류는 초안으로만 제공(D-11), 외부 기관에 직접 보내지 않음 (D-14) |
