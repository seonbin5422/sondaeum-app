## 동시 작업 규칙

### 1. 첫날(10/5) 정할 것

개발 1과 개발 2가 같은 코드를 동시에 고치려면 아래 세 가지를 먼저 합의한다. 합의한 내용은 그날 하나의 PR로 `docs/spec/`에 반영한다.

| 정할 것 | 내용 | 주 담당 |
| --- | --- | --- |
| 스키마 | 이번 프로젝트에서 추가할 필드·모델을 한 번에 정해 마이그레이션 하나로 만든다: `Client.caregiverId`, 서류 초안(DIF-3), `ChatRoom`·`Message`(DIF-5), `Report.shareExpiresAt`, 동의 기록(LAW-3), 체험 계정 표시(OPS-1) | 개발 2 + 개발 1 |
| API 모양 | 새 API의 경로·요청·응답을 [../spec/03-api.md](../spec/03-api.md)에 먼저 적는다. 디자인은 API가 완성되기 전까지 같은 모양의 임시 데이터로 화면을 만든다 | 개발 1 + 개발 2 |
| 권한 함수 | 개발 2가 `lib/authz.ts`에 `requireCaregiver()`, `requireOwnedClient(id)` 같은 함수 이름을 먼저 만들어 둔다(10/6까지). 개발 1은 새 API에서 처음부터 이 함수를 쓰고, 개발 2는 그 안을 채운다 | 개발 2 |

### 2. 파일 나누기

같은 파일을 두 명이 고치지 않는다. 다른 트랙의 파일을 고쳐야 하면 그 담당자에게 요청한다.

| 트랙 | 고치는 파일 |
| --- | --- |
| 개발 2 | `proxy.ts`, `lib/authz.ts`·`session.ts`·`crypto.ts`·`pii.ts`·`kakaoAuth.ts`, `app/login/`, **기존** `app/api/**` 라우트 (권한·상태 확인), 동의·체험 계정 저장 로직 |
| 개발 1 | **새** API 라우트, `lib/careNoteAi.ts` 등 `lib/` 로직, 화면의 데이터 불러오기(`page.tsx`의 조회, 서버 액션) |
| 디자인 | Figma, `docs/design/`, `app/globals.css` 토큰, 화면 컴포넌트(`app/components/`, `app/visit/`·`app/client/`·`app/g/`의 `*Screen.tsx`·`*Form.tsx` 등 UI 파일, 새 화면) — 화면은 props로 데이터를 받고, 연결 전까지 임시 데이터를 쓴다 (D-21) |
| 기획 | `docs/prd/`, 시드 데이터 문구 (`prisma/seed.ts`는 개발 1과 함께) |
| 함께 | `prisma/schema.prisma`는 첫날 합의한 마이그레이션 이후 변경 시 두 사람이 같이 리뷰 |

### 3. 넘겨줄 것과 날짜

누가 누구에게 언제 무엇을 넘기는지는 [06-roles.md](06-roles.md)의 "넘겨줄 것" 표에만 적는다.

넘겨줄 날짜에 못 맞추면 받는 쪽은 기다리지 않고 임시 데이터나 기존 컴포넌트로 먼저 진행한다.
