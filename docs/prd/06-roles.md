## 넘겨줄 것

네 트랙이 서로 기다리지 않도록 넘겨줄 날짜를 정해 둔다. 날짜를 못 맞추면 받는 쪽은 임시 데이터나 기존 컴포넌트로 먼저 진행한다.

같은 파일을 두 명이 고치지 않는다. 개발 2는 기존 API·인증·암호화 파일을, 개발 1은 새 API와 데이터 연결을, 디자인은 화면 컴포넌트를 맡는다 (D-21, 10/6 결정: 화면 구현은 디자인이 Figma MCP로 맡음). 매주 월요일 15분 할 일을 맞추고, 금요일에 그 주 작업을 병합한다.

> **10/9 약속 (D-30)**: 새 화면(1120.ver)은 `app/v1120/`에 있다 (브랜치 `feature/v1120`). 합칠 때까지 **기존 화면 파일(`app/page.tsx`, `app/visit/`, `app/client/`, `app/g/`, `app/components/` 등)은 고치지 않는다.** 화면이 바뀌어야 하면 디자인에 알려 1120 쪽에서 고친다. API·DB·인증·암호화(`app/api`, `lib`, `prisma`)는 지금처럼 개발 1·2가 고친다. 예: D-27 녹음 끊김 저장은 개발 1이 문장마다 저장하는 API·로직을 만들고, 이를 부르는 화면 코드는 1120 기록 화면(`app/v1120/visit/[id]/record`)에 넣는다. `proxy.ts`의 `/v1120` 로그인 예외는 미리보기용이라 main에 넣지 않는다.
