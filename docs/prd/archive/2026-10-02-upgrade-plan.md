- 자동화 테스트 없음

## P0. 실사용 전 반드시 고칠 것

다섯 건 모두 누구나 다른 사람의 수급자 정보를 보거나 바꿀 수 있는 문제다.

| # | 문제 | 위치 |
| --- | --- | --- |
| 1 | API 전체에 로그인 확인이 없음. `/api/`가 공개 경로이고, 수급자·방문·보고서 API가 세션을 확인하지 않아 링크만 알면 수정·삭제 가능 | `proxy.ts`, `app/api/clients/**`, `app/api/reports/**`, `app/api/visits/**` |
| 2 | 요양보호사별 데이터 분리 없음. `Client`에 담당자 필드가 없고, 방문은 로그인한 사람이 아닌 DB의 첫 요양보호사(`findFirst`)로 저장됨 | `prisma/schema.prisma`, `app/api/visits/route.ts`, `app/page.tsx` |
| 3 | AI API를 아무나 호출 가능. `classify-preview`, `transcribe`에 인증과 호출 횟수 제한이 없어 Groq 비용 노출 | `app/api/visits/[id]/classify-preview`, `transcribe` |
| 4 | 카카오 로그인 `state`가 고정값 `"login"`이라 CSRF 방어 없음 | `app/login/page.tsx` |
| 5 | 수급자 개인정보 평문 저장. 암호화는 전사문·보고서에만 적용되고, 이름·전화번호·장기요양인정번호·병력·복용약은 평문 | `prisma/schema.prisma` (Client) |

## P1. 핵심 흐름 안정성

기록이 사라지거나 보고서가 잘못 전달되는 경우를 막는 작업이다.

- **전송한 보고서도 수정 가능:** `PATCH /api/reports/[id]`와 `send`가 상태를 확인하지 않아 전송 후 수정·중복 전송이 됨
- **AI 요약 중복 호출:** `summarize`에 잠금이 없어 새로고침·연타 시 AI가 두 번 호출됨
- **보호자 링크:** 만료 기한이 없고, 카카오톡 링크 미리보기 봇이 열어도 "열람함"으로 기록될 가능성이 높음
- **녹음 중 데이터 유실:** 앱이 꺼지거나 화면이 넘어가면 입력 내용이 사라짐. 임시저장 필요
- **음성 업로드 4MB(약 2분) 제한:** 파일 분할 업로드나 스토리지 직접 업로드 필요
- **만료 수급자 삭제가 페이지 열 때마다 실행:** `purgeExpiredClients`를 Vercel Cron으로 이전
- **테스트 없음:** 일정·권한·암호화 로직부터 테스트 추가

## P2. 기능 고도화

보안과 안정화가 끝난 뒤 4\~6주차에 진행한다.

| 영역 | 항목 |
| --- | --- |
| AI 품질 | 요약 시 수급자 프로필(병력·복용약·알레르기) 맥락 반영, 품질 확인용 평가 샘플, 개인정보 필터 호출 4번 → 1번으로 축소 |
| 보호자 경험 | 카카오 알림톡 전송(지금은 링크 직접 복사), 지난 보고서 이력 화면 |
| 요양보호사 경험 | 수급자별 방문 이력, 일정 예외 처리(휴무·일정 변경·하루 여러 시간대) |
| UX·접근성 | 고령 사용자용 큰 글씨·대비, PWA 오프라인 안내, Figma 디자인 정합성 |
| 운영 | 에러 모니터링(Sentry 등), 감사 로그(누가 무엇을 수정·삭제했는지), README 최신화 |
