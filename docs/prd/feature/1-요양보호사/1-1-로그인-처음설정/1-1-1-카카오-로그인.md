# PRD: 카카오 로그인

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-1 로그인·처음 설정 | C-01 | `/v1120/login` → `/api/auth/kakao/start` → `/api/auth/kakao/callback` | 구현됨 · `feature/v1120` dcaa0df 기준 (SEC-4 리뷰 중) |

## 1. 배경

- 현재 문제: 요양보호사(주로 60대)에게 새 아이디·비밀번호를 만들게 하면 가입에서 이탈한다. 처음 MVP는 카카오 로그인 `state`가 고정값이라 로그인 위조(CSRF)에 열려 있었다 (10/2 계획 P0-4).
- 왜 지금 필요한가: 본선에서 심사위원이 직접 써 보고, 팀 밖 계정·아이폰 로그인 문제가 2차 멘토링에서 지적됐다.
- 관련 문서/이슈: SEC-4, OPS-7, `docs/prd/06-roles.md` 2차 멘토링 피드백(아이폰 카카오 로그인 로그), PR #42

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 카카오 계정 하나로 가입 없이 로그인하고, 필요하면 다른 카카오 계정으로 바꿔 로그인한다.
- 기대 효과: 가입 단계를 없애 첫 기록까지 시간을 줄이고, 로그인 위조를 막는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 한 기기를 여러 사람이 쓰는 경우("다른 카카오 계정으로 로그인")
- 관리자 또는 운영자 영향: 카카오 개발자 콘솔에 서비스 도메인·Redirect URI 등록 필요 (D-34)

## 4. 범위

이번 작업에 포함:

- [x] "카카오로 시작하기" → 카카오 인증 → 콜백에서 세션 생성
- [x] 요청마다 무작위 `state`를 쿠키(10분)에 두고 콜백에서 한 번만 비교 (SEC-4)
- [x] "다른 카카오 계정으로 로그인" (`switch=1` → `prompt=login`)
- [x] 처음 로그인이면 계정을 만들고(카카오 닉네임, 없으면 "요양보호사") 처음 설정으로, 자격번호가 있으면 홈으로
- [x] 실패 이유를 로그(`kakao-login`)와 주소(`?kakao=이유`)에 남김

이번 작업에 포함하지 않음:

- [ ] 아이디·비밀번호 로그인, 비밀번호 찾기·변경
- [ ] 다른 소셜 로그인(네이버·애플 등)
- [ ] 기관 관리자 로그인 (D-07)

## 5. 사용자 흐름

1. 요양보호사가 로그인 화면에서 "카카오로 시작하기"를 누른다.
2. 시스템은 무작위 `state`를 쿠키에 저장하고 카카오 인증 화면으로 보낸다.
3. 요양보호사가 카카오에서 로그인·동의한다.
4. 시스템은 `state`를 비교하고, 카카오에서 사용자 정보를 받아 계정을 찾거나 만든 뒤 세션(7일)을 만든다.
5. 요양보호사는 자격번호가 없으면 처음 설정(C-02), 있으면 홈(C-03)을 본다.

## 6. 기능 요구사항

- FR-1: `/api/auth/kakao/start?to=v1120`은 `newLoginState("v1120")`로 `v1120.<무작위>` 값을 httpOnly 쿠키(`kakao_login_state`, 10분, SameSite=Lax)에 두고 카카오 인증 주소로 303 이동한다.
- FR-2: `switch=1`이면 인증 주소에 `prompt=login`을 붙여 카카오가 계정을 다시 묻게 한다.
- FR-3: 콜백은 `error`가 있거나 `code`가 없으면 실패 처리한다.
- FR-4: 콜백은 카카오에 토큰을 요청하기 **전에** `takeLoginState(state)`로 쿠키 값과 비교하고, 쿠키는 맞든 틀리든 지운다. 다르면 `state_mismatch`로 실패.
- FR-5: 토큰 교환·사용자 조회가 실패하면 `token_or_user`로 실패.
- FR-6: `kakaoId`로 요양보호사를 upsert하고 `createSession()`으로 7일짜리 세션 쿠키를 만든다.
- FR-7: `licenseNumber`가 있으면 `/v1120`, 없으면 `/v1120/onboarding`으로 보낸다.
- FR-8: 실패할 때마다 `console.warn("kakao-login", {reason, host, ua, hasStateCookie})`를 남긴다. `code`·`state` 값은 남기지 않는다.

## 7. 비기능 요구사항

- 성능: 카카오 왕복 외 DB 쓰기 1번(upsert).
- 접근성: 버튼 높이 64px(`h-16`), 글자 18px(`text-lg`), 카카오 공식 노란색(#FEE500) (DIF-1)
- 보안: 무작위 `state` 1회용, 세션·state 쿠키 httpOnly·운영에서 secure. 로그에 인증 값 없음.
- 로깅/모니터링: Vercel 로그에서 `kakao-login` 검색, 사용자 화면 주소의 `?kakao=이유`로 캡처 확인

## 8. 수용 기준

- [ ] Given 처음 쓰는 카카오 계정이, When 카카오 로그인을 마치면, Then 처음 설정(`/v1120/onboarding`)으로 간다.
- [ ] Given 자격번호까지 저장한 계정이, When 다시 카카오 로그인하면, Then 홈(`/v1120`)으로 간다.
- [ ] Given 로그인 시작 쿠키가 없는 브라우저(다른 브라우저로 콜백이 열림)에서, When 콜백 주소가 열리면, Then 로그인되지 않고 주소에 `kakao=state_mismatch`가 붙는다.
- [ ] Given 로그아웃한 뒤, When "다른 카카오 계정으로 로그인"을 누르면, Then 카카오가 계정을 다시 묻는다.
- [ ] Given 팀 밖 사람의 아이폰에서, When 카카오 로그인하면, Then 로그인된다 (OPS-7, 11/1 확인).

## 9. 검증 계획

- 단위 테스트: 없음. `takeLoginState`의 같음·다름·없음 3가지를 STB-7 핵심 로직 테스트에 넣을 수 있다.
- 통합 테스트: 없음
- 수동 확인: 카카오 계정 2개로 위 수용 기준, 아이폰 Safari·Chrome·안드로이드 크롬, 팀 배포 도메인 (OPS-2, OPS-7)

## 10. 리스크와 열린 질문

- 리스크:
  - 아이폰 Safari에서 iCloud 비공개 릴레이가 켜져 있으면 카카오 2단계 인증이 막힌다 → "이메일로 인증하기"나 Chrome으로 우회. 본선 시연은 "먼저 둘러보기"로 한다.
  - 카카오톡 앱 인증 뒤 다른 브라우저로 콜백이 열리면 `state_mismatch`가 난다.
- 열린 질문:
  - 실패 시 `/login?kakao=이유`(옛 화면)로 보낸다. 1120 화면에서 시작한 사람도 옛 로그인 화면을 보게 되는데, `/v1120/login`으로 보낼지
  - 로그아웃해도 카카오 로그인은 브라우저에 남는다. 공용 기기에서 다음 사람이 같은 계정으로 들어갈 위험을 안내할지
  - 세션 7일이 지나면 다시 로그인해야 하는데, 요양보호사에게 적당한 길이인지
