# PRD: 먼저 둘러보기 (체험 계정)

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사(체험), 심사위원 | 1-1 로그인·처음 설정 | C-01 | `/v1120/login` → `POST /api/auth/demo` | 구현됨 · `feature/v1120` ae8748e 기준 (OPS-1 리뷰 중) |

## 1. 배경

- 현재 문제: 본선은 라이브 시연 뒤 심사위원이 직접 써 본다. 카카오 로그인은 아이폰에서 막힐 수 있고(1-1-1 리스크), 빈 계정으로는 게시판·서류 만들기를 바로 볼 수 없다.
- 왜 지금 필요한가: 본선 심사(11/28)와 2차 사용성 테스트(OPS-9)에서 계정 없이 전 흐름을 보여 줘야 한다.
- 관련 문서/이슈: OPS-1, `docs/prd/04-prd.md` 성공 기준 "체험하기로 바로 들어와 샘플 데이터로 써볼 수 있다"

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 버튼 하나로 예시 수급자·지난 기록·게시판 댓글이 채워진 계정에 들어가 기록부터 보내기까지 해 본다.
- 기대 효과: 심사위원이 3분 안에 혼자 핵심 흐름을 끝낸다.

## 3. 대상 사용자

- 주요 사용자: 심사위원, 처음 온 요양보호사
- 보조 사용자: 사용성 테스트 참가자
- 관리자 또는 운영자 영향: 체험 계정이 DB에 쌓이므로 정리 필요 (24시간)

## 4. 범위

이번 작업에 포함:

- [x] "먼저 둘러보기" 버튼, 아래에 "둘러보기는 예시 수급자 3명으로 체험해요. 24시간 뒤 지워져요."
- [x] 누를 때마다 새 체험 계정(`isDemo`, 이름 "체험 요양보호사", 24시간 뒤 만료) 생성
- [x] 예시 수급자 3명(`_mock.ts`의 삭제 안 된 수급자 앞 3명), 이름·전화번호 암호화
- [x] 지난 14일 방문 요일마다 보낸 방문 기록·보고서
- [x] 게시판 샘플: 보호자 있는 첫 수급자의 최근 보고서 2개에 댓글 4개, 둘째 수급자에게 건강 기록 요약 글 + 댓글 1개
- [x] 세션을 만들고 처음 설정(`/v1120/onboarding`)으로 보냄
- [x] 녹음 화면의 "예시 내용 넣기"(체험 계정 전용, 1-4 참고)

이번 작업에 포함하지 않음:

- [ ] 체험 계정을 카카오 계정으로 옮기기
- [ ] 정해진 시각에 도는 만료 계정 삭제 (지금은 누군가 둘러보기를 누를 때만 지움)

## 5. 사용자 흐름

1. 사용자가 로그인 화면에서 "먼저 둘러보기"를 누른다.
2. 시스템은 만료된 체험 계정을 지우고, 새 체험 계정·예시 수급자 3명·지난 2주 기록·게시판 샘플을 만든 뒤 세션을 만든다.
3. 사용자는 처음 설정(이름·자격번호) → 동의를 거쳐 홈에서 예시 수급자를 본다.

## 6. 기능 요구사항

- FR-1: 로그인 화면의 폼이 `POST /api/auth/demo`로 보낸다.
- FR-2: 먼저 `demoExpiresAt`이 지난 체험 계정을 댓글·보고서·방문·서류·수급자·AI 사용 기록과 함께 지운다.
- FR-3: 새 요양보호사를 `isDemo: true`, `demoExpiresAt: 지금+24시간`으로 만든다.
- FR-4: 예시 수급자 3명을 만든다. 이름·수급자 전화·보호자 전화는 `sealPII`로 암호화한다.
- FR-5: 한국 시간 오늘 0시 기준 지난 14일 중 방문 요일마다 `SENT` 방문과 보고서(특이사항 예시 7개를 돌려 씀)를 만든다.
- FR-6: 게시판 샘플(FR 범위의 댓글 4개, 요약 글 1개 + 댓글 1개)을 만든다. 댓글은 암호화한다.
- FR-7: `createSession()` 후 `/v1120/onboarding`으로 303 이동한다.

## 7. 비기능 요구사항

- 성능: 방문·보고서는 `createMany`로 모아 넣는다 (DB가 도쿄에 있어 왕복을 줄임).
- 접근성: 버튼 높이 64px, 글자 18px, 안내 문구 16px
- 보안: 체험 계정마다 데이터를 따로 만들어 다른 체험자와 섞이지 않는다 (SEC-2). 예시 데이터도 실제처럼 암호화한다.
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 로그인 화면에서, When "먼저 둘러보기"를 누르면, Then 처음 설정 화면이 열리고 설정·동의 뒤 홈에 예시 수급자가 보인다.
- [ ] Given 두 사람이 각각 둘러보기를 눌렀을 때, When 한 사람이 기록을 보내면, Then 다른 사람 화면에는 그 기록이 보이지 않는다.
- [ ] Given 체험 계정으로 들어온 사용자가, When 게시판 탭을 열면, Then 댓글이 있는 보고서 글과 건강 기록 요약 글이 보인다.
- [ ] Given 24시간이 지난 체험 계정이 있을 때, When 누군가 둘러보기를 누르면, Then 그 계정과 수급자·기록이 지워진다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음. STB-7에 "체험 계정 둘이 서로의 수급자를 못 봄"을 넣을 수 있다.
- 수동 확인: 둘러보기 → 기록 → 보내기 → 보호자 링크 열기 → 게시판 댓글까지 (OPS-11 시연 전 점검)

## 10. 리스크와 열린 질문

- 리스크:
  - 만료 계정은 누군가 둘러보기를 눌러야 지워진다. 아무도 안 누르면 남는다 (Vercel Cron 필요).
  - 본선 현장에서 여러 명이 동시에 누르면 계정 생성이 몰린다.
- 열린 질문:
  - 체험 계정도 처음 설정·동의를 거친다. 심사위원 3분 목표에 맞춰 건너뛸지 (지금 코드는 거침)
  - 수급자 이름 등 예시 문구는 기획 확정본인지 (06-roles "11/2 체험용 샘플 문구" 넘겨줄 것)
  - 본선 현장은 HTML 파일·영상만 쓸 수 있다는데(URL 시연 실격), 심사위원 직접 사용 때 이 기능을 어떻게 열지
