# PRD: 동의 (개인정보·건강정보·보호자 제공·국외 이전)

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-1 로그인·처음 설정 | C-21 | `/v1120/onboarding/consent` (2/2단계) → `POST /api/caregivers/onboard` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 손다음은 수급자의 건강정보(민감정보)를 다루고, 보고서를 보호자에게 주고, AI 정리·호스팅·저장을 해외 회사에 맡긴다. 개인정보 보호법상 이것들은 한 번에 묶어 받으면 안 되고 따로 동의를 받아야 한다.
- 왜 지금 필요한가: P0(LAW-3). 보호자가 가족이 아닌 경우(사회복지사·주민센터·후견인, D-49)도 동의 항목에 넣어야 한다.
- 관련 문서/이슈: LAW-3, LAW-12, D-49, `docs/prd/03-legal.md`, `app/v1120/_consent.ts`(기획 확정본 10/23)

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 네 항목을 하나씩 읽고 따로 동의한 뒤 손다음을 시작한다.
- 기대 효과: 법적 동의 요건을 채우고, 동의 시각·항목을 기록으로 남긴다.

## 3. 대상 사용자

- 주요 사용자: 처음 설정 중인 요양보호사
- 보조 사용자: 체험 계정 사용자
- 관리자 또는 운영자 영향: 동의 문구가 바뀌면 `_consent.ts` 한 곳만 고치면 동의 화면·내 정보·처리방침에 같이 반영된다.

## 4. 범위

이번 작업에 포함:

- [x] 필수 항목 4개: 개인정보 수집·이용 / 건강정보(민감정보) 처리 / 보호자에게 제공 / 국외 이전(AI 정리·서비스 운영)
- [x] 항목마다 한 줄 설명과 "자세히 보기"(쓰는 곳·모으는 것·보관 기간, 국외 이전은 받는 곳 표)
- [x] 국외 이전 받는 곳: Groq(AI 정리, 보관 안 함), Vercel(호스팅), Turso(저장, 도쿄)
- [x] 크롬 음성 인식은 처리위탁이 아닌 브라우저 기능이라 따로 알림
- [x] "모두 동의하기" 한 번에 켜기·끄기
- [x] 넷 다 동의해야 "동의하고 시작하기"가 눌림, 서버도 한 번 더 확인
- [x] 동의 시각(`consentedAt`)과 항목 키(`consentItems`) 저장, 이름·자격번호도 이때 저장
- [x] "개인정보 처리방침 전체 보기" 링크

이번 작업에 포함하지 않음:

- [ ] 선택 동의 항목 (마케팅 등)
- [ ] 동의 철회
- [ ] 동의 문구가 바뀌었을 때 다시 동의받기

## 5. 사용자 흐름

1. 요양보호사가 처음 설정(1/2)에서 "다음"을 눌러 동의 화면(2/2)을 본다.
2. 항목을 하나씩 체크하거나 "모두 동의하기"를 누른다. 필요하면 "자세히 보기"를 펼친다.
3. "동의하고 시작하기"를 누르면 시스템은 1단계 값과 동의 항목을 서버에 보내 저장한다.
4. 요양보호사는 홈(`/v1120`)을 본다.

## 6. 기능 요구사항

- FR-1: 항목 목록은 `CONSENT_ITEMS`(personal·health·guardian·overseas)를 그대로 쓴다.
- FR-2: 모든 항목이 체크돼야 제출 버튼이 활성화되고, 아니면 "모든 항목에 동의해야 쓸 수 있어요"를 보여 준다.
- FR-3: 제출 때 `sessionStorage["v1120-onboarding"]`이 없으면 제출을 막고 `/v1120/onboarding`으로 돌려보낸다. 있으면 이름·자격번호를 숨은 칸에 넣고 저장소를 지운다.
- FR-4: 서버는 세션을 확인하고(`verifySession`), `next=/v1120`인데 네 항목 중 하나라도 빠지면 400 "모든 항목에 동의해야 쓸 수 있어요."를 돌려준다.
- FR-5: 서버는 이름·자격번호와 `consentedAt=지금`, `consentItems="personal,health,guardian,overseas"`를 저장하고 `/v1120`으로 303 이동한다.

## 7. 비기능 요구사항

- 성능: 제출 1번, DB 쓰기 1번
- 접근성: 체크 줄 높이 48px 이상, 체크박스 24px, "모두 동의하기"는 `aria-pressed`, 글자 18px
- 보안: 로그인 세션이 있어야 저장된다. 동의 항목은 화면과 서버 양쪽에서 확인한다.
- 로깅/모니터링: 동의 시각·항목이 DB에 남는다 (감사 로그 OPS-4는 P2).

## 8. 수용 기준

- [ ] Given 동의 화면에서 세 항목만 체크했을 때, When 시작 버튼을 보면, Then 버튼이 막혀 있다.
- [ ] Given "모두 동의하기"를 눌렀을 때, When 다시 누르면, Then 네 항목이 모두 꺼진다.
- [ ] Given 화면을 거치지 않고 `consent=personal`만 담아 서버로 보냈을 때, When 요청이 처리되면, Then 400 오류가 나고 동의가 저장되지 않는다.
- [ ] Given 네 항목에 동의하고 시작했을 때, When 내 정보 > 동의한 내용을 열면, Then 오늘 날짜와 네 항목 "✓ 동의함"이 보인다.
- [ ] Given 처음 설정을 거치지 않고 동의 화면 주소로 바로 들어왔을 때, When 시작을 누르면, Then 처음 설정 화면으로 돌아간다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음. STB-7에 "필수 동의 누락 시 400"을 넣을 수 있다.
- 수동 확인: 자세히 보기 4개 펼침, 문구가 처리방침과 같은지 기획 확인 (LAW-12)

## 10. 리스크와 열린 질문

- 리스크: 국외 이전 문구는 Groq의 "보관 안 함(ZDR)" 설정을 켠 키 기준이다. AI 키를 바꾸면 그 계정도 ZDR을 켜야 문구가 맞다 (`_consent.ts` 주석).
- 열린 질문:
  - 동의하지 않고 나가려는 사람에게 보여 줄 화면이 없다 (거부 시 안내는 "자세히 보기" 문구에만 있음)
  - 수급자 본인 동의는 누가·어떻게 받는지 (지금은 요양보호사 동의만 받음)
  - 동의 문구 버전을 기록할지 (문구가 바뀌면 누가 어느 문구에 동의했는지 알 수 없음)
