# PRD: 개인정보 처리방침

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사·보호자 | 1-1 로그인·처음 설정 | (화면 ID 없음) | `/v1120/privacy` | 구현됨 · `feature/v1120` dcaa0df 기준 (LAW-12 리뷰 중) |

## 1. 배경

- 현재 문제: 개인정보 보호법상 처리방침을 공개해야 하고, 손다음은 건강정보·보호자 제공·국외 이전이 있어 적을 내용이 많다.
- 왜 지금 필요한가: P0(LAW-12). 가족이 아닌 보호자(D-49)에게 보고서를 주는 내용을 넣어야 한다.
- 관련 문서/이슈: LAW-12, LAW-3, D-49, D-50, `docs/prd/03-legal.md`

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 누구나 로그인 없이 손다음이 모으는 정보·쓰는 곳·보관 기간·문의처를 읽는다.
- 기대 효과: 법적 공개 의무를 채우고, 동의 화면과 같은 내용을 한곳에서 보여 준다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사 (동의 화면·내 정보에서 들어옴)
- 보조 사용자: 보호자 (보호자 내 정보 예시에서 들어옴), 심사위원
- 관리자 또는 운영자 영향: 보호책임자 이름·이메일을 정해 채워야 한다.

## 4. 범위

이번 작업에 포함:

- [x] 절: 모으는 정보 / 쓰는 곳 / 보호자 제공 / 국외 이전 / 보관 기간 / 문의
- [x] 국외 이전 표와 음성 인식 안내는 동의 화면과 같은 데이터(`OVERSEAS_ROWS`, `SPEECH_NOTICE`)
- [x] 보관 기간: 탈퇴할 때까지, 삭제한 수급자는 14일 뒤 완전히 지움, 녹음 원본은 저장 안 함, 급여제공기록 5년 보관은 기관 의무라 손다음이 대신하지 않음
- [x] 침해 신고 기관(개인정보침해신고센터 118, 개인정보분쟁조정위원회)
- [x] 시행일 2026년 11월 28일

이번 작업에 포함하지 않음:

- [ ] 처리방침 변경 이력·이전 버전 보기
- [ ] 영문 처리방침

## 5. 사용자 흐름

1. 사용자가 동의 화면·내 정보·보호자 내 정보의 "개인정보 처리방침" 링크를 누른다.
2. 시스템은 로그인 확인 없이 처리방침 화면을 보여 준다.
3. 사용자는 읽고 뒤로 돌아간다.

## 6. 기능 요구사항

- FR-1: 각 절을 제목 + 문장 목록으로 보여 준다 (`SECTIONS` 상수).
- FR-2: 국외 이전 절은 `OVERSEAS_ROWS`(받는 곳·보내는 것·언제·보관)와 "데이터베이스는 일본 도쿄에 저장돼요", "국외 이전에 동의하지 않으면 손다음을 쓸 수 없어요"를 보여 준다.
- FR-3: 문의 절에 보호책임자·이메일 칸과 법정대리인 요청 안내를 둔다.

## 7. 비기능 요구사항

- 성능: 정적 내용, DB 호출 없음
- 접근성: 글자 16~18px, 제목 구조(h1·절 제목)
- 보안: 개인정보를 표시하지 않는 공개 페이지
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 로그인하지 않은 보호자가, When `/v1120/privacy`를 열면, Then 처리방침 전체가 보인다.
- [ ] Given `_consent.ts`의 국외 이전 받는 곳을 고쳤을 때, When 처리방침과 동의 화면을 열면, Then 두 화면 내용이 같다.
- [ ] Given 처리방침 화면에서, When 문의 절을 보면, Then 보호책임자 이름과 이메일이 채워져 있다. (지금은 빈칸 — 미충족)

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 기획이 `03-legal.md`와 문장 대조, 로그아웃 상태로 열기

## 10. 리스크와 열린 질문

- 리스크: 보호책임자·이메일이 빈칸인 채로 제출되면 법적 요건 미충족 (D-50).
- 열린 질문:
  - 보호책임자 이름·이메일 누구로 할지 (기획, 11/6까지)
  - 로그인 없이 열리는 것이 `proxy.ts`의 `/v1120` 임시 예외 덕분인지 확인 필요 — main에서 예외를 빼면 `/v1120/privacy`도 공개 경로에 넣어야 하는지
  - 처리방침에 "삭제한 수급자 14일 뒤 완전히 지움"이라고 쓰지만 자동 삭제(STB-6 Cron)는 아직 없다
