# PRD: 기록 상태에 따라 바뀌는 버튼

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-2 홈 · 오늘의 돌봄 | C-03 카드 | `/v1120` → 서버 액션 `startVisit` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 기록은 녹음 → AI 정리 → 기록 확인 → 보내기 여러 단계라, 중간에 멈추면 어디서 이어야 할지 헷갈린다. 녹음 중 앱이 꺼지는 일도 있다 (STB-3).
- 왜 지금 필요한가: D-27(문장마다 저장)로 멈춘 녹음을 이어 쓸 수 있게 되어, 홈에서 그 상태를 알려 줘야 한다.
- 관련 문서/이슈: STB-1, STB-3, D-27, `docs/prd/07-features.md` 1-2

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 카드마다 지금 해야 할 일 하나를 버튼으로 보고 누르면 그 단계로 간다.
- 기대 효과: 같은 날 같은 수급자 방문이 두 번 생기지 않고, 멈춘 기록을 잃지 않는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 홈 "마무리 못 한 기록" 카드는 위아래로 쌓고(가장 최근 기록 "OOO 수급자 · 날짜 외 N건" + 넓은 "이어서 하기"), 2건 이상이면 "이어서 하기"가 아래 시트 "어느 기록부터 마무리할까요?"를 열어 수급자·날짜·진행 상태(녹음하다 멈춤·기록 정리 중·확인하고 보내기 전)로 고르게 한다. 1건이면 바로 이동 (11/6 팀 피드백, `_components/ResumeSheet.tsx`)
- [x] 홈 "서류 만들기"는 수급자가 여럿이면 수급자 탭 대신 `/v1120/documents`에서 수급자를 고른다 (11/6)
- [x] 하단 메뉴 탭 화면(홈·수급자·게시판·내 정보, 보호자 홈·게시판·내 정보)은 등장 모션 없이 바로 보이고, 세부 화면은 모션을 유지한다 (`Screen tab`, 11/6 팀 피드백)
- [x] 상태별 버튼 문구

  | 방문 상태 | 버튼 | 누르면 |
  | --- | --- | --- |
  | 방문 없음(`NOT_STARTED`), 녹음 중인데 내용 없음 | 기록하기 | 녹음 화면 |
  | 녹음 중(`RECORDING`)이고 내용 있음 | 이어서 기록하기 + "녹음이 중간에 멈췄어요. 이어서 기록할 수 있어요." | 녹음 화면 |
  | 녹음 끝·정리 중(`RECORDED`·`SUMMARIZING`) | 기록 확인하고 보내기 | AI 정리 화면 |
  | 정리됨(`DRAFT_READY`) | 기록 확인하고 보내기 | 기록 확인(`review?resume=1`) |
  | 보냄(`SENT`) | ✓ 전송 완료 (링크) | 보낸 화면(링크 다시 보내기) |
- [x] 오늘 보내지 않은 방문이 있으면 이어 쓰고, 없을 때만 새 방문 생성
- [x] "정보 수정" 버튼은 상태와 상관없이 늘 보임

이번 작업에 포함하지 않음:

- [ ] 같은 수급자를 하루 두 번 방문하는 경우 (보낸 뒤 "기록하기"는 다시 나오지 않음)
- [ ] 방문 취소·결석 처리

## 5. 사용자 흐름

1. 요양보호사가 홈 카드에서 상태 버튼을 누른다.
2. 시스템은 내 수급자인지 확인하고, 오늘(KST) 보내지 않은 방문을 찾거나 새로 만든 뒤 상태에 맞는 화면으로 보낸다.
3. 요양보호사는 이어서 할 단계 화면을 본다.

## 6. 기능 요구사항

- FR-1: 버튼 문구는 `interrupted`(녹음 중 + 내용 있음)면 "이어서 기록하기", `NOT_STARTED`·`RECORDING`이면 "기록하기", 그 밖(보내기 전)은 "기록 확인하고 보내기"다.
- FR-2: `SENT`면 폼 대신 `/v1120/visit/{id}/sent` 링크 "✓ 전송 완료"를 보여 준다.
- FR-3: `startVisit(clientId)`는 `ownClientOrThrow`로 내 수급자인지 확인한다.
- FR-4: 오늘 KST 범위에서 `SENT`가 아닌 가장 최근 방문을 찾고, 없으면 `RECORDING`·`startedAt=지금`으로 만든다.
- FR-5: 이동할 곳: `DRAFT_READY`→`review?resume=1`, `RECORDED`·`SUMMARIZING`→`processing`, 그 밖→`record`.

## 7. 비기능 요구사항

- 성능: 버튼 한 번에 DB 조회 1번 + 필요 시 생성 1번
- 접근성: 버튼 2개를 2열로, 큰 버튼, 멈춤 안내는 글로 표시
- 보안: 남의 수급자 id로 요청하면 "수급자를 찾을 수 없어요." 오류 (SEC-2). 보낸 방문은 고치는 화면으로 보내지 않음 (STB-1)
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 오늘 방문을 시작하지 않은 수급자가, When "기록하기"를 누르면, Then 새 방문이 하나 생기고 녹음 화면이 열린다.
- [ ] Given 녹음 중 한 문장을 말하고 앱을 닫았을 때, When 홈을 다시 열면, Then "이어서 기록하기"와 멈춤 안내가 보이고 누르면 말한 내용이 남아 있다.
- [ ] Given 기록 확인에서 임시저장한 방문이, When 홈에서 버튼을 누르면, Then 새 방문을 만들지 않고 기록 확인(resume) 화면이 열린다.
- [ ] Given 보낸 방문이, When 홈 카드를 보면, Then "✓ 전송 완료"가 보이고 누르면 보낸 화면이 열린다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음. STB-7에 "같은 날 두 번 눌러도 방문 1개"를 넣을 수 있다.
- 수동 확인: 상태 5가지를 차례로 만들어 버튼 확인, 아이폰에서 녹음 중 앱 종료 (STB-3)

## 10. 리스크와 열린 질문

- 리스크: 보낸 뒤 같은 날 다시 방문하는 경우 새 기록을 시작할 방법이 없다.
- 열린 질문:
  - `RECORDED`·`SUMMARIZING` 상태도 "기록 확인하고 보내기"로 보이는데, AI 정리 중이라는 걸 따로 알릴지
  - 상태 배지(`StatusBadge`) 문구와 버튼 문구가 서로 맞는지 디자인 확인 필요
