# PRD: 수급자 등록 바로가기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-2 홈 · 오늘의 돌봄 | C-03 → C-07 | `/v1120` 아래 고정 버튼 → `/v1120/client/new` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 처음 가입한 요양보호사는 수급자가 없어 홈이 비어 있다. 수급자 탭으로 가야 등록할 수 있으면 첫 기록까지 단계가 늘어난다.
- 왜 지금 필요한가: 첫 사용자가 바로 수급자를 등록하고 기록까지 가도록 홈에 입구를 둔다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-2, C-07

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 홈에서 바로 새 수급자 등록 화면으로 간다.
- 기대 효과: 첫 수급자 등록까지 화면 이동을 한 번으로 줄인다.

## 3. 대상 사용자

- 주요 사용자: 처음 쓰는 요양보호사, 새 수급자를 맡은 요양보호사
- 보조 사용자: 체험 계정 사용자
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 홈 화면 아래 고정 영역에 "+ 수급자 등록하기" 버튼
- [x] 누르면 `/v1120/client/new` (등록 화면은 1-3-2)

이번 작업에 포함하지 않음:

- [ ] 수급자가 없을 때 버튼을 따로 강조하는 빈 화면
- [ ] 기관 시스템에서 수급자 가져오기

## 5. 사용자 흐름

1. 요양보호사가 홈 아래 "+ 수급자 등록하기"를 누른다.
2. 시스템은 수급자 등록 화면을 연다.
3. 요양보호사는 등록을 마치고 보호자 초대 또는 수급자 정보 화면으로 간다 (1-3-2).

## 6. 기능 요구사항

- FR-1: 홈 `Screen`의 `bottom` 영역에 `LinkButton href="/v1120/client/new"`를 둔다. 수급자 수·오늘 건수와 상관없이 늘 보인다.

## 7. 비기능 요구사항

- 성능: 링크 이동만
- 접근성: 화면 아래 고정, 큰 버튼(엄지로 누르기 쉬운 위치)
- 보안: 등록 화면에서 로그인 확인 (`requireCaregiver`)
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 수급자가 0명인 요양보호사가, When 홈을 열면, Then 아래에 "+ 수급자 등록하기"가 보인다.
- [ ] Given 홈에서, When "+ 수급자 등록하기"를 누르면, Then 수급자 등록 화면이 열린다.
- [ ] Given 수급자가 여러 명이라 목록이 길 때, When 홈을 아래로 스크롤해도, Then 버튼이 화면 아래에 계속 보인다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 작은 화면(아이폰 SE)에서 버튼이 카드를 가리지 않는지

## 10. 리스크와 열린 질문

- 리스크: 하단 메뉴와 고정 버튼이 함께 있어 작은 화면에서 목록 보이는 영역이 줄어든다.
- 열린 질문:
  - 수급자가 0명일 때 "먼저 수급자를 등록해 주세요" 같은 빈 화면 안내를 둘지
  - 수급자 탭에도 등록 버튼이 있다면 홈에 둘 다 필요한지 (디자인 판단)
