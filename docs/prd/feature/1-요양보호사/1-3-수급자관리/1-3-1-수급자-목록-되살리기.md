# PRD: 수급자 목록 · 되살리기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-3 수급자 관리 | 수급자 탭 (C-09를 합침) | `/v1120/clients` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 홈(C-03)에는 오늘 방문할 수급자만 보여서, 담당 수급자 전체를 보거나 방문 기록·서류·게시판으로 바로 가는 곳이 없었다. 실수로 삭제한 수급자를 되돌릴 곳도 필요했다.
- 왜 지금 필요한가: 하단 메뉴를 홈·수급자·게시판·내 정보로 정하면서(D-32) 옛 수급자 관리 화면(C-09)을 수급자 탭에 합쳤다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-3, `docs/design/02-screens.md` C-09, D-32

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 담당 수급자 전체를 보고, 수급자마다 방문 기록·서류 만들기·게시판으로 바로 가며, 삭제한 수급자를 14일 안에 되살린다.
- 기대 효과: 수급자 관련 일을 한 화면에서 시작하고, 잘못 삭제해도 기록을 잃지 않는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 체험 계정 사용자 (예시 수급자 3명)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] "담당 수급자 N명"과 수급자 카드(이름, 나이·성별·등급, 방문 일정), 이름순
- [x] 카드마다 방문 기록 · 서류 만들기 · 게시판 버튼, 게시판 버튼에 안 읽은 보호자 댓글 수("게시판 2")
- [x] 아래 고정 버튼 "+ 수급자 등록하기"
- [x] "삭제한 수급자" 묶음: "14일이 지나면 완전히 지워져요" 안내, 되살리기, 완전히 지우기
- [x] 완전히 지우기를 요청한 수급자는 목록에서 빠짐

이번 작업에 포함하지 않음:

- [ ] 수급자 검색·정렬 바꾸기·묶음(요일별 등)
- [ ] 다른 요양보호사에게 수급자 넘기기
- [ ] 완전히 지우기를 취소하기

## 5. 사용자 흐름

1. 요양보호사가 하단 메뉴 "수급자"를 누른다.
2. 시스템은 기한이 지난 완전 삭제 예약을 먼저 처리하고, 내 수급자를 활성/삭제됨으로 나눠 보여 준다.
3. 요양보호사는 카드를 눌러 수급자 정보로 가거나, 카드 아래 버튼으로 방문 기록·서류·게시판으로 간다.
4. 삭제한 수급자에서 "되살리기"를 누르면 시스템은 그 수급자를 다시 활성으로 바꾸고 목록을 새로 보여 준다.

## 6. 기능 요구사항

- FR-1: `myClients()`로 로그인한 요양보호사의 수급자 중 `purgeAt`이 없는 것만 이름순으로 읽는다 (SEC-2).
- FR-2: 읽기 전에 `purgeExpiredClients()`로 `purgeAt`이 지난 수급자와 그 방문·보고서·댓글·서류를 지운다.
- FR-3: `isActive`가 참이면 위 목록, 거짓이면 "삭제한 수급자"에 둔다.
- FR-4: 카드 정보는 나이("82세")·성별·등급(없으면 "등급 미입력")·방문 일정("월·수·금 09:00–11:00")이다.
- FR-5: 게시판 버튼 숫자는 `myUnreadByClient()`의 수급자별 안 읽은 보호자 댓글 수다. 0이면 "게시판"만.
- FR-6: "되살리기"는 서버 액션 `restoreClient(id)`로 내 수급자인지 확인한 뒤 `isActive=true`로 바꾸고 `/v1120/clients`로 돌아온다.
- FR-7: "완전히 지우기"는 `/v1120/client/[id]/delete?step=permanent`로 간다 (1-3-5).

## 7. 비기능 요구사항

- 성능: 수급자 목록과 안 읽은 댓글 수를 동시에 읽는다(`Promise.all`). 기한 지난 삭제는 목록을 열 때 같이 처리하므로, 지울 수급자가 많으면 첫 로딩이 느려질 수 있다.
- 접근성: 버튼 높이 48px 이상(`min-h-12`), 글자 16px 이상, "›"는 `aria-hidden` (DIF-1)
- 보안: 수급자 이름은 암호화된 값을 풀어서 보여 준다(SEC-5). 남의 수급자 id로 되살리기를 요청해도 거부한다.
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 활성 수급자 3명이 있는 요양보호사가, When 수급자 탭을 열면, Then "담당 수급자 3명"과 카드 3개가 이름순으로 보인다.
- [ ] Given 수급자 A의 게시판에 안 읽은 보호자 댓글이 2개 있을 때, When 수급자 탭을 열면, Then A 카드의 게시판 버튼이 "게시판 2"로 보인다.
- [ ] Given 수급자 A를 삭제한 상태에서, When 수급자 탭을 열면, Then A는 "삭제한 수급자"에만 보이고, "되살리기"를 누르면 위 목록으로 돌아온다.
- [ ] Given 완전히 지우기를 요청한 수급자 B가 있을 때, When 수급자 탭을 열면, Then B는 어느 묶음에도 보이지 않는다.
- [ ] Given 다른 요양보호사의 수급자 id로, When `restoreClient`를 부르면, Then "수급자를 찾을 수 없어요." 오류가 나고 바뀌지 않는다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: STB-7 권한 테스트에 "남의 수급자 되살리기 거부"를 넣을 수 있다.
- 수동 확인: 삭제 → 되살리기 → 홈·게시판 탭에 다시 보이는지, 실기기 2종 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크: 완전 삭제가 Cron이 아니라 목록을 열 때 일어나서(STB-6 전), 아무도 목록을 열지 않으면 14일이 지나도 지워지지 않는다.
- 열린 질문:
  - 일반 삭제(`deleteClient`)는 `isActive=false`만 바꾸고 삭제 시각을 남기지 않는다. 안내 문구 "14일이 지나면 완전히 지워져요"와 달리 자동으로 지워지지 않는데(코드 주석 shortcut), 문구를 고칠지 삭제 시각 칸을 만들지
  - 수급자가 많아지면 검색이 필요한지 (요양보호사 1명당 담당 수)
