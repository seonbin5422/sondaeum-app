# PRD: 수급자 등록

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-3 수급자 관리 | C-07 | `/v1120/client/new` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 기록·보고서·서류는 모두 수급자 정보(방문 요일·시간, 보호자, 장기요양인정번호)를 바탕으로 만들어진다. 이 정보가 없으면 홈에 방문이 뜨지 않고 보고서를 보낼 사람도 없다.
- 왜 지금 필요한가: 가족이 없는 수급자가 있어 보호자 관계에 사회복지사·주민센터·후견인·없음을 넣었고(D-49), 등록 직후 보호자를 게시판에 초대하는 흐름을 만들었다(D-33). 수급자 개인정보 암호화(SEC-5)도 등록 때 적용한다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-3, `docs/design/02-screens.md` C-07, D-31, D-33, D-49, SEC-2, SEC-5

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 한 화면에서 수급자 기본 정보·방문 일정·보호자·건강 정보를 적고 등록한다.
- 기대 효과: 등록하자마자 홈 일정에 나타나고, 보호자를 바로 게시판에 초대할 수 있다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 기관 관리자 화면은 범위 밖(D-07). 요양보호사가 직접 등록한다.

## 4. 범위

이번 작업에 포함:

- [x] 필수: 수급자 이름, 장기요양인정번호, 방문 요일, 시작·끝 시간(기본 09:00–11:00), 보호자 성함(관계가 "없음"이 아닐 때)
- [x] 선택: 나이, 성별, 장기요양등급(1~5등급·인지지원등급), 보호자 전화번호, 알레르기, 병력, 복용 중인 약, 수급자 전화번호
- [x] 보호자 관계: 딸·아들·배우자·이웃·친척·기타 / 기관 사회복지사·주민센터 담당자·후견인 / 없음
- [x] "없음"을 고르면 보호자 칸을 숨기고 "보고서를 보내지 않고 방문 기록과 서류로만 남겨요" 안내
- [x] 필수 칸이 비면 등록 버튼을 막고 이유를 보여 줌, 서버에서도 다시 확인
- [x] 수급자 이름·전화번호, 보호자 전화번호 암호화 저장
- [x] 등록 후 보호자가 있으면 초대 화면(1-3-7), 없으면 수급자 정보(1-3-3)로 이동

이번 작업에 포함하지 않음:

- [ ] 장기요양인정번호 형식 검사, 중복 수급자 검사
- [ ] 보호자 여러 명 등록
- [ ] 보호자 이름·장기요양인정번호·병력 암호화 (SEC-5 남은 일)
- [ ] 장기요양인정서 사진으로 자동 입력

## 5. 사용자 흐름

1. 요양보호사가 수급자 탭의 "+ 수급자 등록하기"(또는 홈 바로가기)를 누른다.
2. 시스템은 빈 등록 폼을 보여 준다.
3. 요양보호사가 칸을 채운다. 필수 칸이 비어 있으면 등록 버튼이 막히고 "장기요양인정번호를 적어 주세요" 같은 이유가 보인다.
4. "등록하기"를 누르면 시스템은 다시 검증하고 암호화해 저장한 뒤 초대 화면 또는 수급자 정보로 보낸다.

## 6. 기능 요구사항

- FR-1: 화면 검증 순서는 이름 → 장기요양인정번호 → 보호자 성함("없음"이 아닐 때) → 방문 요일이다. 첫 번째로 빠진 것을 버튼 아래 이유로 보여 준다.
- FR-2: 서버 액션 `saveClient`는 이름·인정번호·요일·시작·끝 시간과(관계가 "없음"이 아니면) 보호자 성함을 다시 확인하고, 빠지면 "필수 항목을 모두 적어 주세요."로 거부한다.
- FR-3: 방문 요일은 0(일)~6(토) 정수만 받아 정렬하고, `"월,수,금 09:00-11:00"` 형식으로 `scheduleLabel`에 저장한다.
- FR-4: 나이는 숫자 1~3자리일 때만, 등급은 정해진 목록에 있을 때만 저장하고 아니면 비운다.
- FR-5: 관계를 고르지 않으면 서버에서 "기타"로 저장한다.
- FR-6: 관계가 "없음"이면 보호자 성함은 빈 글자, 전화번호는 비워 저장한다.
- FR-7: 수급자 이름·전화번호, 보호자 전화번호는 `sealPII`로 암호화한다.
- FR-8: 로그인한 요양보호사를 담당자(`caregiverId`)로 저장한다.
- FR-9: 저장 뒤 관계가 "없음"이면 `/v1120/client/[id]`, 아니면 `/v1120/client/[id]/invite?new=1`로 보낸다.

## 7. 비기능 요구사항

- 성능: 저장은 한 번의 DB 쓰기
- 접근성: 요일·등급·관계는 큰 버튼(48px 이상)과 `aria-pressed`, 칸마다 이름표와 도움말("장기요양인정서에 적힌 번호예요.") (DIF-1)
- 보안: 로그인한 요양보호사만 등록, 개인정보 암호화(SEC-5). 등록 시 개인정보 수집은 동의(LAW-3) 범위 안
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 등록 폼에서 장기요양인정번호만 비어 있을 때, When 화면을 보면, Then 등록 버튼이 눌리지 않고 "장기요양인정번호를 적어 주세요"가 보인다.
- [ ] Given 보호자 관계로 "딸"을 고르고 필수 칸을 모두 채웠을 때, When "등록하기"를 누르면, Then 초대 화면으로 가고 "✓ {이름} 정보를 등록했어요"가 보인다.
- [ ] Given 보호자 관계로 "없음"을 골랐을 때, When 보호자 성함 없이 등록하면, Then 저장되고 수급자 정보 화면으로 간다.
- [ ] Given 월·수·금, 09:00–11:00으로 등록한 수급자가, When 수요일에 홈을 열면, Then 오늘 방문 목록에 보인다.
- [ ] Given 등록한 수급자가, When DB의 이름·전화번호 칸을 보면, Then 평문이 아닌 암호화된 값이 저장되어 있다.
- [ ] Given 화면 검증을 건너뛰고 요일 없이 `saveClient`를 부르면, When 저장을 시도하면, Then "필수 항목을 모두 적어 주세요." 오류가 난다.

## 9. 검증 계획

- 단위 테스트: 없음. `scheduleLabel` 만들기·나이/등급 거르기를 함수로 빼면 단위 테스트 가능
- 통합 테스트: 등록 → 홈 일정 표시 → 초대 화면 이동
- 수동 확인: 관계 "가족/기관/없음" 3가지로 등록, 실기기 키보드(숫자·전화) 확인 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크: 보호자 이름·장기요양인정번호·병력이 아직 평문이라 DB 유출 시 노출된다 (SEC-5 리뷰 중).
- 열린 질문:
  - 화면 검증에 보호자 관계 선택이 없어, 관계를 고르지 않으면 "기타"로 저장된다. 관계를 필수로 할지
  - 시작 시간이 끝 시간보다 늦은 경우를 막을지 (지금은 검사 없음)
  - 수급자 정보 화면의 "꼭 기억할 것"(`personalNotes`)은 등록 폼에 칸이 없다. 폼에 넣을지, 병력·알레르기·약을 묶어 보여 줄지
  - 같은 장기요양인정번호를 두 번 등록하는 경우를 막을지
