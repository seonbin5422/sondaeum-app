# PRD: 수급자 정보

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-3 수급자 관리 | C-05 | `/v1120/client/[id]` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 방문 전에 알레르기·병력·복용 약을 확인하지 않으면 식사·복약 돌봄에서 실수가 생길 수 있다. 보호자 연락처도 급할 때 바로 찾아야 한다.
- 왜 지금 필요한가: 옛 화면에서는 홈 위 모달이었는데, 1120.ver에서 수급자 탭의 화면으로 바꾸고 방문 기록·서류·게시판·초대로 가는 입구를 모았다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-3, `docs/design/02-screens.md` C-05, 04-prd 하루 사용 시나리오 2번

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 수급자 한 명의 건강·연락 정보를 한눈에 보고, 그 수급자와 관련된 다음 일(방문 기록·서류·게시판·초대·수정·삭제)로 간다.
- 기대 효과: 방문 전 확인 시간을 줄이고, 수급자별 일을 이 화면에서 시작한다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 머리: 이름, 나이·성별, "장기요양 {등급}"(없으면 "등급 미입력"), 방문 일정
- [x] "꼭 기억할 것" 상자 (`personalNotes`가 있을 때만)
- [x] 보호자가 아직 게시판에 안 들어왔으면 "{성함} {호칭}님이 아직 게시판에 들어오지 않았어요"와 초대 버튼
- [x] 정보 목록: 알레르기, 병력, 복용 중인 약, 장기요양인정번호, 수급자 전화번호, 보호자(성함·관계), 보호자 전화번호 — 비면 "없음"
- [x] 버튼: 방문 기록 보기(최근 보낸 날짜 표시), 서류 만들기, 게시판(보호자가 있을 때), 정보 수정, 수급자 삭제

이번 작업에 포함하지 않음:

- [ ] 전화번호 눌러 전화 걸기
- [ ] 이 화면에서 바로 "기록하기"
- [ ] 보호자 실제 입장 여부 표시 (보호자 로그인 D-44 이후)

## 5. 사용자 흐름

1. 요양보호사가 수급자 탭에서 수급자 카드를 누른다.
2. 시스템은 내 수급자인지 확인하고 정보와 최근 보낸 방문 날짜를 보여 준다.
3. 요양보호사는 알레르기·병력·약을 확인하고, 필요한 버튼을 눌러 다음 화면으로 간다.

## 6. 기능 요구사항

- FR-1: `myClient(id)`로 내 수급자이고 완전 삭제 예약이 없는 것만 읽는다. 없으면 404 (SEC-2).
- FR-2: `myHistory(id)`에서 상태가 SENT인 가장 최근 방문을 찾아 "방문 기록 보기 (최근 M월 D일)"로 보여 준다.
- FR-3: 보호자 관계가 "없음"이면 보호자·보호자 전화번호 줄, 초대 상자, 게시판 버튼을 숨긴다.
- FR-4: 호칭은 관계에 따라 보호자 / 사회복지사 / 담당자 / 후견인 (`contactTitle`).
- FR-5: 초대 상자는 `guardianJoined`가 거짓일 때 보인다.
- FR-6: 암호화된 이름·전화번호는 풀어서 보여 준다.

## 7. 비기능 요구사항

- 성능: 수급자 1명과 방문 이력을 읽는다. 방문 이력은 전체를 읽고 화면에서 하나만 쓴다.
- 접근성: 글자 18px 이상(`text-lg`), 링크 높이 48px 이상, 빈 값은 회색 "없음"
- 보안: 남의 수급자 id면 404. 건강정보(민감정보)를 보여 주므로 로그인 필수
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 알레르기 "땅콩"이 등록된 수급자가, When 수급자 정보를 열면, Then 알레르기 줄에 "땅콩"이 보인다.
- [ ] Given 병력이 비어 있는 수급자가, When 수급자 정보를 열면, Then 병력 줄에 회색 "없음"이 보인다.
- [ ] Given 보호자 관계가 "없음"인 수급자가, When 수급자 정보를 열면, Then 보호자 줄·초대 상자·게시판 버튼이 보이지 않는다.
- [ ] Given 6월 3일에 보고서를 보낸 수급자가, When 수급자 정보를 열면, Then "방문 기록 보기 (최근 6월 3일)"이 보인다.
- [ ] Given 다른 요양보호사의 수급자 id로, When `/v1120/client/[id]`를 열면, Then 404가 나온다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: STB-7에 "남의 수급자 정보 404" 추가 가능
- 수동 확인: 관계별(가족·사회복지사·없음) 화면, 긴 병력 글이 줄바꿈되는지 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크: `guardianJoined`가 항상 거짓(코드 shortcut)이라 보호자가 이미 게시판을 봐도 초대 상자가 계속 보인다.
- 열린 질문:
  - "꼭 기억할 것"은 `personalNotes` 칸인데 등록·수정 폼에 입력 칸이 없다. 07-features는 "병력·알레르기·복용 약"이라고 적었는데, 어느 쪽이 맞는지
  - 삭제한 수급자(`isActive=false`)도 주소로 들어오면 이 화면이 열린다. 막을지
  - 보호자 전화번호를 눌러 바로 전화 걸기를 넣을지
