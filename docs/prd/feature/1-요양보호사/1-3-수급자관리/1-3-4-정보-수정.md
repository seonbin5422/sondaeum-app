# PRD: 수급자 정보 수정

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-3 수급자 관리 | C-08 | `/v1120/client/[id]/edit` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 방문 요일이 바뀌거나 보호자가 바뀌고, 새 병력·약이 생긴다. 고치지 않으면 홈 일정과 방문 전 확인 정보가 틀린다.
- 왜 지금 필요한가: 등록(C-07)과 같은 폼(`ClientForm`)을 쓰므로, 등록의 검증·암호화 규칙이 수정에도 똑같이 적용되어야 한다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-3, `docs/design/02-screens.md` C-08

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 등록한 수급자의 정보를 기존 값이 채워진 폼에서 고쳐 저장한다.
- 기대 효과: 일정·보호자·건강 정보가 최신으로 유지된다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 등록 폼과 같은 칸, 기존 값으로 채워 열기 (요일·시간은 저장된 일정에서 읽음)
- [x] 제목 "{이름} 정보 수정", 버튼 "고친 내용 저장하기"
- [x] 등록과 같은 화면·서버 검증, 같은 암호화
- [x] 저장 후 수급자 정보(1-3-3)로 이동
- [x] 보호자 관계를 "없음" ↔ 다른 관계로 바꾸기

이번 작업에 포함하지 않음:

- [ ] 수정 이력 남기기
- [ ] 이미 보낸 보고서 내용 바꾸기 (보낸 뒤 잠금, STB-1)

## 5. 사용자 흐름

1. 요양보호사가 수급자 정보 화면 아래 "정보 수정"을 누른다.
2. 시스템은 내 수급자인지 확인하고 기존 값이 채워진 폼을 보여 준다.
3. 요양보호사가 칸을 고치고 "고친 내용 저장하기"를 누른다.
4. 시스템은 검증·암호화 후 저장하고 수급자 정보로 돌려보낸다.

## 6. 기능 요구사항

- FR-1: `myClient(id)`로 내 수급자만 연다. 없으면 404.
- FR-2: 폼에 숨은 `id`를 넣어 `saveClient`가 수정으로 처리한다.
- FR-3: 서버는 `ownClientOrThrow(id)`로 내 수급자인지 다시 확인한 뒤 `update`한다.
- FR-4: 검증·저장 형식·암호화는 등록(1-3-2 FR-1~FR-7)과 같다.
- FR-5: 저장 후 `/v1120/client/[id]`로 보낸다 (초대 화면으로 가지 않는다).

## 7. 비기능 요구사항

- 성능: 한 번의 DB 쓰기
- 접근성: 등록 폼과 같음
- 보안: 남의 수급자 id로 수정 요청 시 "수급자를 찾을 수 없어요." 거부 (SEC-2)
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 월·수 방문 수급자가, When 수정 화면을 열면, Then 월·수 요일 버튼이 눌린 상태로 보인다.
- [ ] Given 방문 요일을 화·목으로 바꿔 저장했을 때, When 목요일에 홈을 열면, Then 그 수급자가 오늘 목록에 보인다.
- [ ] Given 보호자 관계를 "딸"에서 "없음"으로 바꿔 저장했을 때, When 수급자 정보를 열면, Then 보호자 줄과 게시판 버튼이 사라진다.
- [ ] Given 이름을 지우고, When 저장하려 하면, Then 버튼이 막히고 "수급자 이름을 적어 주세요"가 보인다.
- [ ] Given 다른 요양보호사의 수급자 id를 숨은 칸에 넣어, When 저장하면, Then 오류가 나고 바뀌지 않는다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: STB-7에 "남의 수급자 수정 거부" 추가 가능
- 수동 확인: 각 칸 수정 후 수급자 정보·홈 반영 확인 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크:
  - 보호자를 "없음"으로 바꾸면 게시판이 목록에서 사라지지만, 이미 보낸 보고서 링크와 초대 링크는 그대로 열린다(링크 만료 STB-5 전).
  - 방문 기록의 서비스 시간은 방문마다 저장하지 않고 수급자의 지금 일정(`scheduleLabel`)으로 계산한다(`toHistoryVisit`). 방문 시간을 바꾸면 지난 방문 기록·서류의 시간도 새 시간으로 보인다.
- 열린 질문:
  - 보호자를 다른 사람으로 바꿀 때 이전 보호자가 가진 게시판 링크(`boardToken`)를 새로 만들어야 하는지
  - 지난 방문의 서비스 시간을 방문 때 값으로 고정해 저장할지
