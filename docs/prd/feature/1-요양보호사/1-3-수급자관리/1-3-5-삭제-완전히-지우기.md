# PRD: 수급자 삭제 · 완전히 지우기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-3 수급자 관리 | C-10 삭제 · C-11 완전히 지우기 | `/v1120/client/[id]/delete` (`?step=permanent`) | 구현됨 (LAW-8 리뷰 중) · `feature/v1120` ae8748e 기준 |

## 1. 배경

- 현재 문제: 담당이 끝난 수급자를 목록에서 치워야 하지만, 급여제공기록은 기관이 5년 동안 보관해야 한다. 요양보호사가 바로 지우면 기록이 사라지거나 은폐에 쓰일 수 있다.
- 왜 지금 필요한가: 영구 삭제 전 확인 단계(LAW-8)가 P1 요구사항이다. 개인정보 동의 문구에도 "삭제한 수급자는 14일 뒤 완전히 지워요"라고 알렸다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-3, `docs/design/02-screens.md` C-10·C-11, LAW-8, STB-6, `app/v1120/_consent.ts`

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 수급자를 삭제(되살릴 수 있음)하고, 필요하면 기관 시스템에 옮겼는지 확인한 뒤 완전히 지우기를 요청한다.
- 기대 효과: 실수로 지워도 되돌릴 수 있고, 완전히 지우기 전에 기록 보관 의무를 상기시킨다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 보호자 (삭제하면 보호자 링크가 닫힘)
- 관리자 또는 운영자 영향: 완전 삭제 시 방문·보고서·댓글·서류가 DB에서 지워진다.

## 4. 범위

이번 작업에 포함:

- [x] 삭제 예약 14일이 지난 수급자는 화면을 열 때가 아니라 매일 03:00(KST) Vercel Cron `/api/cron/purge-clients`가 지운다. `CRON_SECRET`이 없으면 500, 틀리면 401 (STB-6, 11/6). 화면은 예약된 수급자를 이미 숨긴다
- [x] 삭제 확인(C-10): "목록과 홈에서 보이지 않아요", "14일 동안은 되살릴 수 있어요", "보호자 게시판 링크는 바로 닫혀요" 안내, 삭제하기·취소
- [x] 완전히 지우기(C-11): "방문 기록, 보고서, 댓글이 모두 지워지고 되살릴 수 없어요"
- [x] "급여제공기록은 기관이 5년 동안 보관해야 해요" 안내와 "기관 시스템에 옮겼어요" 체크
- [x] 수급자 이름을 똑같이 적어야 버튼이 열림, 막힌 이유 표시
- [x] 완전히 지우기는 바로 지우지 않고 14일 뒤로 예약(`purgeAt`)
- [x] 삭제·완전히 지우기 뒤 수급자 탭 스낵바 "~했어요" + "되돌리기" 10초. 완전히 지우기를 되돌리면 예약이 풀리고 "삭제한 수급자"로 돌아간다 (D-58, 1-3-1)
- [x] 예약 시각이 지난 수급자는 수급자 목록을 열 때 방문·보고서·댓글·서류와 함께 지움

이번 작업에 포함하지 않음:

- [ ] 정해진 시각에 자동으로 지우는 Cron (STB-6, 11/20)
- [ ] 지우기 전 기록 내보내기(엑셀 등)

## 5. 사용자 흐름

1. 요양보호사가 수급자 정보 아래 "수급자 삭제"를 누른다.
2. 시스템은 삭제 안내를 보여 주고, "삭제하기"를 누르면 수급자를 숨기고 수급자 탭으로 보낸다.
3. 요양보호사가 수급자 탭 "삭제한 수급자"에서 "완전히 지우기"를 누른다.
4. 시스템은 보관 의무 안내, 체크, 이름 입력칸을 보여 준다.
5. 요양보호사가 체크하고 이름을 적어 "완전히 지우기"를 누르면, 시스템은 14일 뒤 삭제를 예약하고 목록에서 뺀 뒤 "14일 뒤 완전히 지워져요." + "되돌리기"를 10초 보여 준다.

## 6. 기능 요구사항

- FR-1: 삭제는 `deleteClient(id)`: 내 수급자인지 확인하고 `isActive=false`로 바꾼다.
- FR-2: 완전히 지우기 버튼은 "기관 시스템에 옮겼어요" 체크 + 이름 일치(앞뒤 공백 무시)일 때만 열린다. 막히면 "기관 시스템에 옮겼는지 먼저 확인해 주세요" 또는 "수급자 이름을 똑같이 적어 주세요".
- FR-3: `permanentDeleteClient(id)`: 내 수급자인지 확인하고 `purgeAt = 지금 + 14일`을 저장한 뒤 `/v1120/clients?done=purge&id=…`로 간다. `deleteClient`는 `?done=deleted`로 간다.
- FR-7: `cancelPermanentDelete(id)`: 내 수급자인지 확인하고 `purgeAt=null`로 되돌린 뒤 `?done=purge-cancel`로 간다 (D-58).
- FR-4: `purgeAt`이 있는 수급자는 수급자 목록·수급자 정보·게시판에서 보이지 않는다.
- FR-5: `purgeExpiredClients()`는 `purgeAt`이 지난 수급자의 댓글 → 보고서 → 방문 → 서류 댓글 → 서류 → 수급자 순으로 지운다.
- FR-6: 삭제(`isActive=false`)되거나 완전 삭제 예약된 수급자의 게시판은 보호자 링크로 열리지 않는다 (`guardianBoard`).

## 7. 비기능 요구사항

- 성능: 실제 삭제는 수급자 목록을 열 때 한꺼번에 일어나므로, 지울 것이 많으면 그 요청이 느려진다.
- 접근성: 삭제 버튼은 위험 색, 막힌 이유를 글로 보여 줌
- 보안: 남의 수급자는 지울 수 없다. 완전 삭제는 개인정보 파기(동의 문구의 보관 기간)와 맞아야 한다.
- 로깅/모니터링: 삭제 기록(누가 언제 지웠는지)은 남기지 않는다 (감사 로그 OPS-4는 P2).

## 8. 수용 기준

- [ ] Given 수급자 A가 있을 때, When 삭제하기를 누르면, Then 수급자 탭 "삭제한 수급자"에 A가 보이고 홈·게시판 탭에서는 사라진다.
- [ ] Given A를 삭제한 뒤, When 보호자가 A의 게시판 링크를 열면, Then 게시판이 열리지 않는다.
- [ ] Given 완전히 지우기 화면에서 체크만 했을 때, When 이름을 다르게 적으면, Then 버튼이 막히고 "수급자 이름을 똑같이 적어 주세요"가 보인다.
- [ ] Given 체크와 이름이 맞을 때, When 완전히 지우기를 누르면, Then A가 수급자 탭에서 사라지고 DB의 `purgeAt`이 14일 뒤로 저장된다.
- [ ] Given `purgeAt`이 지난 수급자가 있을 때, When 아무 요양보호사가 수급자 탭을 열면, Then 그 수급자와 방문·보고서·댓글·서류가 DB에서 지워진다.

## 9. 검증 계획

- 단위 테스트: 없음. `purgeExpiredClients`는 테스트 DB에서 확인 가능
- 통합 테스트: `purgeAt`을 과거로 바꾼 뒤 목록 열기 → 관련 행 모두 삭제 확인 (STB-7)
- 수동 확인: 삭제 → 보호자 링크 닫힘 → 되살리기 → 링크 다시 열림

## 10. 리스크와 열린 질문

- 리스크:
  - 완전 삭제가 Cron이 아니라 목록 열기에 묶여 있어, 접속이 없으면 14일이 지나도 남는다 (STB-6).
  - 일반 삭제는 삭제 시각을 남기지 않아 "14일 동안 되살릴 수 있어요" 뒤에도 자동으로 지워지지 않는다 (코드 shortcut).
- 열린 질문:
  - 일반 삭제 후 14일이 지나면 자동으로 완전 삭제할지, 안내 문구를 고칠지
  - 완전히 지우기 취소는 스낵바가 떠 있는 10초 동안만 된다. 14일 안 아무 때나 취소할 화면을 둘지 (D-58)
  - 5년 보관 의무가 있는 기록을 앱에서 지워도 되는지 법적 검토 (기관 시스템에 옮겼다는 체크만으로 충분한지)
  - 삭제한 수급자도 주소로 들어가면 수급자 정보·요양보호사 게시판이 열린다. 막을지
