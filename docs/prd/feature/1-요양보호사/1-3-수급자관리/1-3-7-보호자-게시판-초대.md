# PRD: 보호자 게시판 초대

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 (받는 사람: 보호자) | 1-3 수급자 관리 | C-23 | `/v1120/client/[id]/invite` (등록 직후 `?new=1`) | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 보호자는 첫 보고서를 받기 전까지 손다음을 모른다. 보고서를 보내기 전에도 게시판을 알려 줄 방법이 필요했다.
- 왜 지금 필요한가: 수급자 등록 직후 초대 화면으로 오게 정했고(D-33), 보고서를 보내기 전에도 수급자별 게시판 링크로 초대하는 안(D-34 (b)안, 11/1)을 넣었다. 카카오톡 공유 카드도 11/1에 연결했다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-3, `docs/design/02-screens.md` C-23, D-33, D-34, DIF-5

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자에게 게시판 링크와 인사 글을 카카오톡·문자·복사로 보낸다.
- 기대 효과: 보호자가 가입 없이 링크 하나로 게시판에 들어와 보고서를 받아 본다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 보호자 (가족·기관 사회복지사·주민센터 담당자·후견인)
- 관리자 또는 운영자 영향: 카카오 개발자 콘솔에 서비스 도메인 등록 필요 (개발 2)

## 4. 범위

이번 작업에 포함:

- [x] 등록 직후면 "✓ {이름} 정보를 등록했어요"
- [x] 제목 "{호칭}님을 게시판에 초대할까요?", 보호자 성함·전화번호
- [x] 안내 3줄(보고서 자동 게시, 바로 질문, 서류 만들기)과 "{호칭}님께 가는 글" 미리보기
- [x] 카카오톡으로 초대하기 (공유 카드 → 안 되면 휴대폰 공유 창 → 안 되면 글·링크 복사)
- [x] 문자로 보내기 (보호자 전화번호가 있을 때 문자 앱을 글이 채워진 채로 염)
- [x] 링크 복사하기
- [x] 보낸 방법에 맞는 결과 안내, 아래 버튼 "나중에 하기" → 보낸 뒤 "다 됐어요"
- [x] 보호자 관계가 "없음"이면 수급자 정보로 돌려보냄

이번 작업에 포함하지 않음:

- [ ] 앱이 직접 문자·알림톡 보내기 (카카오 알림톡은 범위 밖, D-08)
- [ ] 보호자가 실제로 들어왔는지 확인
- [ ] 초대 링크 만료·다시 만들기 (STB-5)

## 5. 사용자 흐름

1. 요양보호사가 수급자를 등록하거나, 수급자 정보의 "{호칭}님 게시판에 초대하기"를 누른다.
2. 시스템은 수급자 게시판 링크를 만들고(처음이면) 보낼 글을 보여 준다.
3. 요양보호사가 "카카오톡으로 초대하기"를 누르면 카카오톡 공유 카드가 뜨고, 보호자를 골라 보낸다.
4. 시스템은 "✓ {성함} {호칭}님께 초대를 보냈어요"를 보여 주고, 요양보호사는 "다 됐어요"로 돌아간다.
5. 보호자는 카드의 "게시판 열기"를 눌러 로그인 없이 게시판(2-2)에 들어간다.

## 6. 기능 요구사항

- FR-1: `myClient(id)`로 내 수급자인지 확인, 아니면 404. 관계가 "없음"이면 `/v1120/client/[id]`로 보낸다.
- FR-2: `myBoardToken(id)`은 수급자의 `boardToken`이 없으면 무작위 값으로 만들어 저장하고 돌려준다. 링크는 `{origin}/v1120/g/{boardToken}/board`.
- FR-3: 보낼 글: "[손다음] 안녕하세요, {성함} {호칭}님. {수급자} 어르신을 돌보는 {요양보호사} 요양보호사예요. … 따로 가입하지 않아도 돼요." 보호자 쪽 글이므로 "어르신"을 쓴다 (D-31).
- FR-4: 카카오 공유 카드는 피드형: 제목 "{성+○○} 어르신 게시판", 설명, 게시판 이미지, 버튼 "게시판 열기". 카드에는 건강 정보를 넣지 않는다.
- FR-5: 카카오 SDK가 없거나 실패하면 `navigator.share`, 그것도 없으면 글·링크를 복사하고 "카카오톡을 열어 붙여 넣어 주세요"를 안내한다. 공유 창을 닫으면 보낸 것으로 보지 않는다.
- FR-6: 보호자 전화번호가 있으면 `sms:` 링크로 문자 앱을 연다. 없으면 버튼을 막고 "보호자 전화번호가 없어 문자는 보낼 수 없어요."
- FR-7: "나중에 하기/다 됐어요"는 등록 직후면 수급자 탭, 아니면 수급자 정보로 간다.

## 7. 비기능 요구사항

- 성능: 화면을 열 때 카카오 SDK를 미리 불러 둔다(`preloadKakao`).
- 접근성: 주 버튼 높이 64px, 보조 버튼 56px, 결과는 글로 안내
- 보안: 카드·글에 건강 정보 없음, 수급자 이름은 카드에서 가림(`maskName`). 링크만 있으면 누구나 게시판을 볼 수 있다(코드 shortcut).
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 보호자 관계 "딸"로 수급자를 등록했을 때, When 등록이 끝나면, Then 초대 화면이 열리고 "✓ {이름} 정보를 등록했어요"가 보인다.
- [ ] Given 카카오 SDK가 준비된 휴대폰에서, When "카카오톡으로 초대하기"를 누르면, Then 공유 카드가 뜨고 받은 사람이 "게시판 열기"를 누르면 로그인 없이 게시판이 열린다.
- [ ] Given 보호자 전화번호가 없는 수급자가, When 초대 화면을 열면, Then 문자 버튼이 막히고 이유가 보인다.
- [ ] Given "링크 복사하기"를 누르면, When 메모장에 붙여 넣으면, Then 보낼 글과 게시판 링크가 함께 붙는다.
- [ ] Given 관계가 "없음"인 수급자의 초대 주소를, When 열면, Then 수급자 정보로 이동한다.
- [ ] Given 같은 수급자를 두 번 초대할 때, When 링크를 비교하면, Then 같은 `boardToken`이다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 카카오톡 공유 카드 수신·클릭(11/1 미리보기에서 확인), 팀 배포 도메인에서 다시 확인, PC 브라우저 복사 대체 흐름, 아이폰·안드로이드 문자 앱 열림 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크:
  - 링크가 만료되지 않아(STB-5) 잘못 전달되면 다른 사람이 게시판을 보고 댓글을 달 수 있다.
  - 팀 배포 도메인이 카카오 콘솔에 등록되지 않으면 공유 카드가 실패한다 (확인만 남음, 06-roles).
- 열린 질문:
  - 보호자가 바뀌면 `boardToken`을 새로 만들지
  - 보호자 첫 입장 여부(`guardianJoined`)를 언제 기록할지 (보호자 로그인 D-44와 함께)
  - 문자 앱 `sms:` 링크의 본문 채우기가 아이폰·안드로이드 모두 되는지 실기기 확인 필요
