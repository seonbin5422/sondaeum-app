# PRD: 녹음·기록

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |

| 요양보호사 | 1-4 돌봄 기록 | C-12 | `/v1120/visit/[id]/record` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 요양보호사는 돌봄 중 손이 바빠 기록을 미루고, 근무가 끝난 뒤 기억에 의존해 급여제공기록지를 쓴다. 기록이 빠지거나 부정확해진다.
- 왜 지금 필요한가: 손다음의 첫 단계다. 말 한 번으로 기록지·보호자 보고서·서류가 이어지려면 녹음 내용이 끊기지 않고 남아야 한다 (STB-3, D-27).
- 관련 문서/이슈: `docs/prd/07-features.md` 1-4, `docs/prd/04-prd.md` 3.3, US-1, STB-3, STB-4, LAW-5, D-24, D-27

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 음성·글·음성 파일로 그날 돌봄 내용을 남기고, 기록지 순서대로 어떤 칸이 채워졌는지 보면서 말한다.
- 기대 효과: 무엇을 말할지 몰라도 질문 목록을 따라 빠짐없이 말하고, 앱이 꺼져도 말한 내용이 남는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사 (주로 60대, 하루 3~4가정 방문)
- 보조 사용자: 체험 계정 사용자. 녹음 내용이 비어 있을 때 "미리보기: 예시 내용 넣기"가 보인다.
- 관리자 또는 운영자 영향: 음성 파일 올리기는 Groq 음성 인식(whisper)을 불러 AI 호출 수(SEC-3)에 잡힌다.

## 4. 범위

이번 작업에 포함:

- [x] "글로 쓰기"를 누르면 위쪽 녹음 내용 글 칸으로 스크롤하고 커서를 끝에 두어 키보드를 바로 띄운다 (11/6 팀 피드백)
- [x] 낱말 찾기(AI 실패 때)도 서식 기준으로: 사진·노래·회상은 말벗, 인지자극은 "인지 활동"·퍼즐·색칠·계산을 말했을 때만, 산책은 외출 동행, 똥·오줌·응가·쉬야도 대소변으로 셈 (D-52·D-55, 11/6)
- [x] 녹음 버튼(누르면 시작, 다시 누르면 끝냄), 녹음 시간 표시, 이어서 녹음
- [x] 글로 쓰기(입력창), 음성 파일 올리기(4MB까지, 글로 바꿔 녹음 내용 뒤에 붙임)
- [x] 확정된 문장마다 서버에 저장, 글로 쓸 때는 0.8초 멈추면 저장
- [x] 기록지 순서 6칸 안내(몸 돌봄·말벗·집안일·달라진 점·대소변·특이사항)와 낱말 찾기로 찾은 값 표시
- [x] 기록 확인에서 "더 말하기"로 돌아왔을 때 고친 값과 새로 말한 값 합쳐 보여 주기 (D-42 261101.ver)
- [x] 체험 계정 "예시 내용 넣기"
- [x] "다 말했어요: AI로 정리하기" → 빠진 항목 되묻기(1-4-2) 또는 정리(1-4-3)

이번 작업에 포함하지 않음:

- [ ] 4MB 넘는 음성 파일 (STB-4, 해커톤 이후)
- [ ] 녹음 원본 소리 저장 (글만 저장)
- [ ] 오프라인 녹음 (DIF-11, P2)
- [ ] 크롬 외 브라우저용 별도 음성 인식

## 5. 사용자 흐름

1. 요양보호사가 홈 카드의 "기록하기"(또는 "이어서 기록하기")를 누른다.
2. 시스템은 오늘 이 수급자의 보내지 않은 방문을 이어 쓰거나 새로 만들고 녹음 화면을 연다.
3. 요양보호사가 "녹음"을 누르고 말한다. 시스템은 확정된 문장을 녹음 내용에 붙여 저장하고, 6칸 안내에 찾은 값을 ✓로 보여 준다.
4. 요양보호사가 다시 눌러 녹음을 끝내고, 필요하면 글로 고치거나 음성 파일을 올린다.
5. "다 말했어요: AI로 정리하기"를 누르면 빠진 칸 되묻기(1-4-2)나 AI 정리(1-4-3)로 간다.

## 6. 기능 요구사항

- FR-1: 음성 인식은 브라우저 `SpeechRecognition`(ko-KR, 연속·중간 결과)을 쓴다. 지원하지 않으면 녹음 버튼을 끄고 "글로 쓰기"를 안내한다.
- FR-2: 확정된 문장이 나올 때마다 `saveTranscript(visitId, 전체 글)`로 저장한다. 원문은 암호화해 저장하고 방문 상태를 `RECORDING`으로 둔다.
- FR-3: 저장에 실패하면 화면의 글은 지우지 않고 "저장하지 못했어요. 인터넷 연결을 확인해 주세요."를 보여 준다.
- FR-4: 글로 쓰기는 입력이 0.8초 멈추면 저장한다.
- FR-5: 음성 파일은 4MB(`MAX_AUDIO_UPLOAD_BYTES`)를 넘으면 화면에서 막고 "녹음 파일이 너무 커요. 2분 이내로 녹음한 파일을 올려주세요."를 보여 준다. 4MB 이하는 `/api/visits/[id]/transcribe`로 보내 글로 바꿔 붙인다.
- FR-6: 녹음 중에는 글로 쓰기·음성 파일 올리기를 끈다.
- FR-7: 안내 값은 `extractRecord`(낱말 찾기)로 인식이 끝난 문장에서만 만든다. "~했고" 이어 말하기, "대소변 실수 없다" → 대변·소변 0회, "상태는 그대로" → 몸·식사·기억 "비슷함"을 알아듣는다.
- FR-8: 기록 확인에서 돌아왔으면 처음 글과 값이 달라진 칸만 지금 말한 값으로, 나머지는 기록 확인 값으로 보여 주고, 달라진 칸 목록을 `finishRecording`에 넘긴다.
- FR-9: "다 말했어요"는 녹음 내용이 있을 때만 보인다. `finishRecording`은 빈 글이면 "녹음 내용이 없어요."로 막고, 상태를 `RECORDED`로 바꾼다.

## 7. 비기능 요구사항

- 성능: 문장마다 서버 액션 1번. 음성 파일 변환은 서버 최대 60초(`maxDuration`).
- 접근성: 녹음 버튼 지름 160px, 상태 문구 20px 이상(`text-xl`), 오류는 `role="alert"`로 알린다 (DIF-1).
- 보안: 마이크는 누를 때만 켜고, 화면을 떠나거나 앱이 가려지면(`visibilitychange`) 끄고 자동으로 다시 켜지 않는다 (LAW-5). 녹음 원문은 암호화 저장, 내 방문이 아니거나 보낸 방문이면 저장을 막는다 (SEC-2, STB-1).
- 로깅/모니터링: 음성 파일 변환 실패만 서버 `console.error`.

## 8. 수용 기준

- [ ] Given 녹음 중인 요양보호사가, When 문장 하나를 말한 뒤 탭을 닫고 홈에서 "이어서 기록하기"를 누르면, Then 마지막으로 확정된 문장까지 녹음 내용에 남아 있다.
- [ ] Given 5MB 음성 파일을, When "음성 파일 올리기"로 고르면, Then 서버로 보내지 않고 "녹음 파일이 너무 커요…" 안내가 보인다.
- [ ] Given "세수 10분 도와드렸어요. 산책 20분 부축했어요."라고 말했을 때, When 문장이 확정되면, Then "몸 돌봄" 칸에 ✓와 "개인위생 · 이동도움 · 30분"이 보인다.
- [ ] Given 녹음 중에, When 다른 앱으로 전환하면, Then 마이크가 꺼지고 돌아와도 자동으로 다시 켜지지 않는다.
- [ ] Given 음성 인식을 지원하지 않는 브라우저에서, When 녹음 화면을 열면, Then 녹음 버튼이 꺼져 있고 "글로 쓰기" 안내가 보인다.

## 9. 검증 계획

- 단위 테스트: `npx tsx app/v1120/_minutesSum.check.ts`(활동별 시간 더하기), `npx tsx app/v1120/_keepFilled.check.ts`(더 말하기 뒤 고친 값 유지)
- 통합 테스트: 없음. STB-7에 "남의 방문에 `saveTranscript` 호출 시 거부"를 넣을 수 있다.
- 수동 확인: 아이폰 Safari·안드로이드 크롬 실기기에서 녹음·끊김·재진입·파일 올리기 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크:
  - 저장 단위가 확정된 문장이라 끊기는 순간 인식 중이던 몇 초는 빠질 수 있다 (D-27).
  - 크롬 음성 인식은 소리를 Google로 보낼 수 있다 (동의 화면에 따로 알림).
  - 음성 파일은 개인정보를 지우지 않은 채 Groq whisper로 간다 (동의의 국외 이전 항목에는 "올린 녹음 파일" 포함).
  - 낱말 찾기 기준이 "들어올 때의 녹음 글"이라, 고치다 나갔다 다시 들어오면 그때 글이 기준이 된다 (코드 주석 shortcut).
- 열린 질문:
  - 음성 파일 변환이 AI 한도(SEC-3)에 걸리면 429 안내 문구가 화면에 그대로 보이는지 실기기 확인 필요
  - 아이폰 Safari에서 `SpeechRecognition` 지원 여부·품질 기준을 어디까지로 볼지 (OPS-2 결과로 정함)
  - 녹음 시간 표시는 이어서 녹음할 때 0부터 다시 세는지, 누적인지 기획 의도 확인 필요
