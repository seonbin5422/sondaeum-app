## 1. 배경

- 현재 문제: 녹음 글에는 군말·반복·말 끊김이 섞여 있어 그대로는 급여제공기록지에 옮길 수 없다. AI가 추측해 채우면 사실이 아닌 기록이 남는다.
- 왜 지금 필요한가: 기록 확인·보호자 보고서·서류가 모두 이 정리 결과(`careRecord`)를 쓴다 (D-24, D-36).
- 관련 문서/이슈: `docs/spec/04-ai-pipeline.md`, LAW-1, LAW-2, LAW-6, SEC-3, STB-2, DIF-8, D-24, D-43

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: "다 말했어요" 뒤 10초 안팎으로 녹음이 기록지 칸에 맞춰 정리되고 기록 확인으로 넘어간다.
- 기대 효과: 말한 사실만, 근거 문장과 함께 칸이 채워지고 말하지 않은 칸은 비어 "확인 필요"가 된다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음 (보호자는 결과만 본다)
- 관리자 또는 운영자 영향: Groq API 키와 사용량. 요양보호사마다 1시간 30번, 하루 100번까지 (`AI_LIMIT`).

## 4. 범위

이번 작업에 포함:

- [x] 개인정보(수급자·보호자·요양보호사 이름, 전화번호)를 앱 안에서 지운 뒤 AI로 보냄 (AI 호출 0번, DIF-8)
- [x] Groq `openai/gpt-oss-120b`, JSON 스키마로 기록지 칸 + 칸별 근거 문장(quotes) 받기
- [x] 근거 문장이 입력에 없는 칸은 비움, 특이사항 근거가 빠지면 한 번 더 물음
- [x] AI가 비운 숫자 칸만 낱말 찾기 값으로 메움 (인지·정서는 AI가 한 칸이라도 채웠으면 안 메움)
- [x] "~ㅂ음" 꼴 고치기("그대롭음" → "그대로임")
- [x] 키가 없거나, 한도를 넘거나, AI가 실패하면 낱말 찾기로 채움
- [x] 같은 방문 중복 정리 막기 (STB-2), "더 말하기" 뒤 다시 정리할 때 고친 값 지키기
- [x] 정리 실패 시 "다시 정리하기"

이번 작업에 포함하지 않음:

- [ ] 수급자 프로필(병력 등)을 AI 맥락에 넣기 (DIF-7)
- [x] AI 품질 평가 세트 24건·예시 쌍 (DIF-7, 11/6 `scripts/ai-eval/`)
- [ ] 유료 STT로 녹음 글 정확도 높이기 (필요할 때만)

## 5. 사용자 흐름

1. 요양보호사가 녹음(또는 되묻기)을 마치면 AI 처리중 화면으로 간다.
2. 시스템은 녹음 글에서 개인정보를 지우고 AI에 보내 기록지 칸을 채운 뒤 저장하고, 방문 상태를 `DRAFT_READY`로 바꾼다.
3. 요양보호사는 기록 확인(C-14)으로 넘어간 화면을 본다. 실패하면 "정리하지 못했어요"와 "다시 정리하기"를 본다.

## 6. 기능 요구사항

- FR-1: `summarizeVisit`은 상태가 `SUMMARIZING`·`DRAFT_READY`면 다시 하지 않는다. 시작할 때 `SUMMARIZING`, 끝나면 `DRAFT_READY`, 예외가 나면 `RECORDED`로 되돌린다.
- FR-2: `redactForAi`로 이름·전화번호를 `[수급자]`·`[보호자]`·`[요양보호사]`·`[전화번호]`로 바꿔 보낸다. 결과의 근거 문장에는 이름을 되돌리고, 글 칸은 역할어로 바꾼다.
- FR-3: 지시문 규칙: 말한 사실만, 진단·처방 금지, 권유는 한 일이 아님, 말한 시간만, 고쳐 말하면 마지막 값, 특이사항은 관찰 → 조치 → 전달 순서의 기록지 말투(~함·~음), 평가하는 말 금지, 서로 다른 말은 둘 다 적고 결론 내지 않음.
- FR-4: 영역 없이 "상태는 그대로"라고 하면 변화상태 세 칸 모두 같은 값으로 채운다.
- FR-5: 특이사항에 관찰만 있고 조치가 없으면 `notesNoAction=true`와 조치 예 2~3개를 담은 질문(`notesAsk`)을 만든다.
- FR-6: 보호자용 특이사항(`guardianNotes`)은 기록지 문장을 빼거나 더하지 않고 쉬운 말('~했어요')로 옮긴다.
- FR-7: `checkAiRecord`로 응답 값을 거른다(숫자 범위, 근거 문장이 입력에 없으면 그 칸 비움). `fillGaps`로 숫자 칸만 낱말 찾기 값으로 메운다.
- FR-8: "더 말하기"로 다시 정리할 때는 `keepFilled`로 이미 있던 값(직접 고친 값 포함)을 지키고 빈 칸만 채운다. 녹음에서 고쳐 말한 칸은 `finishRecording`이 미리 비워 새 값이 들어간다.
- FR-9: AI 한도(`takeAiCall`)를 넘으면 오류 없이 낱말 찾기로 채운다. 특이사항 재질문은 호출 1번으로 센다.
- FR-10: 결과 기록과 근거 문장은 암호화해 `Report.careRecord`·`aiRawJson`에 저장한다.

## 7. 비기능 요구사항

- 성능: 화면 안내 "보통 10초 안에 끝나요". `temperature: 0`, `reasoning_effort: "low"`(무료 한도 절약).
- 접근성: 처리 중 스피너와 20px 이상 안내 문구, 실패 시 버튼 하나로 다시 시도.
- 보안: AI에는 개인정보를 지운 글만 (LAW-6). Groq는 보관 안 함(ZDR) 키 기준 (동의 문구). 결과는 암호화 저장.
- 로깅/모니터링: AI 실패 시 "AI 정리 실패, 낱말 찾기로 채움" 서버 로그. 사용량은 `aiUsage` 테이블에 종류("fill-record")와 함께 쌓인다.

## 8. 수용 기준

- [ ] Given "홍길순 어르신 혈압 135/85였어요"를 말한 방문이, When 정리되면, Then AI로 간 글에는 "홍길순"이 없고 "[수급자]"가 있다.
- [ ] Given "혈압 150/95"를 말했을 때, When 정리되면, Then 특이사항은 "혈압 150/95 측정"처럼 적히고 "고혈압 의심" 같은 진단 표현은 없다.
- [ ] Given 배변을 말하지 않았을 때, When 정리되면, Then 대변·소변 실수 칸은 비어 있고 기록 확인에 "확인 필요"로 보인다.
- [ ] Given `GROQ_API_KEY`가 없거나 Groq가 실패할 때, When "다 말했어요"를 누르면, Then 낱말 찾기로 채워진 기록 확인 화면이 열린다.
- [ ] Given 정리가 진행 중인 방문에, When 처리중 화면을 두 번 열면, Then AI는 한 번만 불린다.
- [ ] Given 기록 확인에서 "가사 30분"으로 고친 뒤 더 말하기로 다른 칸만 말했을 때, When 다시 정리되면, Then 가사는 30분 그대로다.

## 9. 검증 계획

- 단위 테스트: `npx tsx app/v1120/_redact.check.ts`(개인정보 지우기·AI 결과 거르기·fillGaps), `npx tsx app/v1120/_keepFilled.check.ts`, `npx tsx app/v1120/_minutesSum.check.ts`
- 품질 평가(DIF-7): `npx tsx --tsconfig tsconfig.json --env-file=.env.local scripts/ai-eval/run.mts [--runs 3] [--only 17,18]`. `cases.json` 24건(녹음 글·정답 칸·특이사항에 꼭 들어갈 사실·들어가면 안 될 말·모범 특이사항)을 실제 AI에 넣어 사례 통과율·칸 정확도·특이사항 포함률·금지 표현 수를 낸다. `--pairs`는 AI 없이 입력 → 모범 특이사항 예시 쌍 표를 출력. 지시문을 고치면 돌려서 전과 비교한다. 결과는 `results.jsonl`에 쌓이고(지시문 `_ai.ts`·사례 내용이 바뀌면 새로 채점), 무료 Groq 키는 하루 20만 토큰(AI 정리 약 35번)이라 `--resume`으로 며칠에 나눠 이어서 돌린다. 사례 26~46은 권역별 사투리(`dialects.json` 698개, 우리말샘·새국어생활 출처)로 만든 문장이라 지역 화자 검토가 필요하다
- 수동 확인: 시연 문장("점심 반 공기 드셨고, 혈압 135에 85…")으로 결과 확인, 키를 빼고 대체 경로 확인

## 10. 리스크와 열린 질문

- 리스크:
  - 모델이 지시를 가끔 어긴다(예: "그대롭음", 3번 중 1번). 정해 둔 낱말만 코드로 고친다.
  - 무료 Groq 키의 분당 한도에 걸리면 낱말 찾기 결과로 떨어져 품질이 낮아진다.
  - 개인정보 지우기는 등록된 이름·번호만 찾는다. 등록 안 된 사람 이름·주소는 그대로 갈 수 있다.
- 열린 질문:
  - 정리 도중 서버가 끊겨 상태가 `SUMMARIZING`에 멈추면, 다시 들어왔을 때 `summarizeVisit`이 바로 끝나고 기록 확인이 다시 처리중으로 돌려보내는 반복이 생기는지 확인 필요
  - 낱말 찾기로 대신 채웠을 때 요양보호사에게 "AI 없이 정리했어요"를 알릴지
  - 보호자 이름·장기요양인정번호·병력도 AI 전에 지울지 (SEC-5·LAW-6 남은 일과 함께)
