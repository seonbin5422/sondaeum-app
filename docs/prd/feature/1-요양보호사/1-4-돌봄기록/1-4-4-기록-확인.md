## 1. 배경

- 현재 문제: AI 정리 결과를 그대로 보내면 틀린 값이나 빠진 칸이 보호자 보고서·기록지에 그대로 들어간다. 요양보호사가 근거를 보며 짧게 고칠 곳이 필요하다.
- 왜 지금 필요한가: 간단한 항목은 체크·선택으로 고치게 하고(DIF-6), 특이사항 조치 누락(D-43)과 다시 들어와 더 말하기(D-42)를 이 화면에서 처리한다.
- 관련 문서/이슈: `docs/prd/04-prd.md` 3.3, US-2, DIF-6, LAW-2, LAW-7, STB-1, D-41, D-42, D-43

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 기록지 항목을 하나씩 확인하며 고치고, 빈 칸을 채우고, 특이사항에 조치·전달을 더한 뒤 보낼 내용 보기로 간다.
- 기대 효과: 보내기 전에 빠진 항목이 이름으로 드러나고, 고친 값은 언제 나갔다 와도 남는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: "말로 더하기"는 AI 호출 1번을 쓴다 (SEC-3).

## 4. 범위

이번 작업에 포함:

- [x] "기록 확인" 탭 맨 위에 "내가 한 말" 카드로 녹음 글을 먼저 보여 준다(4줄, "모두 보기"로 펼침). 그 아래 AI가 채운 칸을 대조하며 확인 (D-54, 11/6)
- [x] 탭 2개: 기록 확인 / 급여제공기록지(같은 값을 기관 서식 순서로 보기)
- [x] 섹션 하나씩 확인(서비스 시간 → 신체활동 → 인지·정서 → 가사 → 변화상태 → 배변 → 특이사항), "확인했어요, 다음" (D-41)
- [x] 체크(신체활동 6종·가사 2종), 분·회 입력, 변화상태 호전/유지/악화 선택, 기저귀 교환 회수
- [x] 빈 칸 "확인 필요" 표시, 섹션마다 "내가 한 말"(근거 문장) 보기
- [x] 특이사항: 직접 고치기, "특이사항 없음", 조치가 빠졌으면 AI 질문 + "🎤 말로 더하기"
- [x] "누구에게 알렸나요?": 보호자에게 전달함 / 기관에 보고함 / 알리지 않음
- [x] 고칠 때마다 0.6초 뒤 자동 저장, "나중에 하기 (홈으로)"
- [x] 다시 들어오면 "🎤 빠진 내용 더 말하기" (D-42)
- [x] 학대 의심 낱말이 있으면 안내 배너와 노인보호전문기관(1577-1389) 안내 (LAW-7)

이번 작업에 포함하지 않음:

- [ ] 서비스 시간 고치기 (수급자 방문 시간에서 자동)
- [ ] 보낸 뒤 고치기 (STB-1)
- [ ] 기관 서류 초안 따로 만들기 (DIF-3, 리뷰 중 — 지금은 급여제공기록지 탭이 같은 값을 보여 줌)

## 5. 사용자 흐름

1. 요양보호사가 AI 정리 뒤 기록 확인 화면을 본다. 안내 "AI가 급여제공기록지에 맞춰 적었어요"와 첫 섹션이 보인다.
2. 섹션마다 값을 확인·고치고 "확인했어요, 다음"을 누른다. 시스템은 다음 섹션을 펼치고 고친 값을 저장한다.
3. 특이사항에서 조치가 빠졌으면 "말로 더하기"로 말한다. 시스템은 AI로 특이사항을 다시 정리해 그 자리에서 바꾼다.
4. 모든 섹션을 확인하면 "다음: 보낼 내용 보기"가 켜진다. 누르면 저장 후 보낼 내용 보기(1-4-5)로 간다.

## 6. 기능 요구사항

- FR-1: 기록이 없으면 처리중으로, 보낸 방문이면 보낸 화면으로 보낸다.
- FR-2: 확인한 섹션 수(n)까지와 다음 섹션 하나만 보인다. 모든 섹션을 확인해야 "다음: 보낼 내용 보기"가 켜지고, 꺼져 있을 때 "항목을 하나씩 확인해 주세요 (n/7)"을 보여 준다.
- FR-3: 빈 칸 판단: 신체활동·가사 제공시간 없음, 인지·정서 4칸 중 하나라도 없음, 변화상태 3칸 중 하나라도 없음, 대변·소변 실수 중 하나라도 없음, 특이사항 없음 → "확인 필요".
- FR-4: 값을 고치면 0.6초 뒤 `saveRecord`로 저장하고 `wasEdited=true`로 둔다. 실패하면 "저장하지 못했어요…"를 보여 준다.
- FR-5: 특이사항을 직접 고치면 보호자용 문장(`guardianNotes`)을 지우고 보호자 보고서도 고친 글을 보여 준다. "특이사항 없음"은 기록지 "특이사항 없음.", 보호자용 "특별한 일은 없었어요."로 채운다.
- FR-6: "말로 더하기"는 지금 특이사항 + 새로 한 말을 `addToNotes`로 다시 정리한다. 새로 한 말은 녹음 글 끝에도 붙인다. AI가 없거나 실패하면 한 말을 그대로 붙인다.
- FR-7: 특이사항에 전달·보고 표현이 없으면 "누구에게 알렸나요?" 버튼 3개를 보여 주고, 누르면 기록지·보호자용 문장 끝에 각각 붙인다 (예: "보호자에게 전달함." / "보호자님께 알려 드렸어요.").
- FR-8: "더 말하기"·"다음"을 누르면 저장을 먼저 끝낸 뒤 이동한다.
- FR-9: 녹음 직후 들어왔으면 "뒤로"가 녹음 화면(이어 말하기), 임시저장 뒤 홈에서 다시 들어왔으면(`resume=1`) "뒤로"는 홈이고 "빠진 내용 더 말하기" 버튼을 따로 보여 준다 (D-42).
- FR-10: 녹음 글에 학대 의심 낱말(때리·맞았·멍이·욕을·가두·굶겨 등)이 있으면 "보호자 보고서에 싣지 않은 말이 있어요" 배너와 신고 안내를 보여 준다.

## 7. 비기능 요구사항

- 성능: 고칠 때마다 서버 저장 1번(0.6초 묶음). 말로 더하기는 AI 1번.
- 접근성: 탭은 `role="tablist"`·`aria-selected`, 버튼 높이 48px 이상, 섹션 머리를 눌러 접고 펼치기.
- 보안: 내 방문만, 보낸 방문은 저장 거부 (STB-1). 기록은 암호화 저장.
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 배변을 말하지 않은 기록이, When 기록 확인을 열면, Then 배변 변화 섹션에 "확인 필요"가 보인다.
- [ ] Given 7개 섹션 중 6개만 확인했을 때, When 아래 버튼을 보면, Then "다음: 보낼 내용 보기"가 꺼져 있고 "(6/7)"이 보인다.
- [ ] Given 가사 시간을 30분으로 고친 뒤, When 1초 뒤 새로고침하면, Then 30분이 그대로다.
- [ ] Given 특이사항이 "무릎 통증 호소함."뿐일 때, When 특이사항 섹션을 열면, Then 조치가 빠졌다는 안내와 "🎤 말로 더하기"가 보이고, "찜질해 드렸어요"라고 말하면 특이사항에 조치 문장이 더해진다.
- [ ] Given 특이사항에 전달 표현이 없을 때, When "보호자에게 전달함"을 누르면, Then 기록지 문장 끝에 "보호자에게 전달함."이 붙고 버튼 묶음이 사라진다.
- [ ] Given 홈에서 "기록 확인하고 보내기"로 들어왔을 때, When "빠진 내용 더 말하기"를 누르면, Then 고친 값이 저장된 뒤 녹음 화면으로 간다.

## 9. 검증 계획

- 단위 테스트: `npx tsx app/v1120/_keepFilled.check.ts`(다시 정리할 때 고친 값 유지)
- 통합 테스트: 없음. STB-7에 "보낸 방문 `saveRecord` 거부"를 넣을 수 있다.
- 수동 확인: 시연 흐름에서 섹션 확인·말로 더하기·임시저장 뒤 재진입 (OPS-2, OPS-11)

## 10. 리스크와 열린 질문

- 리스크:
  - 말로 더하기는 끝낸 직후 마지막 문장이 늦게 확정될 수 있어 1초 기다린다 (코드 shortcut).
  - 학대 의심 판단이 낱말 몇 개뿐이라 놓치거나 잘못 걸 수 있다.
- 열린 질문:
  - LAW-7: 배너는 "자동으로 보내지 않아요"라고 하지만, 보호자 보고서가 해당 특이사항을 실제로 빼는지 코드에서 확인되지 않음 (`ReportView`는 `guardianNotes ?? notes`를 그대로 보여 줌). 개발 1 확인 필요
  - 서비스 시간을 실제 방문 시각과 다르게 고칠 수 있어야 하는지
  - "나중에 하기"로 나간 기록을 언제까지 둘지 (당일 지나면 홈에 안 보이는지 확인 필요)
