# PRD: 보낼 내용 보기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-4 돌봄 기록 | C-15 | `/v1120/visit/[id]/confirm` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 보낸 보고서는 고칠 수 없다 (STB-1). 요양보호사는 보호자가 실제로 보게 될 모양과 아직 빈 항목을 보내기 직전에 한 번 더 봐야 한다.
- 왜 지금 필요한가: US-2 "빠진 항목을 보내기 전에 알고 싶다"의 마지막 확인 단계다.
- 관련 문서/이슈: US-2, STB-1, DIF-2, D-49, `docs/design/02-screens.md` C-15

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자 보고서 미리보기를 보고, 빠진 항목 목록을 확인한 뒤 돌아가 채우거나 그대로 저장·보낸다.
- 기대 효과: 빈 칸을 모르고 보내는 일이 줄어든다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 보호자 보고서와 같은 모양의 미리보기 ("○○님께는 이렇게 보여요.")
- [x] 빠진 항목이 있으면 아래 시트로 먼저 알림: "아직 확인하지 않은 항목이 N개 있어요" + 항목 이름 목록
- [x] 시트 버튼: "돌아가서 채울게요"(주 버튼) / "그대로 보낼게요"
- [x] 보호자가 없으면(D-49) "이렇게 저장돼요." + "저장하기"
- [x] "보낸(저장한) 뒤에는 고칠 수 없어요." 안내와 "저장하고 공유하기"

이번 작업에 포함하지 않음:

- [ ] 이 화면에서 직접 고치기 (기록 확인으로 돌아가서 고침)
- [ ] 받는 사람 고르기 (수급자에 등록된 보호자 한 명)

## 5. 사용자 흐름

1. 요양보호사가 기록 확인에서 "다음: 보낼 내용 보기"를 누른다.
2. 시스템은 보고서 미리보기를 보여 주고, 빠진 항목이 있으면 시트를 띄운다.
3. 요양보호사는 "돌아가서 채울게요"로 기록 확인에 가거나, "그대로 보낼게요"로 시트를 닫는다.
4. "저장하고 공유하기"(보호자 없음: "저장하기")를 누르면 보내기(1-4-6)가 실행된다.

## 6. 기능 요구사항

- FR-1: 기록이 없으면 처리중으로, 이미 보낸 방문이면 보낸 화면으로 보낸다.
- FR-2: 빠진 항목은 `missingItems`로 계산한다: "신체활동지원: 제공시간", "인지·정서 지원: (빈 칸 이름들)", "가사·일상생활지원: 제공시간", "변화상태: (빈 칸)", "배변 변화: (빈 칸)", "특이사항".
- FR-3: 받는 사람 호칭은 보호자 관계로 정한다(`contactTitle`). 관계가 "없음"이면 받는 사람이 없는 것으로 본다.
- FR-4: "뒤로"와 "돌아가서 채울게요"는 기록 확인으로 가고, 다시 들어온 기록이면 `resume=1`을 지킨다.
- FR-5: 미리보기는 보호자 보고서와 같은 컴포넌트(`ReportSections`)를 쓴다.

## 7. 비기능 요구사항

- 성능: 서버에서 방문 1건 읽기. 추가 호출 없음.
- 접근성: 시트는 `role="dialog"`·`aria-modal`, 버튼 높이 56~64px, 항목 목록 18px 굵게.
- 보안: 내 방문만 연다 (SEC-2).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 대변 실수와 특이사항이 빈 기록이, When 보낼 내용 보기를 열면, Then "아직 확인하지 않은 항목이 2개 있어요"와 "배변 변화: 대변 실수", "특이사항"이 보인다.
- [ ] Given 빈 항목이 없는 기록이, When 보낼 내용 보기를 열면, Then 시트 없이 미리보기와 "저장하고 공유하기"가 보인다.
- [ ] Given 보호자 관계가 "없음"인 수급자의 기록이, When 보낼 내용 보기를 열면, Then "이렇게 저장돼요."와 "저장하기" 버튼이 보인다.
- [ ] Given 시트에서, When "돌아가서 채울게요"를 누르면, Then 기록 확인 화면으로 간다.
- [ ] Given 이미 보낸 방문의 주소로, When 보낼 내용 보기를 열면, Then 보낸 화면으로 이동한다.

## 9. 검증 계획

- 단위 테스트: 없음. `missingItems`를 확인하는 check 스크립트를 더할 수 있다.
- 통합 테스트: 없음
- 수동 확인: 빈 칸 있는/없는 기록, 보호자 있는/없는 수급자 4가지 조합

## 10. 리스크와 열린 질문

- 리스크: "그대로 보낼게요"를 누르면 빈 칸이 "확인 필요"인 채로 보호자에게 간다. 보호자 화면에서 빈 칸을 어떻게 보이는지에 따라 오해가 생길 수 있다.
- 열린 질문:
  - 빈 칸이 있으면 보내기를 막을지, 지금처럼 경고만 할지 (사용성 테스트 OPS-9에서 확인)
  - 기저귀 교환 횟수는 빠진 항목 목록에 넣지 않는데, 기저귀를 쓰는 수급자는 넣어야 하는지
