# PRD: 보내기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-4 돌봄 기록 | C-16 | `/v1120/visit/[id]/sent` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 보호자는 떨어져 살아 그날 돌봄을 알 길이 없다. 카카오 알림톡은 사업자 채널·비용이 들어 본선 범위 밖이다 (D-08).
- 왜 지금 필요한가: 기록 → 보고서 → 보호자 열람으로 이어지는 핵심 흐름의 마지막 단계이고, 보낸 뒤 고칠 수 없게 잠가야 한다 (STB-1).
- 관련 문서/이슈: STB-1, DIF-5, D-08, D-34 261101.ver, D-49, `docs/design/02-screens.md` C-16

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 기록을 확정하고, 보호자에게 카카오톡 공유 카드나 링크로 보고서를 보낸다.
- 기대 효과: 보낸 보고서가 수급자 게시판에도 글로 올라가 보호자가 댓글로 물을 수 있다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 보호자 (받는 사람)
- 관리자 또는 운영자 영향: 카카오 JavaScript SDK 키와 도메인 등록 필요 (팀 배포 도메인 등록 확인 남음)

## 4. 범위

이번 작업에 포함:

- [x] "저장하고 공유하기": 보낸 시각 저장, 방문 상태 "SENT", 이후 고치기 막기
- [x] ① 저장 완료 → ② "카카오톡으로 보내기"(공유 카드), "링크 복사하기"
- [x] 카카오 공유가 안 되면 휴대폰 공유 창, 그것도 없으면 링크 복사로 대신하고 "복사했어요"로 알림
- [x] 보낸 뒤 "○○님께 보냈어요"와 시각, "○○님이 보는 화면 열어 보기", "카카오톡으로 다시 보내기"
- [x] 보호자가 없으면 "기록 저장"만, "보호자가 없어요" 안내
- [x] 보낸 보고서는 수급자 게시판(1-5)에 글로 보임

이번 작업에 포함하지 않음:

- [ ] 카카오 알림톡·문자 자동 발송 (D-08)
- [ ] 보호자 링크 만료·미리보기 봇 제외 (STB-5, 11/13)
- [ ] 보낸 뒤 고치기·다시 정리하기 (STB-1)
- [ ] 보호자가 읽었는지 확인

## 5. 사용자 흐름

1. 요양보호사가 보낼 내용 보기에서 "저장하고 공유하기"를 누른다.
2. 시스템은 보고서를 보냄으로 저장하고 보내기 화면을 연다.
3. 요양보호사가 "카카오톡으로 보내기"를 눌러 카카오톡에서 보호자를 고른다.
4. 시스템은 "○○님께 보냈어요"와 시각을 보여 준다. 보호자는 카드의 "보고서 보기"로 보고서(2-1)를 연다.

## 6. 기능 요구사항

- FR-1: `sendReport`는 내 방문이고 아직 보내지 않았고 정리된 기록이 있을 때만 `Report.sentAt`과 `Visit.status="SENT"`(끝난 시각이 없으면 지금)를 저장한다.
- FR-2: 보낸 뒤에는 녹음 저장·정리·기록 저장이 모두 "이미 보낸 기록은 고칠 수 없어요."로 막힌다. 서명은 기록 내용이 아니라 보낸 뒤에도 받는다.
- FR-3: 보고서 링크는 `/v1120/g/{shareToken}`이다. `shareToken`은 보고서를 만들 때 자동으로 정해진다(cuid).
- FR-4: 카카오 공유 카드: 제목 "{날짜} 방문 보고서", 설명 "{가린 이름} 어르신 · {요양보호사}가 보냈어요", 버튼 "보고서 보기".
- FR-5: 카드를 못 띄우면 `navigator.share`, 없으면 클립보드 복사. 공유 창을 닫으면 보낸 것으로 보지 않는다.
- FR-6: 보낸 시각·복사 여부는 이 기기(localStorage)에 기록해 다시 열어도 보인다.
- FR-7: 보호자 관계가 "없음"이면 제목 "기록 저장", 보내기 버튼 없이 "기록은 수급자의 방문 기록과 서류에 남아요…" 안내.
- FR-8: 보내지 않은 방문으로 이 주소에 오면 보낼 내용 보기로 보낸다.

## 7. 비기능 요구사항

- 성능: 카카오 SDK는 화면을 열 때 미리 불러온다(`preloadKakao`).
- 접근성: 주 버튼 높이 64px, 단계 번호(①②) 표시, 결과 문구 18px 굵게.
- 보안: 공유 카드에 수급자 이름은 가려서 넣는다(`maskName`). 링크를 아는 사람은 누구나 볼 수 있다(만료 없음, STB-5).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 보낼 내용 보기에서, When "저장하고 공유하기"를 누르면, Then 보내기 화면이 열리고 기록 확인 주소로 다시 들어가면 보내기 화면으로 돌아온다.
- [ ] Given 보낸 방문에, When `saveRecord`를 부르면, Then "이미 보낸 기록은 고칠 수 없어요." 오류가 난다.
- [ ] Given 휴대폰 크롬에서, When "카카오톡으로 보내기"를 누르면, Then 카카오톡 공유 카드가 뜨고, 받은 카드의 "보고서 보기"가 보호자 보고서를 연다.
- [ ] Given PC 브라우저에서 카카오 공유를 못 띄울 때, When "카카오톡으로 보내기"를 누르면, Then 링크가 복사되고 "보낼 링크를 복사했어요"와 붙여 넣기 안내가 보인다.
- [ ] Given 보호자가 없는 수급자의 기록을, When 저장하면, Then "기록 저장"과 "보호자가 없어요"가 보이고 보내기 버튼은 없다.
- [ ] Given 보낸 보고서가, When 수급자 게시판을 열면, Then 그 보고서가 글로 보인다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음. STB-7에 "보낸 뒤 수정 거부", "남의 방문 sendReport 거부"를 넣을 수 있다.
- 수동 확인: 실기기 카카오톡 수신·클릭 (11/1 미리보기 배포에서 확인), 팀 배포 도메인에서 다시 확인

## 10. 리스크와 열린 질문

- 리스크:
  - 카카오 공유 카드가 떴다는 것만으로 "보냈어요"로 표시한다. 실제로 보냈는지는 알 수 없다.
  - 보낸 시각이 이 기기에만 있어 다른 기기에서 열면 "아직 보내지 않았어요"로 보인다 (코드 shortcut, DB로 옮길 예정).
  - 링크 만료가 없어 링크가 퍼지면 누구나 볼 수 있다 (STB-5).
- 열린 질문:
  - 팀 배포 도메인이 카카오 콘솔(제품 링크 웹 도메인·JS SDK 도메인)에 등록됐는지 (개발 2 확인)
  - 보낸 기록을 잘못 보냈을 때 철회·정정 방법을 둘지
  - 보낸 시각을 DB에 둘지 (DIF-5 게시판 저장과 함께)
