# PRD: 게시판 목록

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-5 게시판 | 게시판 탭 | `/v1120/chats` | 구현됨 (DIF-5 리뷰 중) · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 하루 3~4가정을 도는 요양보호사는 어느 보호자가 질문을 남겼는지 수급자마다 들어가 봐야 알 수 있었다.
- 왜 지금 필요한가: 2차 멘토링(10/23)에서 실시간 채팅 대신 게시글+댓글로 바꾸라는 피드백을 받아, 11/1에 대화방을 수급자별 게시판으로 바꿨다(D-15 261101.ver). 하단 메뉴의 "게시판" 탭이 입구다(D-32).
- 관련 문서/이슈: `docs/prd/07-features.md` 1-5, `docs/prd/04-prd.md` 8절, DIF-5, D-15, D-32, D-49

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 있는 수급자의 게시판을 한 목록에서 보고, 어디에 새 댓글이 있는지 바로 안다.
- 기대 효과: 보호자 질문에 늦게 답하는 일을 줄인다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 없음 (보호자는 링크로 수급자 게시판에 바로 들어감, 2-2)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] "새 댓글 N" 표시를 이름 옆이 아니라 보호자 이름 아래로 내려 좁은 폰에서 이름이 여러 줄로 쪼개지지 않게 함 (11/6)
- [x] 보호자가 있고 삭제하지 않은 수급자마다 한 줄: 이름, 보호자 성함·관계, 최근 글 제목·댓글 수
- [x] 글이 없으면 "아직 보낸 보고서가 없어요"
- [x] 안 읽은 보호자 댓글이 있으면 "새 댓글 N" 표시
- [x] 하단 메뉴 "게시판"에 안 읽은 댓글 합계, 화면을 옮길 때마다 다시 셈
- [x] 게시판이 하나도 없으면 "수급자를 등록하면 게시판이 생겨요."

이번 작업에 포함하지 않음:

- [ ] 휴대폰 알림(웹 푸시) — 해커톤 이후 (11/1)
- [ ] 목록 화면 자동 새로고침 (수급자 게시판·게시글 화면에만 있음)
- [ ] 안 읽은 게시판 먼저 정렬

## 5. 사용자 흐름

1. 요양보호사가 하단 메뉴 "게시판"을 누른다 (메뉴에 새 댓글 수가 보임).
2. 시스템은 보호자가 있는 수급자별 최근 글과 안 읽은 댓글 수를 보여 준다.
3. 요양보호사가 "새 댓글" 표시가 있는 줄을 눌러 수급자 게시판(1-5-2)으로 간다.

## 6. 기능 요구사항

- FR-1: `myClients()`에서 `isActive`가 참이고 관계가 "없음"이 아닌 수급자만 목록에 넣는다 (D-49).
- FR-2: `myBoardSummary()`로 수급자별 가장 최근 글을 찾는다. 보낸 보고서는 "M월 D일 방문 보고서"(보낸 시각 기준), 올린 서류는 "진료 참고용 요약 (M/D~M/D)", 그 글의 댓글 수.
- FR-3: `myUnreadByClient()`로 보호자가 쓰고 `readAt`이 없는 댓글을 수급자별로 센다.
- FR-4: 보호자 표시는 가족이면 "{성함} 보호자({관계})", 기관·후견인이면 "{성함} {관계}".
- FR-5: 하단 메뉴는 경로가 바뀔 때마다 `myUnreadTotal()`로 합계를 받아 표시한다.

## 7. 비기능 요구사항

- 성능: 수급자·최근 글·안 읽은 수를 동시에 읽는다. 최근 글은 보낸 방문 전체를 읽어 화면 쪽에서 고른다.
- 접근성: 줄 높이 80px 이상(`min-h-20`), 새 댓글은 색과 글자("새 댓글 2")를 함께 씀
- 보안: 내 수급자 글·댓글만 센다 (SEC-2). 완전 삭제 예약된 수급자는 뺀다.
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 보호자가 있는 수급자 2명과 "없음"인 수급자 1명이 있을 때, When 게시판 탭을 열면, Then 2줄만 보인다.
- [ ] Given 수급자 A에게 11월 1일 보고서를 보냈고 댓글이 3개일 때, When 게시판 탭을 열면, Then A 줄에 "11월 1일 방문 보고서 · 댓글 3"이 보인다.
- [ ] Given 보호자가 단 안 읽은 댓글이 2개일 때, When 게시판 탭을 열면, Then 그 줄에 "새 댓글 2"가 보이고 하단 메뉴에도 2가 보인다.
- [ ] Given 그 게시글을 열어 읽은 뒤, When 게시판 탭으로 돌아오면, Then "새 댓글" 표시가 사라진다.
- [ ] Given 보낸 보고서가 없는 수급자가, When 게시판 탭을 열면, Then "아직 보낸 보고서가 없어요"가 보인다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 보호자 댓글 작성 → 안 읽은 수 1 → 읽음 처리 → 0 (STB-7 후보)
- 수동 확인: 체험 계정 샘플(최근 보고서 댓글 4개, 진료 참고용 요약 글)로 표시 확인 (OPS-1)

## 10. 리스크와 열린 질문

- 리스크: 목록 화면은 자동으로 새로 고치지 않아, 열어 둔 동안 온 댓글은 다른 화면으로 갔다 와야 보인다.
- 열린 질문:
  - 06-roles 11/1 기록에는 "안 읽은 댓글 수는 아직 없음", 07-features와 코드에는 있음. 개발 1 리뷰가 끝났는지
  - 안 읽은 댓글이 있는 게시판을 위로 올릴지
  - 웹 푸시 알림(해커톤 이후)을 만들면 알림 설정을 어디에 둘지
