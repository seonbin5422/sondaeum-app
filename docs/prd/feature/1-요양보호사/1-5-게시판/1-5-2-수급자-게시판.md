# PRD: 수급자 게시판

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-5 게시판 | C-18 수급자 게시판 | `/v1120/chats/[clientId]` | 구현됨 (DIF-5 리뷰 중) · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 보낸 보고서와 서류가 흩어져 있으면 보호자와 무엇을 두고 이야기하는지 헷갈린다.
- 왜 지금 필요한가: 수급자 1명 = 게시판 1개로 정하고, 보낸 보고서와 "게시판에 올리기"한 진료 참고용 요약이 글로 자동으로 쌓이게 했다 (D-15 261101.ver).
- 관련 문서/이슈: `docs/prd/07-features.md` 1-5, `docs/prd/04-prd.md` 8절, `docs/design/02-screens.md` C-18, DIF-5

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 한 수급자에게 보낸 보고서·서류를 최신순 글 카드로 보고, 글마다 댓글 상황을 확인한 뒤 게시글로 들어간다.
- 기대 효과: 보호자와 같은 화면을 보며 글 단위로 이야기한다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 보호자 (같은 글을 보호자 게시판 2-2-1에서 봄)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 안내 "{성함} {호칭}({관계})와 함께 보는 게시판이에요. 보고서를 보내면 글이 자동으로 올라와요."
- [x] "보고서 N개 · 최신 글이 위"
- [x] 글 카드: 작성자(요양보호사)·시각, 종류 표시(방문 보고서 / 진료 참고용 요약), 제목, 미리보기 2줄, 마지막 댓글, 댓글 수, 새 댓글 수
- [x] 글이 없으면 "방문 보고서를 보내면 여기에 올라와요."
- [x] 화면을 보고 있는 동안 5초마다 새로 고침

이번 작업에 포함하지 않음:

- [ ] 요양보호사나 보호자가 글을 직접 쓰기
- [ ] 글 지우기·고치기 (보낸 보고서는 잠금, STB-1)
- [ ] 실시간 채팅 (D-15)

## 5. 사용자 흐름

1. 요양보호사가 게시판 탭의 수급자 줄, 수급자 정보의 "게시판", 또는 홈 카드의 "보호자님 새 댓글 N개"를 누른다.
2. 시스템은 이 수급자의 보낸 보고서·올린 서류를 최신순 카드로 보여 준다.
3. 요양보호사는 "새 댓글" 표시가 있는 카드를 눌러 게시글 상세(1-5-3)로 간다.
4. 화면을 열어 둔 동안 시스템은 5초마다 글·댓글을 다시 받아 카드를 갱신한다.

## 6. 기능 요구사항

- FR-1: `myClient(clientId)`로 내 수급자인지 확인하고, 없거나 관계가 "없음"이면 404.
- FR-2: `myBoard(clientId)`는 이 수급자의 상태 SENT 방문(보고서 글)과 `sharedDocument`(서류 글)를 합쳐 시각 최신순으로 돌려준다.
- FR-3: 보고서 글의 미리보기는 특이사항(보호자용) 또는 신체활동 요약, 서류 글은 "YYYY.MM.DD ~ YYYY.MM.DD 방문 기록을 모은 요약이에요…".
- FR-4: 카드의 새 댓글 수는 상대(보호자)가 쓰고 `readAt`이 없는 댓글 수.
- FR-5: `LiveRefresh`는 `document.visibilityState`가 "visible"일 때만 5초마다 `router.refresh()`한다.
- FR-6: 카드를 누르면 `/v1120/chats/[clientId]/[shareToken]`.

## 7. 비기능 요구사항

- 성능: 5초 새로 고침은 화면이 보일 때만. 매번 글·댓글 전체를 다시 읽는다.
- 접근성: 카드 전체가 하나의 링크, 종류 표시는 글자로, 아이콘은 `aria-hidden`
- 보안: 내 수급자·내가 보낸 방문만 (SEC-2). 댓글은 암호화 저장, 풀 수 없으면 "(읽을 수 없는 댓글)" (LAW-11)
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 보고서 2개를 보내고 진료 참고용 요약 1개를 올린 수급자가, When 수급자 게시판을 열면, Then 카드 3개가 시각 최신순으로 보이고 "보고서 3개"가 보인다.
- [ ] Given 보고서를 하나도 안 보낸 수급자가, When 게시판을 열면, Then "방문 보고서를 보내면 여기에 올라와요."가 보인다.
- [ ] Given 게시판을 열어 둔 상태에서, When 보호자가 댓글을 달면, Then 5초 안에 그 카드의 댓글 수와 "새 댓글 1"이 바뀐다.
- [ ] Given 관계가 "없음"인 수급자의 게시판 주소를, When 열면, Then 404가 나온다.
- [ ] Given 다른 요양보호사의 수급자 id로, When 게시판을 열면, Then 404가 나온다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 보고서 보내기 → 게시판에 글 생김, 같은 기간 요약 두 번 올리기 → 글 1개 (STB-7 후보)
- 수동 확인: 두 기기(요양보호사·보호자)로 5초 갱신 확인 (US-6)

## 10. 리스크와 열린 질문

- 리스크: 열어 둔 사람이 많아지면 5초마다 전체를 다시 읽어 DB 부담이 커진다.
- 열린 질문:
  - "보고서 N개"는 서류 글까지 센다. 제목을 "글 N개"로 바꿀지
  - 삭제한 수급자(`isActive=false`)도 주소로 들어오면 요양보호사 게시판이 열리고 댓글도 달 수 있다. 막을지
  - 학대 의심 표현이 있는 보고서(LAW-7)는 게시판에 글로 올리지 않는지, 어떻게 표시할지 확인 필요
