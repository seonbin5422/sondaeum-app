# PRD: 게시글 상세 · 댓글

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-5 게시판 | C-18 게시글 상세 | `/v1120/chats/[clientId]/[shareToken]` | 구현됨 (DIF-5 리뷰 중, LAW-11 댓글 암호화 11/1 반영) · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 보호자가 보고서를 보고 궁금한 점이 생겨도 전화 말고는 물을 곳이 없었다. 대화방 하나에 모든 이야기를 섞으면 어떤 방문 이야기인지 알기 어렵다.
- 왜 지금 필요한가: 글(보고서)마다 댓글로 이야기하도록 바꿨다(D-15 261101.ver). 성공 기준 US-6 "보호자 댓글이 요양보호사 화면에 5초 안에 보임"이 이 화면에 걸려 있다.
- 관련 문서/이슈: `docs/prd/07-features.md` 1-5, `docs/prd/04-prd.md` 4절 US-6·8절, DIF-5, LAW-11

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보고서·서류 요약을 보고, 보호자 댓글을 읽고, 댓글로 답한다.
- 기대 효과: 보호자 질문에 그 방문 기록을 옆에 두고 답한다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 보호자 (같은 글에 2-2-2에서 댓글)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 글 요약: 작성자·시각·"보낸 보고서/올린 서류", 한 일, 특이사항(또는 기간), "보고서 전체 보기 / 요약 보기" 버튼
- [x] 댓글 목록: 오래된 것이 위, 작성자 이름·"요양보호사/보호자"·"나"·시각·내용
- [x] 아래 고정 입력칸 "댓글을 입력해 주세요"와 "올리기", 500자까지
- [x] 실패하면 입력칸 아래 오류 문구
- [x] 화면을 연 동안 보호자 댓글을 읽음으로 처리, 5초마다 새 댓글 확인
- [x] 댓글 암호화 저장

이번 작업에 포함하지 않음:

- [ ] 댓글 고치기·지우기
- [ ] 사진·파일 첨부
- [ ] 댓글 알림 (웹 푸시, 해커톤 이후)

## 5. 사용자 흐름

1. 요양보호사가 수급자 게시판에서 글 카드를 누른다.
2. 시스템은 글 요약과 댓글을 보여 주고, 안 읽은 보호자 댓글을 읽음으로 바꾼다.
3. 요양보호사가 댓글을 적고 "올리기"를 누른다.
4. 시스템은 검사·암호화해 저장하고 화면을 새로 고쳐 댓글을 보여 준다. 5초마다 보호자의 새 댓글도 확인한다.

## 6. 기능 요구사항

- FR-1: `myClient`로 내 수급자인지, 관계가 "없음"이 아닌지 확인하고, `myBoard`에서 `shareToken`이 같은 글을 찾는다. 없으면 404.
- FR-2: "전체 보기"는 보고서면 `/v1120/g/[shareToken]?from=board`, 서류면 `/v1120/client/[id]/documents/summary?from=…&to=…`.
- FR-3: 댓글 쓰기 `commentAsCaregiver(shareToken, text)`: 앞뒤 공백을 지우고, 비면 "댓글을 적어 주세요.", 500자를 넘으면 "댓글은 500자까지 쓸 수 있어요."로 거부한다.
- FR-4: 댓글은 내 수급자의, 보낸 보고서 또는 올린 서류에만, 완전 삭제 예약이 없을 때만 달린다(`postTarget`). 아니면 "게시글을 찾을 수 없어요."
- FR-5: 댓글 본문은 `encryptText`로 저장하고, 읽을 때 풀 수 없으면 "(읽을 수 없는 댓글)".
- FR-6: 안 읽은 보호자 댓글이 있으면 `markReadAsCaregiver(shareToken)`로 `readAt`을 채운다. 새 댓글이 오면 다시 부른다.
- FR-7: 입력칸은 `maxLength=500`, 빈 칸이거나 보내는 중이면 "올리기"를 막는다.

## 7. 비기능 요구사항

- 성능: 5초 새로 고침(화면이 보일 때만), 실시간 연결 없음
- 접근성: 입력칸 높이 56px, `aria-label="{글 제목}에 댓글 쓰기"`, 댓글 글자 18px
- 보안: 댓글 암호화(LAW-11), 내 수급자 글에만 쓰기(SEC-2)
- 로깅/모니터링: 따로 없음

## 8. 수용 기준

- [ ] Given 보호자 댓글 2개가 안 읽은 상태일 때, When 요양보호사가 게시글을 열면, Then 댓글 2개가 보이고 게시판 목록·하단 메뉴의 새 댓글 수가 0이 된다.
- [ ] Given 게시글에서, When "오늘은 잘 드셨어요"를 적고 올리기를 누르면, Then 목록 맨 아래에 "요양보호사 · 나"로 보인다.
- [ ] Given 공백만 적었을 때, When 화면을 보면, Then 올리기 버튼이 눌리지 않는다.
- [ ] Given 화면 검사를 건너뛰고 501자 댓글을 보내면, When 서버가 받으면, Then "댓글은 500자까지 쓸 수 있어요."가 보이고 저장되지 않는다.
- [ ] Given 게시글을 열어 둔 상태에서, When 보호자가 댓글을 달면, Then 5초 안에 화면에 나타난다.
- [ ] Given 저장된 댓글이, When DB에서 보면, Then 평문이 아닌 암호화된 값이다.

## 9. 검증 계획

- 단위 테스트: 없음. `commentBody`(빈 글·500자 검사)를 단위 테스트로 뺄 수 있다.
- 통합 테스트: 남의 수급자 `shareToken`으로 `commentAsCaregiver` 거부 (STB-7)
- 수동 확인: 요양보호사·보호자 두 기기로 주고받기, 아이폰에서 고정 입력칸이 키보드에 가리지 않는지 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크: 댓글을 고치거나 지울 수 없어 잘못 쓴 개인정보를 지울 방법이 없다.
- 열린 질문:
  - 댓글에 건강 정보가 들어갈 텐데, 동의 문구의 "게시판 댓글" 보관 기간(탈퇴할 때까지)이 맞는지 기획 확인
  - 요양보호사 댓글 고치기·지우기를 넣을지
  - 삭제한 수급자의 글에도 요양보호사 댓글이 달린다(`postTarget`이 `isActive`를 보지 않음). 막을지
