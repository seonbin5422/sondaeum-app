# PRD: 서류·기간 고르기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 (보호자 G-03도 같은 화면) | 1-6 서류 만들기 | C-19 | `/v1120/client/[id]/documents` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 보호자가 병원 진료 때 돌봄 기록을 보여 주려면 지난 보고서를 다시 모아야 한다. 요양보호사도 기관 시스템에 옮길 때 기록지 순서로 다시 봐야 한다.
- 왜 지금 필요한가: D-29(10/13 확정)로 기능 이름을 "서류 만들기"로 정하고, 진료 참고용 요약과 급여제공기록지 두 가지를 하루~기간 단위로 만들기로 했다. 보험사·기관 제출용은 법적 문제로 뺐다.
- 관련 문서/이슈: DIF-4, D-26, D-29, US-4, `docs/prd/04-prd.md` 7절, Figma 308:57·308:2·307:2

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 서류 종류와 기간을 골라 그 기간에 보낸 기록으로 서류를 만든다.
- 기대 효과: 두 번만 고르면 서류가 나오고, 기록이 없는 기간은 미리 알려 빈 서류를 만들지 않는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사 (수급자 정보·방문 기록 화면에서 들어옴)
- 보조 사용자: 보호자 (G-03, 보호자 앱 예시에서 같은 화면을 씀, D-26)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 홈에서 들어올 때 수급자가 여럿이면 `/v1120/documents` "누구의 서류를 만들까요?"에서 먼저 고른다. 뒤로 가면 고르는 화면으로 (11/6)
- [x] "어떤 서류가 필요하세요?": 진료 참고용 요약 / 급여제공기록지
- [x] 서류를 고르면 "어느 기간을 모을까요?": 하루(날짜 하나) / 최근 1주 / 최근 1개월 / 직접 고르기(시작·끝)
- [x] 기간마다 그 안의 방문 수 표시, "보낸 기록만 모아요. 방문 N번이 들어가요."
- [x] 안 고르거나 기록이 없으면 버튼을 끄고 이유 표시
- [x] 안내 "요양보호사가 보낸 기록으로 만들어요 · 진단서나 기관이 발급하는 공식 사본은 아니에요."

이번 작업에 포함하지 않음:

- [ ] 보험사·기관 제출용 보고서 (D-29)
- [ ] 외부 기관으로 바로 보내기 (D-14)
- [ ] 보내지 않은(임시저장) 기록 넣기

## 5. 사용자 흐름

1. 요양보호사가 수급자 화면에서 "서류 만들기"를 누른다.
2. 시스템은 서류 종류 두 개를 보여 준다. 하나를 고르면 기간 선택이 나타난다.
3. 요양보호사가 기간을 고른다. 시스템은 그 기간의 보낸 방문 수를 보여 주고 "서류 만들기" 버튼을 켠다.
4. "서류 만들기"를 누르면 진료 참고용 요약(1-6-2)이나 급여제공기록지(1-6-3)가 열린다.

## 6. 기능 요구사항

- FR-1: 내 수급자가 아니면 404. 보낸 방문(`status === "SENT"`)의 날짜만 센다.
- FR-2: 오늘은 KST 날짜(`kstYmd`). 최근 1주 = 7일 전 ~ 오늘, 최근 1개월 = 30일 전 ~ 오늘.
- FR-3: 하루는 기본값으로 가장 최근 보낸 날(없으면 오늘)을 넣는다. 날짜 칸은 오늘 이후를 고를 수 없다(`max`).
- FR-4: 버튼이 꺼지는 이유: "서류 종류를 골라 주세요" → "기간을 골라 주세요" → "이 기간에 보낸 기록이 없어요".
- FR-5: 버튼을 누르면 `{basePath}/summary|care-sheet?from=YYYY-MM-DD&to=YYYY-MM-DD`로 간다.
- FR-6: 보호자 화면(G-03)은 같은 컴포넌트(`DocumentPicker`)를 `basePath`만 바꿔 쓴다.

## 7. 비기능 요구사항

- 성능: 서버에서 수급자 1명과 방문 이력을 한 번 읽고, 방문 수 계산은 화면에서 한다.
- 접근성: 선택 버튼 높이 64px 이상, `aria-pressed`로 선택 상태, 날짜 입력 높이 56px.
- 보안: 내 수급자만 (SEC-2). 보호자 쪽은 토큰으로 들어옴.
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 서류 만들기 화면에서, When 아무것도 고르지 않으면, Then 버튼이 꺼져 있고 "서류 종류를 골라 주세요"가 보인다.
- [ ] Given "진료 참고용 요약"을 고른 뒤, When 기간을 고르지 않으면, Then "기간을 골라 주세요"가 보인다.
- [ ] Given 최근 1주에 보낸 방문이 3번일 때, When "최근 1주"를 고르면, Then "방문 3번"이 보이고 버튼이 켜진다.
- [ ] Given 보낸 기록이 없는 날을, When "하루"로 고르면, Then 버튼이 꺼지고 "이 기간에 보낸 기록이 없어요"가 보인다.
- [ ] Given 급여제공기록지와 직접 고르기 10/1~10/31을 골랐을 때, When "서류 만들기"를 누르면, Then `care-sheet?from=2026-10-01&to=2026-10-31`이 열린다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 체험 계정 예시 수급자로 네 가지 기간 × 두 서류, 아이폰 Safari 날짜 입력

## 10. 리스크와 열린 질문

- 리스크: 기간 계산이 화면(브라우저)에서 `+09:00` 기준 날짜 이동으로 되어 있어, 서버 `kstYmdDaysAgo`와 하루 어긋날 가능성이 있다 (확인 필요).
- 열린 질문:
  - 직접 고르기에서 시작이 끝보다 늦으면 방문 0번으로 버튼만 꺼진다. "기간을 다시 골라 주세요"처럼 따로 알릴지
  - 최근 1주를 "7일 전부터 오늘까지(8일)"로 둘지 "오늘 포함 7일"로 둘지 기획 확인
  - 1-6-2의 기본 기간(최근 30일)과 1-6-3의 기본 기간(오늘)이 다른데, 주소에 기간 없이 들어오는 경우를 허용할지
