# PRD: 내 정보 고치기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-7 내 정보 | C-06 | `/v1120/me/edit` → 서버 액션 `updateMe` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 처음 설정에서 이름·자격번호를 잘못 적으면 보고서·서류의 작성자 칸에 틀린 값이 들어간다.
- 왜 지금 필요한가: 내 정보 탭(D-32)을 만들면서 처음 설정(C-02)과 같은 칸을 고칠 수 있게 했다.
- 관련 문서/이슈: C-06, `docs/prd/07-features.md` 1-7

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 지금 값이 채워진 폼에서 이름·자격번호를 고치고 저장한다.
- 기대 효과: 작성자 정보를 직접 바로잡는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 체험 계정 사용자
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 이름(필수)·자격번호(필수, "자격증에 적힌 번호예요.") 두 칸, 지금 값으로 채움
- [x] "고친 내용 저장하기" → 저장 후 내 정보로 이동
- [x] 위쪽 뒤로 가기(내 정보로)

이번 작업에 포함하지 않음:

- [ ] 비밀번호 변경 (카카오 로그인이라 없음)
- [ ] 연락처·소속 기관·사진 고치기
- [ ] 고친 기록(이력) 남기기

## 5. 사용자 흐름

1. 요양보호사가 내 정보에서 "내 정보 고치기"를 누른다.
2. 시스템은 지금 이름·자격번호가 채워진 폼을 보여 준다.
3. 요양보호사가 고치고 "고친 내용 저장하기"를 누른다.
4. 시스템은 값을 확인해 저장하고 내 정보 화면으로 보낸다.

## 6. 기능 요구사항

- FR-1: `requireCaregiver()`로 지금 값을 읽어 `defaultValue`로 채운다. 자격번호가 없으면 빈칸.
- FR-2: 두 칸 모두 `required` (브라우저가 빈 칸 제출을 막음).
- FR-3: `updateMe(form)`은 앞뒤 공백을 지운 값이 둘 중 하나라도 비면 "이름과 자격번호를 적어 주세요." 오류를 낸다.
- FR-4: 로그인한 요양보호사 본인 행만 고친 뒤 `/v1120/me`로 보낸다.

## 7. 비기능 요구사항

- 성능: DB 쓰기 1번
- 접근성: 입력칸 높이 56px, 라벨 18px, "(필수)" 글자 표시
- 보안: 세션의 요양보호사 id로만 고친다 (다른 사람 id를 보낼 칸이 없음).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 이름이 "박현우"인 요양보호사가, When 이름을 "박현수"로 고쳐 저장하면, Then 내 정보에 "박현수 요양보호사"가 보인다.
- [ ] Given 고치기 화면에서, When 자격번호를 지우고 저장하면, Then 저장되지 않는다.
- [ ] Given 이름을 공백 세 칸으로 바꿔 서버로 보냈을 때, When 처리되면, Then "이름과 자격번호를 적어 주세요." 오류가 나고 값이 바뀌지 않는다.
- [ ] Given 이름을 고친 뒤, When 새로 서류(진료 참고용 요약)를 만들면, Then 작성자 칸에 새 이름이 나온다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 위 수용 기준, 고친 뒤 홈 인사말 확인

## 10. 리스크와 열린 질문

- 리스크: 보호자 보고서·서류 화면은 작성자 이름을 **보낼 때 저장한 값이 아니라 지금 계정 이름**으로 읽는다(`visit.caregiver.name`). 이름을 고치면 이미 보낸 보고서의 작성자 이름도 바뀌어 보인다.
- 열린 질문:
  - 보낸 보고서·서류의 작성자 이름을 보낸 시점 값으로 고정할지 (STB-1 "보낸 뒤 고칠 수 없음"과 맞추려면 고정 필요)
  - `updateMe`가 오류를 던질 때 화면에 어떻게 보이는지 (오류 화면 vs 칸 아래 안내) 확인 필요
  - 자격번호 형식 검사를 할지
