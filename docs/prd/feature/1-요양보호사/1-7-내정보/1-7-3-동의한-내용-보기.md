# PRD: 동의한 내용 보기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-7 내 정보 | (C-21 내용 다시 보기) | `/v1120/me/consent` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 처음 설정 때 동의한 뒤에는 무엇에 언제 동의했는지 다시 볼 곳이 없었다. 정보주체는 자기 동의 내용을 확인할 수 있어야 한다.
- 왜 지금 필요한가: LAW-3에서 동의 시각·항목을 저장하기 시작했다 (10/13부터).
- 관련 문서/이슈: LAW-3, `app/v1120/_consent.ts`, `prisma/schema.prisma` `consentedAt`·`consentItems`

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 동의한 날짜와 네 항목, 항목별 자세한 내용을 다시 본다.
- 기대 효과: 동의 화면과 같은 내용을 언제든 확인한다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 체험 계정 사용자
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] "{날짜}에 아래 항목에 동의했어요." (한국 시간, 예: 2026년 11월 2일)
- [x] 동의 날짜가 없는 계정은 "처음 시작할 때 아래 항목에 동의했어요. (동의 날짜는 10월 13일부터 기록해요)"
- [x] 네 항목 제목 + "✓ 동의함" + "자세히 보기"
- [x] "개인정보 처리방침 전체 보기" 링크

이번 작업에 포함하지 않음:

- [ ] 동의 철회
- [ ] 동의한 문구 버전 표시
- [ ] 동의 내역 내려받기

## 5. 사용자 흐름

1. 요양보호사가 내 정보에서 "동의한 내용 보기"를 누른다.
2. 시스템은 저장된 동의 시각·항목을 읽어 날짜와 항목 목록을 보여 준다.
3. 요양보호사는 필요하면 "자세히 보기"나 처리방침을 연다.

## 6. 기능 요구사항

- FR-1: `requireCaregiver()`로 `consentedAt`·`consentItems`를 읽는다.
- FR-2: `consentedAt`이 있으면 `ko-KR`·`Asia/Seoul`·`dateStyle: long`으로 날짜를 만든다.
- FR-3: 항목 목록은 `CONSENT_ITEMS`를 쓰고, `consentItems`에 키가 있거나 `consentedAt`이 없으면 "✓ 동의함"을 보여 준다.
- FR-4: "자세히 보기"는 동의 화면과 같은 `ConsentDetails`를 쓴다.

## 7. 비기능 요구사항

- 성능: DB 읽기 1번(요양보호사)
- 접근성: 항목 제목 18px, 배지는 "✓" 기호와 글자로 표시(색만으로 구분하지 않음)
- 보안: 본인 동의 기록만 보여 준다.
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 2026-11-02에 네 항목에 동의한 요양보호사가, When 동의한 내용을 열면, Then "2026년 11월 2일에 아래 항목에 동의했어요."와 네 항목 "✓ 동의함"이 보인다.
- [ ] Given 동의 시각이 없는 옛 계정이, When 화면을 열면, Then "동의 날짜는 10월 13일부터 기록해요" 안내가 보인다.
- [ ] Given 화면에서, When 국외 이전의 "자세히 보기"를 펼치면, Then 동의 화면과 같은 받는 곳 3곳이 보인다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 새 계정·옛 계정(동의 시각 없음) 각각

## 10. 리스크와 열린 질문

- 리스크: 동의 시각이 없는 옛 계정도 네 항목 모두 "✓ 동의함"으로 보인다. 실제로 그 항목(예: 국외 이전)에 동의했는지 기록은 없다.
- 열린 질문:
  - 동의 시각이 없는 옛 계정에게 다시 동의를 받을지
  - 동의 철회를 이 화면에 둘지 (철회하면 손다음을 쓸 수 없으므로 탈퇴와 함께 설계 필요)
