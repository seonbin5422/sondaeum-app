# PRD: 개인정보 처리방침 링크 · 로그아웃

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 요양보호사 | 1-7 내 정보 | 내 정보 탭 메뉴 | `/v1120/me` → `/v1120/privacy`, 서버 액션 `logout` | 구현됨 · `feature/v1120` dcaa0df 기준 |

## 1. 배경

- 현재 문제: 처리방침은 언제든 열어 볼 수 있어야 하고, 한 기기를 여럿이 쓰거나 체험 계정을 끝낼 때 로그아웃이 필요하다.
- 왜 지금 필요한가: 하단 메뉴 4개(D-32)로 정리하면서 계정 관련 메뉴를 내 정보 탭에 모았다.
- 관련 문서/이슈: LAW-12, D-32, `docs/prd/07-features.md` 1-7

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 내 정보에서 처리방침을 열고, 로그아웃해 로그인 화면으로 돌아간다.
- 기대 효과: 공유 기기에서 다른 사람이 내 수급자 정보를 보지 않게 한다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사
- 보조 사용자: 체험 계정 사용자 (체험을 끝내고 카카오로 다시 로그인)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] "개인정보 처리방침" 메뉴 → `/v1120/privacy` (내용은 1-1-5)
- [x] "로그아웃" 메뉴 → 세션 쿠키 삭제 → `/v1120/login`

이번 작업에 포함하지 않음:

- [ ] 카카오 계정 로그아웃(카카오 쪽 세션 끊기)
- [ ] 로그아웃 확인창
- [ ] 회원 탈퇴

## 5. 사용자 흐름

1. 요양보호사가 내 정보에서 "로그아웃"을 누른다.
2. 시스템은 손다음 세션 쿠키를 지우고 로그인 화면으로 보낸다.
3. 요양보호사는 로그인 화면을 본다. 다른 계정으로 들어가려면 "다른 카카오 계정으로 로그인"을 누른다.

## 6. 기능 요구사항

- FR-1: 처리방침 메뉴는 `Link href="/v1120/privacy"`다.
- FR-2: 로그아웃은 `<form action={logout}>` 버튼이고, `logout()`은 `deleteSession()`(쿠키 `session` 삭제) 후 `/v1120/login`으로 보낸다.
- FR-3: 로그아웃 뒤 로그인이 필요한 화면은 `requireCaregiver()`가 `/v1120/login`으로 돌려보낸다.

## 7. 비기능 요구사항

- 성능: 쿠키 삭제만, DB 호출 없음
- 접근성: 메뉴 줄 높이 64px, 글자 18px, 로그아웃은 링크가 아닌 버튼
- 보안: 세션 쿠키를 지운다. 카카오 로그인 상태는 브라우저에 남는다 (로그인 화면 주석).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 내 정보 탭에서, When "개인정보 처리방침"을 누르면, Then 처리방침 화면이 열린다.
- [ ] Given 로그인한 요양보호사가, When "로그아웃"을 누르면, Then 로그인 화면이 열린다.
- [ ] Given 로그아웃한 뒤, When 주소창에 `/v1120`을 입력하면, Then 홈 대신 로그인 화면이 열린다.
- [ ] Given 로그아웃한 뒤, When "카카오로 시작하기"를 누르면, Then 카카오가 계정을 묻지 않고 같은 계정으로 들어갈 수 있다 (알려진 동작).

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음. STB-7에 "로그아웃 후 보호 화면 접근 차단"을 넣을 수 있다.
- 수동 확인: 카카오·체험 계정 각각 로그아웃, 뒤로 가기 눌러 보기

## 10. 리스크와 열린 질문

- 리스크: 로그아웃해도 카카오 로그인은 남아 있어, 공용 기기에서 다음 사람이 "카카오로 시작하기"를 누르면 앞사람 계정으로 들어갈 수 있다.
- 열린 질문:
  - 로그아웃 때 카카오 로그아웃까지 할지, 아니면 로그인 화면에 안내를 둘지
  - 체험 계정이 로그아웃하면 그 데이터를 바로 지울지 (지금은 24시간 뒤)
  - 실수로 누르는 것을 막는 확인창이 필요한지
