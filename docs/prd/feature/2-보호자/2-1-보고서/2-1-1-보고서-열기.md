# PRD: 받은 보고서 열기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 보호자 | 2-1 보고서 | G-01 | `/v1120/g/[token]` | 구현됨 · `feature/v1120` ae8748e 기준 |

## 1. 배경

- 현재 문제: 보호자는 떨어져 사는 어르신이 그날 어떤 돌봄을 받았는지 알 길이 없다. 앱 설치나 가입을 요구하면 보호자(특히 사회복지사·주민센터 담당자)가 보고서를 열지 않는다.
- 왜 지금 필요한가: 요양보호사가 보낸 보고서(C-16)를 카카오톡 공유 카드·링크로 받는 흐름이 핵심 시연 흐름(기록 → 전송 → 열람)의 마지막 단계다.
- 관련 문서/이슈: `docs/prd/07-features.md` 2-1, `docs/prd/04-prd.md` 3.2·US-5, STB-5, LAW-9, D-25, D-48

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 받은 링크를 누르면 로그인 없이 그 방문의 보고서를 바로 본다.
- 사용자가 무엇을 할 수 있어야 하는가 (11/14 추가): 보호자가 보고서를 확인하고 그 화면에서 확인 서명을 보낸다 (D-48 261114.ver).
- 기대 효과: 보호자 열람까지 걸리는 단계를 링크 클릭 한 번으로 줄인다. 보호자가 방문 현장에 없어도 급여제공기록지의 수급자·보호자 서명을 받는다.

## 3. 대상 사용자

- 주요 사용자: 보호자 (가족·사회복지사·주민센터·후견인, D-49)
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 링크의 `shareToken`으로 보고서를 찾아 로그인 없이 보여 준다
- [x] 보낸(`sentAt` 있음) 보고서만, 기록(`careRecord`)이 있는 것만 보여 준다
- [x] 지운 수급자(`isActive=false`)·완전히 지우기 예약(`purgeAt` 있음)이면 보여 주지 않는다
- [x] 머리말: "안녕하세요, {보호자 이름} {호칭}님", "{어르신} 어르신 방문 보고서", 방문 날짜·시간·길이
- [x] 확인 서명 (D-48 261114.ver): "보고서 내용을 확인하셨으면 서명해 주세요. 기관에 내는 급여제공기록지에 함께 들어가요." + 서명칸 + "서명 보내기". 보내면 "서명을 보냈어요. 고마워요.", 실패하면 "서명을 보내지 못했어요. 인터넷 연결을 확인하고 다시 눌러 주세요."
- [x] 요양보호사로 로그인된 기기("보호자가 보는 화면 확인하기" 등)에서는 서명칸을 숨기고 "요양보호사로 로그인되어 있어 서명칸은 보이지 않아요."를 보여 준다
- [x] 보호자 서명과 함께 서명 시각·기기(브라우저 종류)·접속 주소를 바꾼 값을 남기고(`recipientMeta`), 요양보호사 급여제공기록지에 "보호자 서명: 시각, 보고서 링크에서"로 보인다

이번 작업에 포함하지 않음:

- [ ] 링크 만료·미리보기 봇 열람 제외 (STB-5, 11/13 예정)
- [ ] 열람 기록 남기기
- [ ] 보호자 로그인 (D-44, P2). 그 전까지는 링크가 있는 다른 브라우저에서도 서명할 수 있다

## 5. 사용자 흐름

1. 보호자가 카카오톡 공유 카드의 버튼이나 복사된 링크를 누른다.
2. 시스템은 토큰으로 보낸 보고서를 찾고, 수급자가 지워지지 않았는지 확인한 뒤 보고서 화면을 연다.
3. 보호자는 어르신 이름·방문 날짜와 보고서 내용(2-1-2)을 본다.
4. 보호자가 아래 서명칸에 서명하고 "서명 보내기"를 누른다. 시스템은 서명을 그 보고서에 저장하고 "서명을 보냈어요. 고마워요."를 보여 준다.

## 6. 기능 요구사항

- FR-1: `report.shareToken = token`으로 보고서·방문·수급자·요양보호사를 함께 읽는다.
- FR-2: `sentAt`·`careRecord`가 없거나, 수급자가 `isActive=false`이거나 `purgeAt`이 있으면 보낸 보고서로 취급하지 않는다.
- FR-3: 수급자 이름은 `openPII`로 풀고, 기록은 `decryptText`로 풀어 보여 준다.
- FR-4: 방문 시간은 수급자 방문 시간(`scheduleLabel`)과 방문 날짜로 만든다(`serviceTimeOf`).
- FR-5: 보호자 호칭은 관계에 따라 `contactTitle()`로 정한다.
- FR-6: `signAsGuardian(shareToken, strokes)`는 보낸 보고서이고 수급자가 지워지지 않았을 때만 받는다. 수급자·보호자 칸만 바꾸고 요양보호사 서명·사유는 그대로 둔다. 빈 서명이면 "서명을 해 주세요."
- FR-7: 요양보호사 세션이 있으면 서명칸을 숨기고, 서버도 "요양보호사 계정으로는 보호자 서명을 할 수 없어요."로 거절한다 (대리 서명 막기).
- FR-8: `recipientMeta`는 `{ at, device, ipHash }`: 서명 시각, user-agent 200자, 접속 주소를 `SESSION_SECRET`과 섞어 sha256 한 앞 16자. 접속 주소 원래 값은 남기지 않는다. 처리방침 "모으는 정보"에 적었다.

## 7. 비기능 요구사항

- 성능: 서버 컴포넌트에서 쿼리 1번(보고서 + include).
- 접근성: 제목 24px(`text-2xl`), 본문 18px 이상, 화면 폭 최대 448px(`max-w-md`) 모바일 기준 (DIF-1)
- 보안: 토큰은 추측하기 어려운 값이어야 한다. 기록·이름은 DB에 암호화되어 있다 (SEC-5). 링크만 있으면 누구나 볼 수 있다는 점은 STB-5 전까지 남는 위험이다.
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 요양보호사가 보낸 보고서의 링크가 있을 때, When 로그인하지 않은 브라우저에서 링크를 열면, Then 어르신 이름과 방문 날짜·시간이 있는 보고서가 보인다.
- [ ] Given 임시저장만 하고 보내지 않은 방문의 토큰으로, When 링크를 열면, Then 그 방문의 실제 기록은 보이지 않는다.
- [ ] Given 로그인하지 않은 브라우저에서 보낸 보고서를 연 보호자가, When 서명하고 "서명 보내기"를 누르면, Then "서명을 보냈어요. 고마워요."가 보이고 요양보호사의 급여제공기록지 "수급자 또는 보호자" 칸에 그 서명이 보인다.
- [ ] Given 요양보호사로 로그인된 기기에서, When 보낸 보고서 링크를 열면, Then 서명칸 대신 "요양보호사로 로그인되어 있어 서명칸은 보이지 않아요."가 보인다.
- [ ] Given 보낸 보고서의 수급자를 요양보호사가 삭제했을 때, When 같은 링크를 다시 열면, Then 그 수급자의 실제 기록은 보이지 않는다.

## 9. 검증 계획

- 단위 테스트: `npx tsx --tsconfig tsconfig.json lib/core.check.mts`(요양보호사 기기에서 보호자 서명 거절, 빈 서명·없는 링크 거절, `recipientMeta`에 접속 주소 원래 값이 없음)
- 통합 테스트: 없음. STB-7 권한 테스트에 "보내지 않은 토큰·지운 수급자 토큰으로 실제 기록이 안 보임"을 넣을 수 있다.
- 수동 확인: 카카오톡으로 받은 카드를 아이폰·안드로이드에서 열기 (OPS-2), 삭제 후 같은 링크 다시 열기

## 10. 리스크와 열린 질문

- 리스크: 링크가 다른 사람에게 전달되면 그 사람도 보고서를 본다 (만료 없음).
- 열린 질문:
  - 토큰에 맞는 보낸 보고서가 없을 때 코드(`GuardianReport.tsx`)는 "볼 수 없음" 안내 대신 **예시 보고서(`sampleGuardianReport`)를 보여 준다.** 실제 보호자가 잘못된 링크로 예시 어르신 보고서를 볼 수 있는데, 이 동작을 유지할지, 안내 화면으로 바꿀지
  - 링크 만료 기간을 얼마로 할지 (STB-5)
  - 보호자 서명을 링크만 있으면 누구나 할 수 있다. 보호자 카카오 로그인(P1)이 생기면 초대받은 보호자만 서명하게 바꿀지 (D-48 261114.ver)
  - 카카오톡 미리보기 봇이 열어도 "열람"으로 세지 않게 하려면 무엇을 기준으로 거를지
