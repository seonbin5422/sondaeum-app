## 1. 배경

- 현재 문제: 급여제공기록지 항목(분·체크·호전/유지/악화)은 보호자가 읽기 어렵다. 반대로 보호자용으로 따로 쓰면 요양보호사가 두 번 기록해야 한다.
- 왜 지금 필요한가: 보호자 보고서 고도화(DIF-2, P0)로 같은 기록 데이터를 기록지 순서 그대로, 보호자가 읽기 쉬운 말로 보여 주기로 했다 (D-24).
- 관련 문서/이슈: `docs/prd/04-prd.md` 3.3, DIF-2, D-24, LAW-1, LAW-7

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 오늘 어르신이 받은 돌봄, 상태 변화, 특이사항을 한 화면에서 이해한다.
- 기대 효과: 보호자가 요양보호사에게 따로 묻지 않아도 그날 상태를 안다.

## 3. 대상 사용자

- 주요 사용자: 보호자
- 보조 사용자: 요양보호사 — 보내기 전 "보낼 내용 보기"(C-15)에서 같은 컴포넌트(`ReportSections`)로 미리 본다
- 관리자 또는 운영자 영향: 없음

## 5. 사용자 흐름

1. 보호자가 보고서 링크를 연다 (2-1-1).
2. 시스템은 기록을 항목 순서대로, 한 것·값이 있는 것만 보여 준다.
3. 보호자는 위에서 아래로 읽고, 맨 아래 고지와 "게시판으로 이동하기"(2-1-3)를 본다.

## 6. 기능 요구사항

- FR-1: 신체활동 도움 — 체크한 항목(개인위생·몸씻기·식사도움·체위변경·이동도움·화장실 이용)만 나열, 제공시간이 있으면 "N분", 신체활동 메모(`physicalNote`)가 있으면 보여 준다.
- FR-2: 인지·정서 지원 — 4항목(인지자극활동·일상생활 함께하기·인지행동변화 관리·의사소통·말벗·격려) 중 값이 있는 것을 "N분"으로, 0분은 흐리게 보여 준다.
- FR-3: 가사·일상생활 지원 — 체크한 것(식사준비·청소·세탁, 외출 동행)과 제공시간.
- FR-4: 지난 방문과 비교 — 신체기능·식사기능·인지기능 중 값이 있는 것을 "좋아졌어요/비슷해요/나빠졌어요" 색 칩으로. 값이 하나도 없으면 절을 숨긴다.
- FR-5: 배변 변화 — 대변 실수·소변 실수·기저귀 교환, 0이면 "없음", 아니면 "N번", 값이 없으면 줄을 숨긴다.
- FR-6: 특이사항 — 보호자용 문장(`guardianNotes`), 없으면 기록지용 문장(`notes`). 특이사항이 없으면 절을 숨긴다.

## 7. 비기능 요구사항

- 성능: 클라이언트 렌더링, 추가 요청 없음.
- 접근성: 변화 칩은 색과 글자를 함께 쓴다(색만으로 구분하지 않음). 본문 18px 이상 (DIF-1)
- 보안: 진단·처방 표현을 쓰지 않는다 (LAW-1). 학대 의심 표현은 기록 확인(C-14)에서 자동 전송하지 않도록 막는다 (LAW-7, 리뷰 중).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 신체활동에서 식사도움·이동도움만 체크하고 30분을 적은 보고서에서, When 보호자가 열면, Then "신체활동 도움"에 두 항목과 "제공시간 30분"만 보인다.
- [ ] Given 변화상태 세 칸이 모두 비어 있는 보고서에서, When 보호자가 열면, Then "지난 방문과 비교" 절이 보이지 않는다.
- [ ] Given 대변 실수 0, 소변 실수 2인 보고서에서, When 보호자가 열면, Then "대변 실수 없음", "소변 실수 2번"이 보인다.
- [ ] Given 보호자용 특이사항이 있는 보고서에서, When 보호자가 열면, Then 기록지용 문장(~함·~음) 대신 보호자용 문장이 보인다.
