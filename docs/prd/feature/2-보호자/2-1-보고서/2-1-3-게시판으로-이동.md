# PRD: 게시판으로 이동하기

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 보호자 | 2-1 보고서 | G-01 → G-02 | `/v1120/g/[token]` → `/v1120/g/[token]/board` | 구현됨 · `feature/v1120` ae8748e 기준 |

## 1. 배경

- 현재 문제: 보호자가 보고서를 읽고 궁금한 점이 생겨도 요양보호사에게 따로 전화하거나 문자해야 한다.
- 왜 지금 필요한가: 10/23 멘토링 피드백으로 채팅 대신 게시글 + 댓글 구조를 택했고(D-15 261101.ver), 보호자는 로그인 없이 받은 보고서 링크에서 게시판으로 들어간다.
- 관련 문서/이슈: `docs/prd/04-prd.md` 8절, US-6, DIF-5

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 보고서 아래 버튼 하나로 그 어르신 게시판에 들어가 댓글을 남긴다.
- 기대 효과: 보고서 → 질문 흐름을 한 링크 안에서 끝낸다.

## 3. 대상 사용자

- 주요 사용자: 보호자
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 실제로 보낸 보고서일 때만 "게시판으로 이동하기" 버튼 표시
- [x] 같은 토큰으로 게시판(`/g/[token]/board`)을 연다
- [x] 그 보고서를 보낸 요양보호사가 로그인한 채 "보호자가 보는 화면"으로 열었으면, "게시판으로 이동하기"와 뒤로 가기는 요양보호사 게시판 글(`/v1120/chats/[clientId]/[token]`)로 간다 (D-65)
- [x] 게시판 글의 "보고서 전체 보기"(`?from=board`)로 들어왔으면 버튼을 숨긴다 (뒤로 가기로 돌아감)
- [x] 뒤로 가기 버튼: 돌아갈 곳이 없으면(카톡 링크로 바로 들어옴) 게시판으로 보낸다

이번 작업에 포함하지 않음:

- [ ] 보고서 화면에서 바로 댓글 쓰기
- [ ] 보호자 앱 하단 메뉴(2-3, P2)

## 5. 사용자 흐름

1. 보호자가 보고서 맨 아래 "게시판으로 이동하기"를 누른다.
2. 시스템은 같은 토큰으로 그 어르신 게시판을 열고 보낸 보고서·서류 글을 최신순으로 보여 준다.
3. 보호자는 글을 골라 댓글을 남긴다 (2-2-2).

## 6. 기능 요구사항

- FR-1: `sent`(실제 보낸 보고서)가 있고 `from=board`가 아닐 때만 버튼을 보여 준다.
- FR-2: 버튼 주소는 `/v1120/g/{token}/board`. 요양보호사 세션이 그 방문의 요양보호사와 같으면 `/v1120/chats/{clientId}/{token}` (D-65).
- FR-3: `BackButton`의 fallback은 보낸 보고서면 FR-2와 같은 게시판 주소다.

## 7. 비기능 요구사항

- 성능: 링크 이동만, 추가 요청 없음.
- 접근성: 버튼은 `LinkButton`(큰 터치 영역) (DIF-1)
- 보안: 게시판 접근도 같은 토큰으로 확인한다 (`guardianBoard`). 토큰 하나로 그 어르신 게시판 전체가 열린다.
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 카카오톡으로 받은 보고서 링크를 연 보호자가, When "게시판으로 이동하기"를 누르면, Then "{어르신} 어르신 게시판"이 열리고 방금 본 보고서 글이 목록에 있다.
- [ ] Given 게시판 글에서 "보고서 전체 보기"로 보고서를 연 보호자가, When 화면 아래를 보면, Then "게시판으로 이동하기" 버튼이 없다.
- [ ] Given 보고서를 보낸 요양보호사가 "보호자가 보는 화면 확인하기"로 연 보고서에서, When "게시판으로 이동하기"를 누르면, Then 요양보호사 게시판의 그 글이 열린다 (D-65).
- [ ] Given 카톡 링크로 바로 보고서를 연 보호자가, When 뒤로 가기 버튼을 누르면, Then 게시판으로 간다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 카톡 인앱 브라우저(아이폰·안드로이드)에서 버튼·뒤로 가기 동작 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크: 보고서 하나의 링크로 그 어르신의 모든 보고서·서류가 보인다. 링크가 전달되면 노출 범위가 보고서 하나보다 넓다.
- 열린 질문:
  - 보고서 링크로 들어온 사람에게 게시판 전체를 보여 주는 범위를 STB-5(링크 만료)나 보호자 로그인(D-44) 전까지 이대로 둘지
