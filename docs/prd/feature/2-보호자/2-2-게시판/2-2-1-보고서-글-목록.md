# PRD: 게시판 글 목록 (보고서 글 전체 보기)

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 보호자 | 2-2 게시판 | G-02 | `/v1120/g/[token]/board` | 구현됨 (DIF-5 리뷰 중) · `feature/v1120` ae8748e 기준 |

## 1. 배경

- 현재 문제: 보호자는 보고서를 날마다 따로 받아서 지난 보고서를 다시 찾기 어렵다.
- 왜 지금 필요한가: 수급자 1명 = 게시판 1개로 정하고, 보낸 보고서가 글로 자동으로 올라가게 했다 (D-15 261101.ver).
- 관련 문서/이슈: `docs/prd/04-prd.md` 8절, DIF-5, D-33(초대 링크), D-57, D-65

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 그 어르신에게 보낸 보고서와 올라온 서류를 최신순으로 모아 보고, 새 댓글이 있는 글을 안다.
- 기대 효과: 보고서 이력과 대화가 한곳에 모인다.

## 3. 대상 사용자

- 주요 사용자: 보호자 (보고서 링크·서류 링크·게시판 초대 링크 중 하나를 가진 사람)
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 링크를 보낸 날부터 90일이 지나면 게시판·글·서류 대신 "링크 기간이 지났어요 · 요양보호사에게 새 링크를 받아 주세요" 화면. 받은 보고서 화면 자체는 열린다 (STB-5, D-53, 11/6)
- [x] 토큰 3종으로 입장: 보낸 보고서 `shareToken`, 올린 서류 `shareToken`, 수급자 `boardToken`(초대 링크)
- [x] 요양보호사 게시판(C-18)과 같은 모양 (D-65): 회색 바탕, 상단 바 제목 "{어르신} 어르신 게시판", 흰 글 카드, 최신 글부터·오래된 글부터 정렬
- [x] 머리말: "안녕하세요, {보호자} {호칭}님", 안내 문구
- [x] 주의 문구: "받은 링크로 로그인 없이 들어왔어요. … 다른 사람에게 보내지 말아 주세요."
- [x] 글 카드: 작성자·시각, 종류 칩(방문 보고서/건강 기록 요약), 제목, 미리보기 2줄, 마지막 댓글, 댓글 수, "새 댓글 N"
- [x] 글이 없으면 "아직 보낸 보고서가 없어요…"
- [x] 화면이 보이는 동안 5초마다 새로고침 (`LiveRefresh`)
- [x] 초대 링크로 들어왔으면 뒤로 가기 버튼을 숨긴다
- [x] 처음 열 때 코치마크 "보고서를 눌러 보세요" (D-57)

이번 작업에 포함하지 않음:

- [ ] 보호자가 직접 글 쓰기
- [ ] 실시간 채팅, 푸시 알림 (해커톤 이후)
- [ ] 검색·기간 필터

## 5. 사용자 흐름

1. 보호자가 보고서의 "게시판으로 이동하기"나 초대 링크를 연다.
2. 시스템은 토큰으로 수급자를 찾고, 그 수급자의 보낸 보고서와 올린 서류를 최신순 글로 보여 준다.
3. 보호자는 "새 댓글" 표시가 있는 글을 눌러 상세(2-2-2)로 간다.

## 6. 기능 요구사항

- FR-1: `guardianBoard(token)`은 보낸 보고서 → 올린 서류 → 초대 토큰 순으로 수급자를 찾는다. 수급자가 `isActive=false`거나 `purgeAt`이 있으면 404.
- FR-2: 글 = 그 수급자의 `status=SENT` 방문 + `sharedDocument`, 최신순.
- FR-3: "새 댓글 N" = 요양보호사가 단 댓글 중 `readAt`이 없는 수.
- FR-4: 화면이 보이는 상태(`visibilityState=visible`)일 때만 5초마다 `router.refresh()`.
- FR-5: 초대 링크로 들어오면(`viaInvite`) 뒤로 가기 버튼을 숨긴다.
- FR-6: 목록은 요양보호사 게시판과 같은 `PostList`를 쓴다. 글 주소는 `/v1120/g/{글 토큰}/post` (D-65).

## 7. 비기능 요구사항

- 성능: 5초 폴링은 화면이 보일 때만. 수급자 1명의 글 전체를 매번 읽는다 (페이지 나누기 없음).
- 접근성: 카드 제목 20px, 본문 18px, 칩은 글자로 종류를 표시 (DIF-1)
- 보안: 링크만 있으면 누구나 그 수급자 게시판 전체를 본다 (코드 주석에 shortcut으로 표시, STB-5·D-44에서 막을 예정). 댓글은 암호화 저장, 읽을 수 없으면 "(읽을 수 없는 댓글)".
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 보낸 보고서 3개와 올린 건강 기록 요약 1개가 있는 수급자의 링크로, When 게시판을 열면, Then 글 4개가 최신순으로 보이고 각 글에 종류 칩이 있다.
- [ ] Given 글이 3개인 게시판에서, When 정렬을 "오래된 글부터"로 바꾸면, Then 가장 오래된 글이 맨 위에 온다.
- [ ] Given 요양보호사가 보호자가 아직 안 읽은 댓글 2개를 단 글이 있을 때, When 보호자가 게시판을 열면, Then 그 글에 "새 댓글 2"가 보인다.
- [ ] Given 게시판을 열어 둔 보호자가, When 요양보호사가 새 보고서를 보내면, Then 5초 안에 새 글이 목록에 나타난다.
- [ ] Given 요양보호사가 수급자를 삭제했을 때, When 보호자가 같은 링크로 게시판을 열면, Then 404 화면이 나온다.
- [ ] Given 초대 링크로 들어온 보호자가 보낸 보고서가 없을 때, When 게시판을 열면, Then "아직 보낸 보고서가 없어요"가 보이고 뒤로 가기 버튼이 없다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음. STB-7 권한 테스트에 "지운 수급자 게시판 404"를 넣을 수 있다.
- 수동 확인: 요양보호사 기기와 보호자 기기를 나란히 두고 5초 갱신 확인, 체험 계정 게시판 샘플(댓글 4개·요약 글) 확인

## 10. 리스크와 열린 질문

- 리스크: 글이 많아지면 5초마다 전체를 다시 읽는 비용이 커진다.
- 열린 질문:
  - 글 수가 늘었을 때 페이지 나누기를 할지, 기간을 자를지
  - 초대 링크(`boardToken`)를 다시 만들거나(재발급) 끊는 방법이 필요한지
