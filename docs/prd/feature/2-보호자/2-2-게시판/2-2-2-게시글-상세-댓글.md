# PRD: 게시글 상세 · 댓글 (보호자)

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 보호자 | 2-2 게시판 | G-02 게시글 상세 | `/v1120/g/[token]/post` | 구현됨 (DIF-5·LAW-11 리뷰 중) · `feature/v1120` ae8748e 기준 |

## 1. 배경

- 현재 문제: 보호자가 보고서 내용에 대해 물을 창구가 전화·문자뿐이라 기록이 남지 않고, 어느 날 이야기인지 섞인다.
- 왜 지금 필요한가: 10/23 멘토링에서 "채팅 대신 게시글 + 댓글"로 바꾸라는 피드백을 받아 11/1에 반영했다 (D-15 261101.ver).
- 관련 문서/이슈: US-6, DIF-5, LAW-11, `docs/prd/04-prd.md` 8절

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 보고서 글 아래에 댓글로 묻고, 요양보호사의 답을 같은 글에서 본다.
- 기대 효과: 질문과 답이 해당 방문 보고서에 묶여 남는다.

## 3. 대상 사용자

- 주요 사용자: 보호자
- 보조 사용자: 요양보호사 — 같은 모양의 C-18 게시글 상세(1-5-3)에서 답한다
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 요양보호사 게시글 상세(C-18)와 같은 모양: 흰 바탕, 상단 바에 글 제목 (D-65)
- [x] 글 제목, 작성자·시각·종류("보낸 보고서/올린 서류"), 요약, "전체 보기" 버튼
- [x] 전체 보기: 보고서면 `/g/[token]?from=board`, 서류면 `/g/[token]/document`
- [x] 댓글 목록(오래된 글이 위), 작성자 이름 + 역할 칩("요양보호사"/"보호자 · 나")
- [x] 아래 고정 입력칸, 500자까지
- [x] 글을 열면 요양보호사가 단 댓글을 읽음 처리
- [x] 화면이 보이는 동안 5초마다 새 댓글 확인

이번 작업에 포함하지 않음:

- [ ] 댓글 수정·삭제
- [ ] 사진·파일 첨부
- [ ] 실시간 채팅(웹소켓), 푸시 알림

## 5. 사용자 흐름

1. 보호자가 게시판 목록에서 글을 누른다.
2. 시스템은 글 요약과 댓글을 보여 주고, 요양보호사 댓글 중 안 읽은 것을 읽음으로 바꾼다.
3. 보호자가 댓글을 적고 보내면, 시스템은 검증·암호화해 저장하고 화면을 새로 고친다.
4. 요양보호사가 답을 달면 보호자 화면에 5초 안에 나타난다.

## 6. 기능 요구사항

- FR-1: `guardianBoard(token)`의 글 중 `shareToken === token`인 글을 찾고, 없으면 404.
- FR-2: `commentAsGuardian(token, text)` — 앞뒤 공백을 지우고 빈 글이면 "댓글을 적어 주세요.", 500자를 넘으면 "댓글은 500자까지 쓸 수 있어요."
- FR-3: 댓글은 보낸 보고서·올린 서류에만, 지우지 않은 수급자에만 단다 (`postTarget`).
- FR-4: 본문은 `encryptText`로 암호화해 `author="guardian"`으로 저장한다 (LAW-11).
- FR-5: 안 읽은 상대 댓글이 있으면 `markReadAsGuardian(token)`으로 요양보호사 댓글의 `readAt`을 채운다.
- FR-6: 저장 실패 시 오류 문구를 입력칸 근처에 보여 주고 입력한 글은 지우지 않는다.

## 7. 비기능 요구사항

- 성능: 댓글 저장 후 `router.refresh()` 한 번, 그 외 5초 폴링.
- 접근성: 입력칸 `maxLength=500`, 본문 18px, 역할을 글자 칩으로 표시 (DIF-1)
- 보안: 댓글 암호화 저장(AES-256-GCM, `lib/crypto.ts`). 링크만 있으면 누구나 보호자로 댓글을 달 수 있다 (코드 주석 shortcut, D-44에서 막을 예정).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 보호자가 보고서 글 상세에 있을 때, When "오늘 식사는 어떠셨어요?"를 적어 보내면, Then 댓글 목록 맨 아래에 "보호자 · 나" 칩과 함께 나타나고, 열어 둔 요양보호사 화면에도 5초 안에 보인다 (US-6).
- [ ] Given 보호자가 공백만 입력했을 때, When 보내기를 누르면, Then 저장되지 않는다.
- [ ] Given 요양보호사 댓글 1개를 아직 안 읽은 보호자가, When 그 글을 열면, Then 게시판 목록으로 돌아갔을 때 그 글의 "새 댓글" 표시가 사라진다.
- [ ] Given 수급자가 삭제된 뒤, When 보호자가 이전에 열어 둔 화면에서 댓글을 보내면, Then "게시글을 찾을 수 없어요." 오류가 나고 저장되지 않는다.

## 9. 검증 계획

- 단위 테스트: 없음 (`commentBody` 검증 함수는 테스트 스크립트 없음)
- 통합 테스트: 없음. STB-7에 "다른 수급자·지운 수급자 글에 댓글 불가"를 넣을 수 있다.
- 수동 확인: 두 기기로 댓글 주고받기, DB에서 댓글 본문이 암호문인지 확인

## 10. 리스크와 열린 질문

- 리스크: 보호자 인증이 없어 링크를 가진 제3자도 "보호자"로 댓글을 달 수 있다.
- 열린 질문:
  - 보호자가 자기 댓글을 지우거나 고칠 수 있어야 하는지 (개인정보 정정 요구와 연결)
  - 보호자가 여러 명(가족 둘 + 사회복지사)일 때 누가 쓴 댓글인지 구분할 방법
  - 댓글에 쓴 건강 정보도 개인정보 처리방침의 수집 항목에 포함되는지 (동의 문구에는 "게시판 댓글"이 있음)
