# PRD: 건강 기록 요약 보기 · PDF 저장 (보호자)

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 보호자 | 2-2 게시판 | G-02 → 서류 화면(C-20과 같음) | `/v1120/g/[token]/document` | 구현됨 · `feature/v1120` ae8748e 기준 |

## 1. 배경

- 현재 문제: 보호자가 병원 진료나 등급 재판정 때 어르신의 최근 돌봄 기록을 보여 주려면 보고서를 하나씩 다시 모아야 한다.
- 왜 지금 필요한가: 요양보호사가 만든 건강 기록 요약을 "게시판에 올리기"로 글로 만들고(1-6-2), 보호자가 게시판에서 열어 PDF로 저장하게 했다 (D-26, D-29). 11/14 "진료 참고용 요약"에서 이름을 바꿨다 (D-63).
- 관련 문서/이슈: US-4, DIF-4, LAW-10, D-14, D-29, D-63, `docs/prd/04-prd.md` 7절

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 게시판에 올라온 요약 글을 열어 A4 화면으로 보고 PDF로 저장·인쇄한다.
- 기대 효과: 진료나 등급 재판정 때 보여 줄 자료를 보호자가 따로 만들지 않는다.

## 3. 대상 사용자

- 주요 사용자: 보호자
- 보조 사용자: 의료진 (인쇄물·PDF를 보는 사람, 앱 사용자는 아님)
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] 게시글 상세의 "전체 보기"로 서류 화면 열기 (기간이 있는 글만)
- [x] 요양보호사 C-20과 같은 `SummaryView`, `role="guardian"` (게시판에 올리기 버튼 없음)
- [x] 내용: 1 기간 중 달라진 점 → 2 변화상태 추이 → 3 배변 변화 → 4 특이사항 → 5 기간 요약
- [x] 아래 고지: "…의료적 진단이 아니니, 건강 상태는 꼭 의료진과 상담해 주세요.", 작성자·작성일
- [x] "PDF로 저장"·"인쇄하기" (브라우저 인쇄 창)

이번 작업에 포함하지 않음:

- [ ] 병원·기관으로 직접 보내기 (D-14)
- [ ] 보호자가 기간을 바꿔 새로 만들기 (보호자 앱 예시 2-3-2에서만, P2)
- [ ] 급여제공기록지를 게시판에 올리기 (요약만 올라감)

## 5. 사용자 흐름

1. 보호자가 게시판에서 "건강 기록 요약 (M/D~M/D)" 글을 연다.
2. 보호자가 "전체 보기"를 누르면 시스템은 그 기간의 보낸 방문 기록으로 요약을 다시 만들어 A4 화면으로 보여 준다.
3. 보호자가 "PDF로 저장"을 누르면 브라우저 인쇄 창이 열리고 PDF로 저장한다.

## 6. 기능 요구사항

- FR-1: `guardianBoard(token)`의 글 중 토큰이 같고 `period`가 있는 글만 연다. 아니면 404.
- FR-2: 요약은 저장된 내용이 아니라 글의 기간(`from`~`to`)과 `guardianHistory(clientId)`(그 수급자의 보낸 방문)로 볼 때마다 만든다.
- FR-3: 요약은 기록에 있는 사실만 센다 (LAW-1).
- FR-4: 버튼은 인쇄 시 숨긴다(`print:hidden`). PDF·인쇄 모두 `window.print()`.

## 7. 비기능 요구사항

- 성능: 열 때마다 그 수급자의 보낸 방문을 모두 읽는다.
- 접근성: A4 인쇄 레이아웃, 표는 글자와 기호(▲●▼)로 변화를 표시 (DIF-1)
- 보안: 요양보호사가 올린 서류 토큰으로만 열린다. 서류 링크로도 게시판 전체에 들어갈 수 있다 (`guardianBoard`).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 요양보호사가 10/1~10/31 요약을 게시판에 올렸을 때, When 보호자가 그 글의 "전체 보기"를 누르면, Then 기간 10/1~10/31 요약 A4 화면과 아래 고지 문구가 보인다 (US-4).
- [ ] Given 요약 화면에서, When "PDF로 저장"을 누르면, Then 인쇄 창이 열리고 미리보기에 버튼이 보이지 않는다.
- [ ] Given 방문 보고서 글의 토큰으로, When `/document` 주소를 직접 열면, Then 404가 나온다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 아이폰 Safari·안드로이드 크롬·카톡 인앱 브라우저에서 PDF 저장, A4 한 장 넘침 확인 (OPS-2)

## 10. 리스크와 열린 질문

- 리스크: 요약을 볼 때마다 다시 만들기 때문에, 올린 뒤 같은 기간에 보고서가 더 보내지면 보호자가 보는 내용이 올린 시점과 달라진다.
- 열린 질문:
  - 올린 시점의 내용을 고정(스냅샷)할지
  - 요약의 "4. 특이사항"은 기록지용 문장(`notes`)을 쓴다. 보호자가 볼 때도 기록지 말투(~함·~음)가 맞는지, 보호자용 문장을 쓸지
  - 카톡 인앱 브라우저에서 `window.print()`로 PDF 저장이 되는지 (실기기 확인 필요)
