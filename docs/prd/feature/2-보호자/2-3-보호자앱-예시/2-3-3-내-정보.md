# PRD: 보호자 내 정보 (예시)

| 대상 | 큰 기능 | 화면 | 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 보호자 | 2-3 보호자 앱 예시 | G-05 | `/v1120/c/[token]/me` | **프로토타입 · 임시 데이터(`_mock.ts`)** · P2 (D-44, DIF-12) |

> 보호자 로그인 전이라, 요양보호사가 수급자를 등록할 때 적은 보호자 정보를 보여 주는 예시다.

## 1. 배경

- 현재 문제: 보호자 정보(이름·관계·전화)는 요양보호사가 등록하므로, 보호자는 자기 정보가 맞는지 확인할 곳이 없다.
- 왜 지금 필요한가: D-44에서 보호자 앱 하단 메뉴(홈·게시판·내 정보)를 정하면서 예시로 만들었다. 개인정보 처리방침(LAW-12)을 보호자도 볼 수 있어야 한다.
- 관련 문서/이슈: `docs/design/02-screens.md` G-05, D-44, LAW-12

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 보호자가 등록된 자기 정보를 확인하고, 처리방침을 연다.
- 기대 효과: 잘못 등록된 보호자 정보를 보호자가 알아채 요양보호사에게 알린다.

## 3. 대상 사용자

- 주요 사용자: 보호자 (예시)
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 없음

## 4. 범위

이번 작업에 포함:

- [x] "{보호자} 보호자님", "{어르신} 어르신의 {관계}", 전화번호(없으면 "전화번호 없음")
- [x] 안내: "정보가 다르면 게시판 댓글로 요양보호사에게 알려 주세요."
- [x] "개인정보 처리방침" 링크(`/v1120/privacy`)

이번 작업에 포함하지 않음:

- [ ] 보호자가 직접 정보 고치기
- [ ] 보호자 로그인·로그아웃, 비밀번호 변경
- [ ] 알림 설정 (알림 기능 없음, 해커톤 이후)

## 5. 사용자 흐름

1. 보호자가 하단 메뉴 "내 정보"를 누른다.
2. 시스템은 임시 데이터에서 보호자 이름·관계·전화번호를 보여 준다.
3. 보호자는 정보를 확인하고, 필요하면 처리방침을 연다.

## 6. 기능 요구사항

- FR-1: 토큰으로 임시 수급자를 찾고, 없으면 404.
- FR-2: 보호자 이름·관계·전화번호를 수급자 데이터에서 보여 준다.
- FR-3: 처리방침은 요양보호사와 같은 `/v1120/privacy`.

## 7. 비기능 요구사항

- 성능: DB 요청 없음.
- 접근성: 메뉴 높이 64px 이상, 18px 이상 글자 (DIF-1)
- 보안: 실제 연결 시 보호자 전화번호는 암호화 값을 풀어 보여 줘야 한다 (SEC-5).
- 로깅/모니터링: 없음

## 8. 수용 기준

- [ ] Given 임시 데이터의 보호자 토큰으로, When 내 정보를 열면, Then 보호자 이름·관계·전화번호가 보인다.
- [ ] Given 전화번호가 없는 보호자일 때, When 내 정보를 열면, Then "전화번호 없음"이 보인다.
- [ ] Given 내 정보에서, When "개인정보 처리방침"을 누르면, Then 로그인 없이 처리방침이 열린다.

## 9. 검증 계획

- 단위 테스트: 없음
- 통합 테스트: 없음
- 수동 확인: 예시 링크에서 화면·링크 확인

## 10. 리스크와 열린 질문

- 리스크: 실제 연결 시 링크만으로 보호자 전화번호가 보이면 링크 전달로 개인정보가 노출된다.
- 열린 질문:
  - 실제 보호자 앱에서 보호자 정보를 누가 고칠 수 있게 할지 (보호자 본인 / 요양보호사만)
  - 보호자에게도 별도 동의(개인정보 수집·이용)를 받아야 하는지 — 지금 동의는 요양보호사만 한다
