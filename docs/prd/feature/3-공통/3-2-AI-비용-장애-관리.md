# PRD: AI 비용·장애 관리

## 1. 배경

- 현재 문제: 본선에서는 심사위원 여러 명이 체험 계정으로 동시에 쓴다. AI(Groq) 호출에 제한이 없으면 무료 한도·비용이 순식간에 바닥나고, AI가 멈추면 기록 전체가 막힌다.
- 왜 지금 필요한가: SEC-3(AI 호출 제한)·STB-2(중복 정리 차단)가 P0였고, 라이브 시연에서 AI 장애가 나도 흐름이 끊기면 안 된다.
- 관련 문서/이슈: SEC-3, STB-2, `docs/spec/04-ai-pipeline.md`

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: AI가 실패하거나 한도를 넘어도 요양보호사는 기록 확인 화면으로 넘어가 기록을 끝낸다.
- 기대 효과: AI 비용 상한을 두고, 시연 중 AI 장애로 흐름이 끊기지 않는다.

## 3. 대상 사용자

- 주요 사용자: 요양보호사 (체험 계정 포함)
- 보조 사용자: 없음
- 관리자 또는 운영자 영향: 운영자는 `GROQ_API_KEY`와 한도 값(`AI_LIMIT`)을 관리한다.

## 4. 범위

이번 작업에 포함:

- [x] 요양보호사별 AI 호출 한도: 1시간 30번, 24시간 100번 (`aiUsage` 표로 셈)
- [x] AI 정리(`fill-record`)는 한도를 넘으면 오류 대신 낱말 찾기(`extractRecord`)로 채운다
- [x] API 경로(transcribe·summarize·classify-preview·stop·reports)는 한도를 넘으면 429와 "AI 사용 횟수를 넘었어요. 잠시 뒤에 다시 해 주세요."
- [x] 같은 방문을 정리 중(`SUMMARIZING`)이거나 끝났으면(`DRAFT_READY`) 다시 정리하지 않는다 (STB-2)
- [x] 키가 없거나, 녹음 글이 비었거나, AI가 실패하면 낱말 찾기로 채운다
- [x] AI가 비운 숫자 칸(시간·횟수)은 낱말 찾기 값으로 메운다 (`fillGaps`)
- [x] 특이사항을 놓친 결과면 한 번 더 묻고, 그것도 실패하면 첫 결과를 쓴다 (호출 수는 1번으로 셈)

이번 작업에 포함하지 않음:

- [ ] 계정 전체(서비스 전체) 한도·비용 알림
- [ ] 한도를 넘었다는 사실을 요양보호사 화면에 알리기 (정리 경로는 조용히 낱말 찾기로 대체)
- [ ] 에러 모니터링 (OPS-3, P2)

## 5. 사용자 흐름

1. 요양보호사가 "다 말했어요" 후 정리(C-13)로 간다.
2. 시스템은 한도를 확인하고, 남아 있으면 개인정보를 지운 글로 AI 정리를, 없거나 실패하면 낱말 찾기 정리를 한다.
3. 요양보호사는 어느 경우든 기록 확인(C-14)에서 결과를 보고 고친다.

## 6. 기능 요구사항

- FR-1: `takeAiCall(caregiverId, kind)` — 최근 1시간·24시간 호출 수를 세고 한도 미만이면 1건 기록 후 `true`.
- FR-2: `summarizeVisit`는 시작할 때 상태를 `SUMMARIZING`으로 바꾸고, 실패하면 `RECORDED`로 되돌린 뒤 오류를 낸다.
- FR-3: `fillVisitRecord`는 키 없음·글 없음·수급자 없음·한도 초과·AI 예외에서 모두 `extractRecord(transcript)`를 돌려준다.
- FR-4: AI 결과는 `checkAiRecord`로 모양·근거를 검사한다 (근거 없는 값 거르기, LAW-2).
- FR-5: "말로 더하기"(`addToNotes`)도 같은 `fillVisitRecord`를 쓰고, AI가 없으면 한 말을 특이사항 뒤에 그대로 붙인다.

## 7. 비기능 요구사항

- 성능: 한도 확인은 count 쿼리 2번. AI 실패 시 낱말 찾기는 서버에서 바로 끝난다.
- 접근성: 해당 없음
- 보안: 한도는 계정 단위라 체험 계정을 많이 만들면 우회된다.
- 로깅/모니터링: AI 실패는 `console.error("AI 정리 실패, 낱말 찾기로 채움")`. 호출 기록은 `aiUsage` 표.

## 8. 수용 기준

- [ ] Given 한 요양보호사가 최근 1시간에 AI를 30번 썼을 때, When 31번째 정리를 하면, Then 오류 없이 낱말 찾기로 채운 기록 확인 화면이 열린다.
- [ ] Given `GROQ_API_KEY`가 없을 때, When "대소변 실수 없다"를 말하고 정리하면, Then 대변·소변 실수 0회로 채워진다.
- [ ] Given 정리 버튼을 빠르게 두 번 눌렀을 때, When 처리가 끝나면, Then AI 호출 기록은 1건이다.
- [ ] Given AI 호출 중 오류가 났을 때, When 정리가 끝나면, Then 방문 상태가 `RECORDED`로 돌아가지 않고 낱말 찾기 결과로 `DRAFT_READY`가 된다.

## 9. 검증 계획

- 단위 테스트: `npx tsx app/v1120/_redact.check.ts` (AI 결과 거르기·`fillGaps`·`notesLost`), `npx tsx app/v1120/_keepFilled.check.ts` (다시 정리할 때 고친 값 지키기)
- 통합 테스트: 없음. STB-7에 "한도 초과 시 정리 경로 대체" 추가 가능
- 수동 확인: 키를 뺀 미리보기 배포로 전체 흐름, 시연 전 점검(OPS-11)

## 10. 리스크와 열린 질문

- 리스크: 한도 세기와 기록 사이가 잠금이 아니라 동시에 몰리면 한두 번 넘칠 수 있다 (코드 주석 shortcut).
- 리스크: 한도를 넘어 낱말 찾기로 채워져도 요양보호사는 알 수 없어 품질 차이를 AI 탓으로 오해할 수 있다.
- 열린 질문:
  - 1시간 30번·하루 100번이 본선 심사 인원(체험 계정 동시 사용)에 맞는 값인지
  - 낱말 찾기로 대체됐을 때 화면에 "AI 없이 정리했어요" 같은 안내를 넣을지
  - 서비스 전체 일일 상한(비용 상한)이 필요한지
