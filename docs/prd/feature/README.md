# 손다음 세부 기능 PRD

[위키독스 036. PRD.md 작성법](https://wikidocs.net/347441)의 템플릿대로, 지금 구현된 기능(`docs/prd/07-features.md`, `feature/v1120` dcaa0df 기준, 11/7~11/15 변경은 ae8748e 기준으로 고친 파일만 머리표 해시를 바꿈)을 **대상 → 큰 기능(페이지) → 세부 기능**으로 쪼개고 **세부 기능 하나 = PRD.md 하나**로 만들었다. 모두 45개 (11/15 상태변화기록지 1-6-4 추가).

## 모든 PRD의 틀 (가이드 10개 절)

1. 배경 · 2. 목표 · 3. 대상 사용자 · 4. 범위 / 비범위 · 5. 사용자 흐름 · 6. 기능 요구사항(FR) · 7. 비기능 요구사항 · 8. 수용 기준(Given/When/Then) · 9. 검증 계획 · 10. 리스크와 열린 질문

- 범위의 `[x]`는 이미 구현된 것, `[ ]`는 이번에 하지 않는 것이다.
- 코드·문서에서 확인하지 못한 내용은 추정하지 않고 **10. 열린 질문**에 남겼다 (가이드 원칙).

## 다음 단계 (가이드 흐름)

PRD 작성 → **PRD 검토**(모호한 부분, 빠진 수용 기준, 구현 위험, 테스트 전략) → **구현 계획** → **progress.md**로 진행 관리 (가이드 037장)

- 비밀번호 변경: 카카오 로그인이라 비밀번호가 없다.
- 알림 설정: 웹 푸시 알림을 해커톤 이후로 미뤘다 (11/1). 만들게 되면 이 틀로 `1-7-5-알림-설정.md`를 추가한다.

## 작성하며 찾은 코드·문서 불일치 (팀 확인 필요)

각 PRD의 "열린 질문"에서 중요한 것만 모았다.

| PRD | 내용 |
| --- | --- |
| 2-1-1 보고서 열기 | 맞지 않는 토큰이면 "볼 수 없음" 대신 **예시 보고서**를 보여 준다 |
| 2-1-2 보고서 내용 | "지난 방문과 비교"가 실제 비교가 아니라 이번 방문의 변화상태 표시다 |
| 2-1-1 · D-25 | 보호자 보고서 화면에 "PDF로 저장" 버튼이 없다 |
| 1-4-6 · 2-1-2 · LAW-7 | 학대 의심 표현이 보호자 보고서에서 빠지는 코드를 찾지 못했다 |
| 1-7-2 내 정보 고치기 | 이름을 고치면 이미 보낸 보고서·서류의 작성자 이름도 바뀐다 (STB-1과 충돌) |
| 1-3-5 삭제 | 일반 삭제는 "14일 뒤 지워져요" 안내와 달리 자동으로 지우지 않는다. 완전히 지우기도 Cron이 아니다 (STB-6) |
| 1-3-3 수급자 정보 | "꼭 기억할 것"은 `personalNotes`를 보여 주는데 등록·수정 폼에 입력 칸이 없다 |
| 1-5-3 댓글 | 삭제한 수급자도 요양보호사 쪽 게시판·댓글이 열린다 (`postTarget`이 `isActive`를 안 봄) |
| 1-4-3 AI 정리 | 상태가 `SUMMARIZING`에 멈추면 처리중↔기록 확인 사이를 오갈 수 있다 |
| 1-4-6 보내기 | "보냈어요" 표시와 보낸 시각이 그 기기 localStorage에만 남는다 |
| 1-6-2 건강 기록 요약 | 고지 문구는 "AI가 모아 쓴 요약"인데 실제로는 AI를 쓰지 않는다 |
| 1-6-3 급여제공기록지 | 같은 날 두 번 방문하면 장이 겹칠 수 있다 |
| 1-1-1 카카오 로그인 | 콜백 실패 시 `/v1120/login`이 아니라 옛 `/login`으로 간다 |
| 1-2-1 · 1-2-3 | 홈 목록은 한국 시간, 일정 달력은 휴대폰 시간대 기준이다 |
| 1-1-3 처음 설정 | 처음 설정을 안 끝낸 계정이 `/v1120` 홈으로 바로 들어오는 것을 막지 않는다 |
